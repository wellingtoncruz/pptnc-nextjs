Epic 13: Migração SDK — Análise de Complexidade

Data: 2026-02-17 Contexto: @google-cloud/vertexai deprecated Jun 2025, remoção Jun 2026 Destino: @google/genai (v1.41.0+)

Superfície de Impacto

Arquivos que importam @google-cloud/vertexai

Arquivo Imports Impacto
src/lib/llm/client.ts VertexAI, GenerativeModel, Part ALTO — core do LLM
src/app/api/wizard/phase/5b/route.ts VertexAI, GenerativeModel, Part ALTO — duplica init do client
src/app/api/wizard/phase/5b/route.test.ts vi.mock('@google-cloud/vertexai') MÉDIO — mock do SDK

Arquivos que usam tipos/funções do client.ts (impacto indireto)

Arquivo Relação
src/lib/llm/types.ts Define VertexAIConfig, tipos de resposta
src/lib/llm/llm.test.ts Testa createTranscriptionFile, cleanupTranscriptionFile
src/lib/llm/index.ts Re-exporta do client
src/lib/llm/errors.ts Error handling (agnóstico ao SDK)
src/lib/llm/queue.ts Queue wrapper (agnóstico ao SDK)
src/lib/llm/prompts.ts Prompt building (agnóstico ao SDK)
src/lib/llm/interpolation.ts Variable interpolation (agnóstico ao SDK)
src/lib/llm/parse-json.ts JSON parsing (agnóstico ao SDK)

Resumo: 3 arquivos com import direto, ~5 com impacto indireto

Mapeamento de APIs: Antigo → Novo

Inicialização

// ANTES (@google-cloud/vertexai)
import { VertexAI } from '@google-cloud/vertexai'
const vertexAI = new VertexAI({ project: PROJECT_ID, location: GCP_REGION })
const model = vertexAI.getGenerativeModel({ model: 'gemini-2.5-flash', generationConfig: {...} })

// DEPOIS (@google/genai)
import { GoogleGenAI } from '@google/genai'
const ai = new GoogleGenAI({ vertexai: true, project: PROJECT_ID, location: GCP_REGION })
// Model é passado por chamada, não no construtor

generateContent / generateContentStream

// ANTES
const result = await model.generateContentStream({
  contents: [{ role: 'user', parts }],
  systemInstruction: { role: 'system', parts: [{ text: systemPrompt }] },
})
for await (const chunk of result.stream) { ... }
const response = await result.response

// DEPOIS (a verificar — API pode diferir)
const response = await ai.models.generateContentStream({
  model: 'gemini-2.5-flash',
  contents: [{ role: 'user', parts }],
  config: { systemInstruction: systemPrompt, ...generationConfig },
})

Inline Data (attachment)

// ANTES
parts.push({ inlineData: { mimeType: 'text/plain', data: base64Content } })

// DEPOIS — opção 1: inline (mesmo approach)
parts.push({ inlineData: { mimeType: 'text/plain', data: base64Content } })

// DEPOIS — opção 2: Files API (novo!)
const file = await ai.files.upload({ file: filePath, config: { mimeType: 'text/plain' } })
parts.push({ fileData: { fileUri: file.uri, mimeType: file.mimeType } })

Response Structure

// ANTES
response.candidates?.[0]?.content?.parts?.[0]?.text
response.usageMetadata?.promptTokenCount
response.usageMetadata?.candidatesTokenCount

// DEPOIS (a verificar — nomes podem diferir)
// Precisa validar a estrutura exata do response no novo SDK

Avaliação de Complexidade

Por Componente

Componente Complexidade Justificativa
Inicialização (getVertexAI, getModel) Baixa Trocar construtor, ajustar config
callVertexAIWithAttachment Média Core function — streaming, retry, parsing. API de streaming pode diferir
Phase 5B route Média Duplica lógica do client — ideal refatorar para usar callLLM
Response parsing Média Nomes de campos podem mudar (usageMetadata, candidates)
generationConfig + thinkingConfig Média thinkingConfig já era cast via as Record<string, unknown> — verificar suporte no novo SDK
undici timeout workaround Baixa Pode não ser necessário no novo SDK
Testes (mocks) Média Todos os mocks de @google-cloud/vertexai precisam atualizar
Files API (novo) Baixa Feature aditiva, não quebra nada existente

Complexidade Global: MÉDIA

Riscos

Risco Probabilidade Impacto Mitigação
API de streaming diferente no novo SDK Alta Alto Spike com PoC antes de implementar
thinkingConfig não suportado Média Alto Verificar docs/changelog do @google/genai
Response structure diferente Alta Médio Adaptar parsing, manter testes como safety net
Timeout/retry behavior diferente Média Médio Validar com transcrições grandes
ADC authentication diferente Baixa Alto Novo SDK suporta ADC nativamente

Estimativa total: 8-14h (incluindo spike e file reuse)

Recomendação

Prioridade: Média — deadline Jun 2026, mas idealmente fazer antes de Q2 2026 para ter margem

Approach:

  1. Começar com spike (13.1) para validar API de streaming e thinkingConfig
  2. Se PoC positivo, migrar incrementalmente (13.2 → 13.6)
  3. File reuse (13.5) é bônus — implementar se spike confirmar que ai.files funciona via Vertex AI backend
