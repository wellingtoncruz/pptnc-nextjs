Auditoria de Prompts LLM — IAra (AS-IS)

Data: 2026-02-24 Versão: v2.2.2-beta-iara Objetivo: Mapear tudo que é enviado ao LLM além do que está no banco de dados (Firestore)

Arquitetura Geral

Route Handler → callLLMQueued() → callLLM() → callGenAI()
                                                    ↓
                                          generateContentStream()

Modelo: gemini-2.5-flash (ou env VERTEX_AI_MODEL) SDK: @google/genai com backend Vertex AI Config fixa (toda chamada):

  • temperature: 0.7
  • maxOutputTokens: 65536
  • thinkingConfig.thinkingBudget: 24576
  • responseMimeType: 'application/json'

Estrutura da Chamada à API

// client.ts:170-184
generateContentStream({
  model: modelName,
  contents: [
    { text: userPrompt },                          // ← User prompt (texto)
    { inlineData: { mimeType: 'text/plain',        // ← Transcrição (base64)
                    data: base64Transcription } }
  ],
  config: {
    systemInstruction: systemPrompt,               // ← System prompt
    responseMimeType: 'application/json',
    temperature: 0.7,
    maxOutputTokens: 65536,
    thinkingConfig: { thinkingBudget: 24576 },
  },
})

Quando podcast está configurado (fluxo principal)

prompts.ts:538-545 → buildPhasePrompt()

│ Seu papel: {persona.role}                           │ ← Firestore

│ Seu contexto: {persona.resume}                      │ ← Firestore
│                                                     │
│ ## TAREFA                                           │ ← ESTÁTICO (código)
│ {prompts[videoType][promptKey].description}          │ ← Firestore
│                                                     │
│ {PHASE_JSON_SCHEMAS[phase]}                         │ ← ESTÁTICO (código)
└─────────────────────────────────────────────────────┘

Nota: O expectedOutput do Firestore é IGNORADO quando PHASE_JSON_SCHEMAS[phase] existe (todas as fases 1-7). Ele só seria usado se o JSON schema fosse vazio.

Para fases reprocessáveis (5, 6, 7) com instrução do produtor

client.ts:394-395

Adicionado ao FINAL do system prompt:

┌─────────────────────────────────────────────────────┐
│ \n\n**INSTRUÇÃO PRIORITÁRIA DO PRODUTOR:**          │ ← ESTÁTICO (código)
│ Dê uma atenção especial a essa instrução:           │ ← ESTÁTICO (código)
│ {additionalContext}                                 │ ← Input do usuário (UI)
└─────────────────────────────────────────────────────┘

Fallback (sem podcast configurado)

Usa BASE_SYSTEM_PROMPTS[phase] — prompts 100% hardcoded no código (ver Apêndice A).

Composição do User Prompt

O user prompt é construído via template + interpolação de variáveis:

client.ts:402-407

template = USER_PROMPT_TEMPLATES[phase]       // ← ESTÁTICO (código)
variables = extractVariables(video, ...)       // ← Dados do vídeo (Firestore)
variables.transcript = '[Transcrição anexada como arquivo]'  // ← ESTÁTICO (código)
userPrompt = interpolatePrompt(template, variables, additionalContext)

Fase 2 — Checagem de Edição

Persona: critic | Prompt key: editing | Attachment: SRT

System prompt:

Seu papel: {persona.critic.role}
Seu objetivo: {persona.critic.objective}
Seu contexto: {persona.critic.resume}

## TAREFA
{prompts[videoType].editing.description}

## FORMATO DE RESPOSTA

Responda APENAS com JSON válido. A resposta será parseada diretamente como JSON.
NÃO use tags, NÃO use markdown, NÃO inclua texto fora do JSON.

Estrutura obrigatória:
{"hasIssues": boolean, "issues": [{"timestamp": "HH:MM:SS", "description": "string"}]}

## REGRAS OBRIGATÓRIAS DE OUTPUT

1. JSON COMPACTO: sem indentação, sem quebras de linha, uma única linha.
2. DESCRIPTIONS CURTAS: máximo 80 caracteres. Descreva o tipo do problema, NÃO transcreva o diálogo.
3. TIMESTAMPS válidos: formato "HH:MM:SS", dentro da duração do vídeo.

## EXEMPLOS

CORRETO: {"hasIssues":true,"issues":[{"timestamp":"00:12:45","description":"Pausa longa de 5s entre falas"},{"timestamp":"00:25:30","description":"Instrução de edição: apresentador pede corte"}]}
CORRETO: {"hasIssues":false,"issues":[]}
ERRADO: {"hasIssues":true,"issues":[{"timestamp":"00:12:45","description":"O apresentador falou: \"vamos cortar essa parte aqui porque ficou ruim e eu acho que a gente deveria regravar essa cena toda\" - Remover imediatamente do corte final."}]}

IMPORTANTE: O campo "timestamp" DEVE ser STRING no formato "HH:MM:SS".

**Duração:** {formatDuration(video.duration)}

Diferenças na Fase 5B vs Fases 1-7

Aspecto Fases 1-7 Fase 5B
Chamada callLLMQueued() (fila) callGenAI() direto

expectedOutput do DB Ignorado (JSON schema prevalece) Ignorado (JSON inline)

Observação Importante

O campo expectedOutput configurado no Firestore para cada prompt de fase nunca é usado nas fases 1-7, porque PHASE_JSON_SCHEMAS[phase] sempre existe e tem precedência (ver prompts.ts:536-546). Esse campo só seria usado na branch else da linha 548, que nunca é alcançada para fases com LLM.
