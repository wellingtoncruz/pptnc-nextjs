O Que Deu Certo

  • Spike pivotou de Vertex AI pra Anthropic API direta (R4 allowlist eliminada). O spike economizou 10% no custo, abriu prompt caching, e desbloqueou cobertura via plano Max do Wellington ($100/mês créditos programáticos a partir de 15-jun-2026). Decisão documentada em spike-claude-vertex-results.md.
  • Adapter pattern limpo. LLMProvider interface + 2 implementações (GeminiProvider, AnthropicProvider) + factory simples. Os 9 callers diretos da app não precisaram mudar lógica de negócio — só passar 1-2 args extras. Doc em architecture-llm-adapter.md.
  • Tolerant read no schema (.catch(undefined) em LlmConfigSchema.provider) preveniu quebra do GET /api/podcast quando IDs de modelo ficaram stale. Mesma técnica usada em LlmLogCreateSchema (defaults gemini/0 pra docs legacy).
  • Auto-fallback Claude→Gemini simplificou Story 23.7 sem mexer no wizard-orchestrator.tsx (2700 LOC, TD-7 conhecida). AC2 (alert por fase) foi deferido com justificativa explícita; AC1 (retry/backoff) já estava atendido por construção.
  • Cost estimator + provider indicator deram visibilidade visual imediata. Badge no Settings mostra estimativa colorida (verde/amarelo/vermelho); indicador na sidebar mostra qual provider está ativo a todo momento.
  • Telemetria estruturada (Story 23.6): logs event: 'llm.call.complete' e 'llm.call.error' viabilizam queries Cloud Logging sem grep. Custo agregado no painel de debug logs ajuda auditar gasto sem abrir Anthropic console.
  • A/B bench cego (Story 23.8): Wellington tem ferramenta objetiva pra comparar Claude vs Gemini com transcrições PPTNC reais. Anonimização A/B aleatória reduz viés "Claude é melhor porque eu acho que é".
  • AskUserQuestion antes de tradeoffs. Usada pra decidir escopo simplificado da 23.7 (auto-fallback ao invés de UI por fase), fases do bench (criativas 5/5B/6/7), e integration tests (com gate). Cada decisão preservou ~1 dia de trabalho não-necessário.

O Que Deu Errado

1. Bug do 7º arg em 9 callers diretos (Story 23.4 → 23.7)

O que aconteceu: Ao adicionar providerOverride como 7º arg de callGenAI, atualizei callLLM (wizard) mas esqueci 9 callers diretos em rotas API. Resultado: Settings salvava provider: 'claude', mas as chamadas continuavam com o default (Gemini), tentando Vertex AI com claude-sonnet-4-6 → 404.

Wellington pegou em homologação. Custou 1 commit extra (76f016d) + atualização de 21 assertions de teste.

Por que aconteceu: falha de propagação (AI 4 Retro 16). Quando alterei callLLM assumi que era o único caller. grep callGenAI src/ teria mostrado os 9 callers no mesmo PR.

Mitigação aplicada: debug log temporário em callGenAI mostrando providerOverride resolvido — Wellington conseguiu validar visualmente que o fix funcionou.

Lição: AI nova abaixo (#16).

2. Quebra repetida de 21 testes ao adicionar arg posicional

Cada vez que adicionei um arg posicional em callGenAI (1x para providerOverride, depois 1x para fallbackProviderOverride), os mesmos 21 assertions de toHaveBeenCalledWith quebraram em 7 arquivos de teste. Mecânico, mas atrito repetido.

Causa raiz: assinatura de 8 args posicionais é frágil. Ordem dos args importa, defaults misturados, cada adição custa 21 ajustes.

Mitigação imediata: replace_all com Edit acelerou.

Mitigação estrutural: TD-9 nova (refatorar pra options: object).

3. Path relativo no bench script

scripts/llm-ab-bench.ts usou 'apps/iara/scripts/.bench-output' literal como path do outDir. Quando o Wellington rodou do diretório apps/iara/, o script criou apps/iara/apps/iara/scripts/.bench-output/ (caminho aninhado errado).

Causa: path relativo ao cwd em vez de __dirname.

Mitigação: corrigido no commit d36a6ea antes do push. AI nova abaixo (#15).

Novos Action Items

Adicionam-se aos 13 anteriores. Total cumulativo: 16 AIs, pré-requisitos pra próximos epics.

AI 14 — Refatorar callGenAI pra options object quando passar 8 args

Origem: Epic 23 atingiu 8 args posicionais em callGenAI. Cada adição (1x provider, 1x fallback) custou 21 ajustes em testes + arriscou esquecer callers (AI 14 do bug acima).

Quando aplicar: próxima adição de arg em callGenAI (10º arg) é gatilho. Refactor:

// De:
callGenAI(systemPrompt, userPrompt, timeout, attachmentPath, debugContext, modelOverride, providerOverride, fallbackProviderOverride)

// Para:
callGenAI({ systemPrompt, userPrompt, timeout, attachmentPath, debugContext, modelOverride, providerOverride, fallbackProviderOverride })

Custo estimado: ~4-6h (atualizar 10 callers + 21 testes). Quebra positiva: mocks ficam mais legíveis.

Quem implementa: dev no primeiro epic que precisar tocar callGenAI de novo.

AI 15 — Scripts CLI sempre via __dirname, nunca path relativo a cwd

Origem: bench script criou diretório aninhado quando Wellington rodou de cwd diferente.

Aplicação: todo path de output/input em apps/iara/scripts/*.ts deve ser resolve(__dirname, ...). Path relativo ao monorepo root é proibido.

Verificação: code review revisa diff de scripts/ buscando padrão join('apps/, join('./apps/, etc.

AI 16 — Ao adicionar arg em função compartilhada (callGenAI, callLLM, etc.), grep callers no mesmo commit

Origem: bug do 7º arg em Story 23.4.

Aplicação: quando alterar assinatura de função em src/lib/llm/client.ts:

grep -rn "<function-name>(" src/

Listar TODOS os callers, atualizar todos no mesmo PR. Não confiar que "callLLM é o único". grep é barato.

Verificação: code review checa diff buscando se a nova função foi propagada coerentemente.
