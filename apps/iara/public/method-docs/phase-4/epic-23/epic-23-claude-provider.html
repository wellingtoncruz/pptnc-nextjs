Epic 23 — Multi-Provider LLM: Claude (Anthropic) via API direta

Status: Story 23.1 (Spike) ✅ DONE 2026-05-15 — 6/6 PASS — GO formalizado Documentado em: 2026-05-14 (Vertex), pivotado em 2026-05-15 (direta) Pré-requisito: Epic 22 estável em produção por ≥ 2 semanas Tamanho estimado pós-pivot: 11-16 dias dev + 2-3 dias QA (spike já consumido) Risk profile: MÉDIO — refactor de arquitetura LLM + provider novo. R1, R2, R4, R6, R8 ELIMINADOS pelo spike.

Pivot crítico 2026-05-15: decisão de usar Anthropic API direta (@anthropic-ai/sdk) em vez de Vertex AI. Motivos:

  1. Vertex bloqueado por R4 (allowlist publisher Anthropic não habilitado em pptnc-stage).
  2. Direta é -10% mais barata ($3/$15 vs $3.30/$16.50 regional Vertex).
  3. SDK mainstream Anthropic é Turbopack-safe (R1 validado no spike).
  4. Wellington é assinante Max 5x → potencial cobertura via "créditos programáticos" $100/mês a partir de 15-jun-2026 (validar empiricamente pós-data).

Toda referência abaixo ao "Vertex" deve ser lida como "Anthropic API direta". Sizing original 12-17 dias reduz pra 11-16 (sem Story de IAM/allowlist Vertex).

1. Goal

Permitir que o IAra Admin Portal use Claude (Anthropic) via Vertex AI como provider alternativo de LLM para geração de texto nas fases do wizard, mantendo Gemini como provider padrão e único para geração de imagem (Newsletter, Thumbnail).

Driver de produto (Wellington, party-mode 2026-05-14): "Claude tem gerado textos com mais qualidade" — avaliação subjetiva sobre escrita em fases LLM. Hipótese ainda não validada com conteúdo PPTNC.

2. Não-objetivos (Out of Scope)

Para manter escopo controlado, NÃO entram neste epic:

Item Razão
Claude para geração de imagem Claude não gera imagem — incompatível por definição
Outros providers (OpenAI, Mistral, Llama via Vertex Garden) Avaliar após Claude. Adapter pattern fica pronto pra eles.
Migração compulsória de podcasts antigos Provider Gemini permanece default; Claude é opt-in por podcast
Substituir Gemini totalmente Fica como fallback automático e provider default
Otimização de prompts específica pra Claude Story 3 fará ajustes mínimos; otimização profunda é epic futuro
Cache de respostas LLM Decisão Wellington 2026-04 (revert do context caching, ver lesson_cache_revert.md)
Provider por usuário (multi-tenant) Provider é por podcast (podcast.llmConfig.provider); single-tenant atual

3. Decisões Técnicas (ADRs)

ADR-23.1 — Adapter Pattern obrigatório

Contexto: O cliente atual (src/lib/llm/client.ts) usa GoogleGenAI diretamente. Suportar Claude exige uma camada de abstração.

Decisão: Criar interface LLMProvider com métodos generateText(options) e streamText(options). Implementações: VertexAIProvider (Gemini, refactor do código atual) e ClaudeProvider (novo, via @anthropic-ai/vertex-sdk).

Consequências:

  • (+) Permite providers futuros sem refactor adicional.
  • (+) Mocks de teste ficam padronizados na interface.
  • (–) Toda chamada LLM passa por mais um nível de indireção (overhead trivial).
  • (–) Adapter força mapping de tipos Anthropic ↔ formato interno (LLMResult, LLMError).

ADR-23.2 — Provider escopo é POR PODCAST, não por fase

Contexto: O wizard tem múltiplas fases LLM (1-7). Permitir provider por fase multiplicaria configurações e complicaria diagnóstico.

Decisão: podcast.llmConfig.provider: 'gemini' | 'claude' define o provider único para TODAS as fases LLM de texto. Image generation continua em podcast.llmConfig.imageModel (Gemini, sempre).

Consequências:

  • (+) Configuração simples no Settings (1 dropdown).
  • (+) Telemetria/billing claros.
  • (–) Sem A/B-test fino por fase. Mitigação: dev pode forçar via env var em diagnóstico (LLM_PROVIDER_OVERRIDE).

ADR-23.3 — Default provider continua Gemini

Contexto: Mudar default afeta podcasts existentes silenciosamente — custo 40-50x.

Decisão: podcast.llmConfig.provider é opcional, fallback explícito 'gemini'. Documento Firestore sem o campo continua usando Gemini. Wellington precisa explicitamente trocar para Claude no Settings.

Consequências:

  • (+) Zero migração de dados.
  • (+) Zero custo silencioso.
  • (–) Toggle requer ação humana — não vai pra Claude por engano nem por engano não vai.

ADR-23.4 — Fallback automático em falha persistente

Contexto: Claude pode dar RATE_LIMIT, timeout, ou erro 5xx. Hoje, Gemini com falha persistente quebra o wizard.

Decisão: Quando Claude falhar 3 vezes consecutivas numa mesma sessão de wizard (após retry/backoff exhausting), o ClaudeProvider lança erro e o orchestrator mostra alerta amber ao produtor com botão "Tentar com Gemini". Não há fallback automático silencioso — produtor decide.

Consequências:

  • (+) Resiliência sem decisões mágicas.
  • (+) Custo não vaza pra Gemini sem o produtor saber.
  • (–) UX mais elaborada (Story 7).

ADR-23.5 — Pre-flight cost estimate na UI antes de salvar

Contexto: Trocar Gemini → Claude eleva custo de ~$1/mês → ~$40-50/mês no volume PPTNC (estimativa preliminar). Sem visibilidade prévia, surpresa em fatura.

Decisão: Settings UI calcula estimativa de custo mensal com base em: vídeos produzidos no último mês × tokens médios por fase × pricing do modelo selecionado. Mostra antes do produtor clicar Salvar.

Consequências:

  • (+) Transparência total.
  • (+) Wellington pode comparar Sonnet 4.6 vs Haiku 4.5 vs Opus 4.7.
  • (–) Implementação adicional (~4-6h, parte da Story 5).

ADR-23.6 — Telemetria por provider obrigatória

Contexto: Sem métricas por provider, não dá pra comparar qualidade nem detectar regressão silenciosa.

Decisão: Toda chamada LLM grava em llm-logs/{podcastId}/{logId}: provider, model, phase, prompt token count, completion token count, latency ms, error code (se houver), cost estimado. Já existe LLM log; só adicionar campo provider.

Consequências:

  • (+) Comparação Gemini × Claude no mesmo prompt em prod.
  • (+) Cost tracking auditável.
  • (–) Schema migration leve (LlmLog ganha campo).

ADR-23.7 — Spike de viabilidade pré-epic é OBRIGATÓRIO

Contexto: Spike de 2026-02 está desatualizado. Pontos críticos não validados:

  1. @anthropic-ai/vertex-sdk v0.16.0 com Turbopack (Next.js 16) — @google-cloud/tasks quebrou no Epic 21, mesmo padrão pode acontecer.
  2. Autenticação ADC com Vertex AI Claude endpoints.
  3. Performance real com transcrição PPTNC (50K tokens em episódio de 1h).

Decisão: Story 1 do epic é spike isolado de 2-3 dias com gate go/no-go. Se Turbopack falhar e REST direta também não funcionar, epic é abortado e documentado como bloqueador.

Consequências:

  • (+) Risco de blocked-at-end-of-epic mitigado.
  • (–) 2-3 dias antes do refactor propriamente dito.

6. Stories

Story 23.1 — Spike de Viabilidade (Gate Go/No-Go)

Como dev, Eu quero validar empiricamente que @anthropic-ai/vertex-sdk funciona com nossa stack (Turbopack, Next.js 16, ADC) antes de pagar o refactor, Para evitar descobrir bloqueador irrecuperável no meio do epic.

AC6 — Streaming semantics:

AC7 — Gate de decisão:

Arquivos:

Story 23.3 — ClaudeProvider Implementation

Como dev, Eu quero implementar ClaudeProvider usando @anthropic-ai/vertex-sdk, Para que o sistema possa rotear chamadas LLM para Claude quando configurado.

Acceptance Criteria:

AC1 — Adapter completo:

  • Given interface LLMProvider
  • When src/lib/llm/providers/claude-provider.ts é criado
  • Then implementa todos os métodos da interface
  • And usa AnthropicVertex client do @anthropic-ai/vertex-sdk@0.16.0

AC2 — Error mapping:

  • Given erros do SDK Anthropic (APIError, RateLimitError, etc.)
  • When o adapter executa
  • Then mapeia para LLMError interno com codes RATE_LIMIT | TIMEOUT | API_ERROR | INVALID_RESPONSE | NETWORK_ERROR
  • And retryable é setado conforme tipo

AC3 — Token counting:

  • Given texto de prompt
  • When estimateTokens() é chamado
  • Then usa tiktoken ou contador Anthropic-compatible (decidido no spike)
  • And retorna estimativa em ≤200ms

AC4 — Streaming uniforme:

  • Given chamada streamText()
  • When Claude responde via stream
  • Then eventos são mapeados para StreamEvent (mesmo shape do Vertex)
  • And UI de feedback temporal não precisa saber qual provider está em uso

AC5 — Context window guard:

  • Given prompt + transcrição com >180K tokens (margem segurança vs limite 200K)
  • When enviado ao Claude
  • Then ClaudeProvider rejeita com LLMError('CONTEXT_TOO_LARGE', ...) ANTES de chamar a API
  • And sugere fallback (truncar transcrição ou usar Gemini com 1M context)

AC6 — Testes unitários:

  • Given mock de AnthropicVertex
  • When rodados
  • Then cobrem: sucesso, RATE_LIMIT, TIMEOUT, INVALID_JSON, CONTEXT_TOO_LARGE, stream events, error mapping

AC7 — Cost reporting no LLMResult:

  • Given chamada completa
  • When retorna LLMResult
  • Then inclui usage.estimatedCostUsd calculado pelo provider

B. Glossário

  • GA (General Availability): Modelo com SLA e estabilidade contratual.
  • Preview: Sem SLA, quota agressiva, sujeito a mudança/descontinuação.
  • ADC (Application Default Credentials): Mecanismo do GCP de auth via service account ou user credentials.
  • Provider: Camada do adapter pattern que abstrai o cliente LLM concreto (Gemini, Claude).
  • Fallback automático: Troca de provider sem aviso ao produtor — explicitamente rejeitado neste epic (ADR-23.4).
  • A/B Blind Comparison: Wellington julga outputs sem saber qual provider gerou.
