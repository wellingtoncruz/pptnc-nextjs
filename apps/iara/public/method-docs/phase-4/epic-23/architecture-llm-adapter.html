Arquitetura — LLM Provider Adapter

Epic: 23 — Multi-Provider LLM Story de origem: 23.2 (refactor não-funcional, Gemini-only) Implementado em: 2026-05-15 Provider atual: GeminiProvider (Vertex AI via @google/genai) Provider planejado: AnthropicProvider (Story 23.3 — Anthropic API direta via @anthropic-ai/sdk)

1. Motivação

O Epic 23 quer permitir trocar Gemini ↔ Claude (e futuros providers) sem reescrever as camadas de orquestração, queue, retry, parse e logging. A solução é um adapter pattern com interface LLMProvider isolando o que diverge entre providers concretos.

2. Camadas

┌─────────────────────────────────────────────────────────┐
│ Route handlers de fase, Newsletter, Phase 5B            │
└─────────────────────┬───────────────────────────────────┘
                      │ chamam
                      ▼
┌─────────────────────────────────────────────────────────┐
│ callLLMQueued()    (queue: 1 chamada por vez)           │
│ callLLM()          (orchestra: valida vídeo + prompts)  │
│ callGenAI()        (retry/backoff + parse JSON + logs)  │
└─────────────────────┬───────────────────────────────────┘
                      │ chama
                      ▼
┌─────────────────────────────────────────────────────────┐
│ LLMProvider                                             │
│   generateText(opts) → { text, usage, cost, latency }   │
│   streamText(opts)   → AsyncIterable<event>             │
│   estimateTokens(s)  → number (síncrono, sem rede)      │
└─────────────────────┬───────────────────────────────────┘
                      │ implementado por
                      ▼
┌──────────────────────┴──────────────────────────────────┐
│ GeminiProvider                  AnthropicProvider       │ (Story 23.3)
│   @google/genai                   @anthropic-ai/sdk     │
│   Vertex AI ADC                   API key Bearer        │
│   stream + responseMimeType       messages.create       │
│   thinkingConfig                  ext. thinking         │
└─────────────────────────────────────────────────────────┘

3. Contratos

LLMProvider (src/lib/llm/providers/types.ts)

export interface LLMProvider {
  readonly name: 'gemini' | 'claude'
  readonly defaultModel: string

  generateText(opts: GenerateTextOptions): Promise<GenerateTextResult>
  streamText(opts: StreamTextOptions): AsyncIterable<LLMStreamEvent>
  estimateTokens(text: string): number
}

GenerateTextOptions

Campo Tipo Origem
systemPrompt string construído por buildPhasePrompt() na camada acima
userPrompt string template da fase + dados do vídeo
attachment? { mimeType, content } transcrição (text/plain) opcional
model? string override de podcast.llmConfig.textModel
debugContext? DebugContext metadata pra LLM log
timeoutMs? number default 120000

GenerateTextResult

{
  text: string                    // bruto, sem parse
  usage: {
    promptTokens: number
    completionTokens: number
    totalTokens: number
  }
  estimatedCostUsd: number         // calculado pelo provider via pricing table
  latencyMs: number                // tempo da chamada (sem retry externo)
  modelUsed: string                // ID resolvido (após default fallback)
}

LLMStreamEvent

| { type: 'delta'; text: string }
| { type: 'done'; usage; estimatedCostUsd; modelUsed }
| { type: 'error'; code; message; retryable }

4. Responsabilidades por camada

Provider faz

  • Auth (ADC pro Gemini, API key pro Claude)
  • Request shape (parts/contents/messages — formato nativo)
  • Configs específicas (responseMimeType, thinkingConfig, max_tokens, etc.)
  • Stream consumption (Gemini sempre retorna stream)
  • Token counting heurístico (chars/4 em PT-BR)
  • Cost calculation (lookup em pricing table interna)
  • Error mapping nativo → LLMError interno

Provider NÃO faz

  • Retry / backoff (camada callGenAI)
  • Parse JSON (parse-json.ts na camada callGenAI)
  • Queue (callLLMQueued)
  • Prompt building (prompts.ts + interpolation.ts)
  • LLM log persistence (camada callGenAI)
  • Validation de vídeo (callLLM)
  • Image generation (image-client.ts é Gemini-only, fora do adapter)

5. Singleton + reset pattern

Cada provider expõe duas funções módulo-level:

export function getGeminiProvider(): GeminiProvider
export function resetGeminiProvider(): void
  • Singleton lazy — primeira chamada constrói o cliente subjacente; subsequentes reusam.
  • reset* zera o singleton; usado em beforeEach de testes que precisam re-instrumentar mocks de @google/genai ou @anthropic-ai/sdk.

6. Pricing tables

Cada provider mantém pricing interno por modelo, em PRICING_USD_PER_M:

{
  'gemini-2.5-flash': { input: 0.075, output: 0.3 },
  ...
}

Custos não cobertos (modelo desconhecido) retornam zero — caller pode ignorar ou tratar como sinal de configuração faltante. A Story 23.5 introduz cost estimator dedicado que reusa essas tabelas.

7. Compatibilidade preservada

Após Story 23.2, callers existentes não foram tocados:

  • callGenAI() mantém signature pública idêntica
  • Newsletter (src/lib/news/...) usa callGenAI — funciona sem mudança
  • Phase 5B (/api/wizard/phase/5b/route.ts) usa callGenAI — funciona sem mudança
  • Route handlers de fase 1-7 usam callLLMQueued → callLLM → callGenAI — funcionam sem mudança
  • getAI() ainda exportado de client.ts — usado por image-client.ts e embedding/vertex-ai.ts (fora do scope do adapter)
  • Mocks de @google/genai em testes existentes continuam interceptando (o singleton do provider usa o mesmo GoogleGenAI internamente)
