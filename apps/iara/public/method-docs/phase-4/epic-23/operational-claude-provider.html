Operational Guide — Claude Provider (Epic 23)

Última atualização: 2026-05-15 Status: Em produção (branch feature/epic-23-claude-provider, aguardando merge em main)

Este guia é o referencial pra produtor/dev que precisa ativar, monitorar ou diagnosticar problemas com o provider Claude no IAra.

1. Como ativar Claude

1.1 Pré-requisitos

Item Onde Obrigatório
ANTHROPIC_API_KEY .env.local (dev) ou Cloud Run env (prod) Sim
@anthropic-ai/sdk instalado apps/iara/package.json Sim (já no repo)
Conta Anthropic com créditos https://console.anthropic.com Sim

1.2 Passo a passo (UI)

  1. Login no IAra como admin
  2. Sidebar → Configurações
  3. Aba LLM (ou seção "Configuração de LLM")
  4. Em Provider de Texto, selecionar Claude (Anthropic) — opt-in, requer ANTHROPIC_API_KEY
  5. Modelo de Texto mostra automaticamente os modelos Claude disponíveis. Escolher um:
    • claude-sonnet-4-6 — recomendado (qualidade × custo equilibrado)
    • claude-opus-4-7 — máxima qualidade, ~5x mais caro
    • claude-haiku-4-5-20251001 — barato, qualidade inferior
  6. Badge de custo estimado aparece imediatamente embaixo do select. Cor:
    • 🟢 Verde: <$20/mês (seguro)
    • 🟡 Amarelo: $20-100/mês (atenção)
    • 🔴 Vermelho: ≥$100/mês (cuidado)
  7. (Opcional) Marcar "Usar Gemini automaticamente quando Claude falhar" se quiser fallback silencioso

A configuração persiste em podcasts/{podcastId}.llmConfig no Firestore.

1.3 Confirmação que Claude está ativo

  • Indicador na sidebar (abaixo do mascote IAra) mostra [logo Anthropic] claude-sonnet-4-6 em cinza
  • Próxima chamada LLM aparece com provider: 'claude' no Cloud Logging

2. IAM / Auth

Diferente do Gemini (que usa Vertex AI via ADC no GCP), Claude usa API key direta:

  • Não precisa IAM permissions no GCP pra Claude
  • Precisa ANTHROPIC_API_KEY válida — gerada em https://console.anthropic.com/settings/keys
  • Em Cloud Run: setar como secret. Não commitar a key.
gcloud run services update iara \
  --update-env-vars ANTHROPIC_API_KEY=$(gcloud secrets versions access latest --secret=anthropic-api-key) \
  --region us-east1

3. Monitoramento de custo

3.1 Console Anthropic

O canal canônico de truth pra billing:

  • https://console.anthropic.com/settings/usage
  • Mostra consumo por API key, por modelo, por dia
  • Atualização ~5 minutos de delay

3.2 Dentro do IAra (Settings)

A badge no Settings calcula estimativa mensal usando:

  • Histórico real (llmLogs últimos 30 dias) quando disponível
  • Defaults documentados (12 episódios + 50 cortes + 30 reels/mês) caso contrário

Threshold por mês:

  • Verde: <$20
  • Amarelo: $20-100 (zona PPTNC com Sonnet 4.6)
  • Vermelho: ≥$100

3.3 Cloud Logging

Query pra somar custo do mês corrente:

jsonPayload.event="llm.call.complete"
AND jsonPayload.provider="claude"
AND timestamp >= "2026-05-01T00:00:00Z"

Soma o jsonPayload.estimatedCostUsd no console pra obter total.

3.4 Alerts recomendados

Cloud Billing (não cobre Anthropic, mas sim Vertex AI):

  • Console GCP → Billing → Budgets & alerts
  • Threshold $20/mês

Anthropic (única forma de alertar billing real do Claude):

  • Console Anthropic → Usage → Set monthly budget cap
  • Sugestão PPTNC: $50/mês (cobre Sonnet 4.6 com folga)

4. Comportamento esperado vs Gemini

Dimensão Gemini 2.5 Flash Claude Sonnet 4.6
Custo / 1M tokens $0.075 in / $0.30 out $3 in / $15 out
Latência fase 5 (título) ~2-5s ~3-8s
Latência fase 6 (descrição) ~8-15s ~15-30s
Estilo escrita Mais conciso, técnico Mais elaborado, prosa fluida
Aderência a JSON schema Excelente Excelente (com prompt explícito)
Hallucination em fatos do transcript Moderada Menor (em geral)
Suporte a imagens Sim (Newsletter, Thumbnail) Não (Newsletter/Thumbnail seguem Gemini)

4.1 Quando Claude vale a pena

  • Fases criativas (5, 6, 7, 5B) onde o estilo importa
  • Vídeos longos (transcrição > 50K tokens) onde context window grande de Claude (200K) ajuda
  • Quando o produtor já tem assinatura Anthropic Max (créditos programáticos a partir de 15-jun-2026)

4.2 Quando Gemini é melhor

  • Fases analíticas (1-4) que são determinísticas
  • Geração de imagens (Claude não gera)
  • Operação em escala onde custo importa (>1000 chamadas/dia)
  • Quando a infraestrutura GCP já está montada e não há ANTHROPIC_API_KEY

4.3 Como decidir: rodar o A/B bench

cd apps/iara
pnpm exec tsx scripts/llm-ab-bench.ts --episodes vid-1,vid-2 --phases 5,6,7

Custo ~$0.50 por run. Output em apps/iara/scripts/.bench-output/{timestamp}/ com summary.md cego (Provider A vs B) e mapping.json separado pra julgamento sem viés.

5. Troubleshooting

5.1 RATE_LIMIT (Anthropic 429)

Sintoma: log event: 'llm.call.error' com errorCode: 'RATE_LIMIT', provider claude.

Causa: Anthropic tier rate limits — Sonnet 4.6 começa em 50 req/min, 40K tokens/min, escalando com gasto histórico.

Mitigação automática:

  • Retry loop: 30s, 60s, 120s (já em produção)
  • Auto-fallback pra Gemini se fallbackProvider: 'gemini' configurado no Settings

Resolver permanentemente:

  • Anthropic console → Settings → Usage → solicitar tier upgrade após mês de uso consistente

5.2 CONTEXT_TOO_LARGE

Sintoma: errorCode: 'API_ERROR' com mensagem contendo "context window" ou "input too long".

Causa: Transcrição passou de 200K tokens (limite Claude Sonnet 4.6). PPTNC ~3h transcript fica em ~50-70K tokens, então é raro — pode ocorrer com episódios excepcionalmente longos ou múltiplas referências.

Mitigação: nada automático. Logs mostram attachment.estimatedTokens pra diagnosticar. Se for um padrão, considerar truncar transcrições > 150K tokens antes de enviar (ainda não implementado).

5.3 Fallback acionado

Sintoma: log event: 'llm.call.fallback' aparece com primaryProvider: 'claude', fallbackProvider: 'gemini', errorCode: <código>.

Significado: Claude exauriu retries e o fallback foi acionado. O resultado retornado vem do Gemini (silenciosamente — sem alerta UI).

Ação: ignorar se ocasional. Se recorrente em uma fase específica, investigar:

  • Anthropic console pra ver tier limits
  • errorCode do log pra saber se foi rate limit, network, ou content filter

5.4 ANTHROPIC_API_KEY não definida

Sintoma: erro ao tentar gerar com Claude: ANTHROPIC_API_KEY environment variable is required.

Resolver: setar a env var. Em dev:

echo "ANTHROPIC_API_KEY=sk-ant-..." >> apps/iara/.env.local

Em Cloud Run: ver §2.

5.5 Modelo não encontrado (404)

Sintoma: Publisher Model... not found ou Model claude-X not available.

Causa frequente: ID de modelo desatualizado. A allowlist atual (src/lib/llm/models.ts):

  • claude-opus-4-7
  • claude-sonnet-4-6
  • claude-haiku-4-5-20251001

Se um modelo novo for anunciado pela Anthropic, atualizar AVAILABLE_CLAUDE_MODELS em models.ts + PRICING_USD_PER_M em anthropic-provider.ts E cost-estimator.ts.

5.6 Settings: badge "Custo estimado indisponível"

Sintoma: badge no Settings não aparece com valor.

Causa: erro no endpoint /api/podcast/cost-estimate — checar Network do browser e log do server.

Diagnóstico: tente acessar diretamente:

https://localhost:3000/api/podcast/cost-estimate?provider=claude&model=claude-sonnet-4-6

Deve retornar JSON com monthlyUsd, breakdown, threshold.

6. Migração de produtores legacy

Documentos podcast.llmConfig antigos (pré-Epic 23) não têm campo provider. Eles continuam funcionando — defaults para gemini via .catch(undefined) no schema. Não há migração necessária.

Para migrar pra Claude:

  1. Abrir Settings
  2. Trocar provider via dropdown
  3. Save automático (não precisa rerun de scripts)

7. Operação dia-a-dia

Quando reverter pra Gemini

  • Custo mensal > $50 e qualidade subjetiva não justifica
  • Latência > 30s em fases curtas atrapalhando workflow
  • Outage Anthropic (raro mas acontece)

Como: Settings → Provider de Texto → Gemini. Save automático. Próxima chamada usa Gemini.

Quando rodar o A/B bench

  • A cada nova versão major (claude-N+1)
  • Quando você suspeita que qualidade caiu
  • Mensalmente como sanity check

Quando atualizar pricing

Anthropic anuncia mudança em https://docs.anthropic.com/en/api/pricing. Atualizar:

  • apps/iara/src/lib/llm/providers/anthropic-provider.ts → PRICING_USD_PER_M
  • apps/iara/src/lib/llm/cost-estimator.ts → mesma tabela
  • apps/iara/scripts/llm-ab-bench.ts → mesma tabela
