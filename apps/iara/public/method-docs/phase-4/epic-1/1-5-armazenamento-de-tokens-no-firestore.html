Story 1.5: Armazenamento de Tokens no Firestore

Status: done

Story

Como um sistema, Eu quero armazenar tokens OAuth no Firestore com isolamento por tenant, Para que os tokens sejam persistidos de forma segura e o modelo white-label seja suportado desde o MVP.

Acceptance Criteria

AC1: Armazenamento de tokens no primeiro login

Given um usuário faz login com sucesso When os tokens são recebidos do Google Then o access_token é armazenado no Firestore And o refresh_token é armazenado no Firestore (apenas na primeira autorização) And o expires_at é armazenado para controle de expiração

AC2: Preservação de refresh_token em logins subsequentes

Given um usuário faz login subsequente When o callback do OAuth é executado Then o access_token é atualizado And o refresh_token existente NÃO é sobrescrito (preservation rule)

AC3: Estrutura de collection white-label ready

Given tokens armazenados no Firestore When eu consulto via admin SDK Then os tokens estão na collection podcasts/{podcastId}/users/{userId}/tokens/oauth And o podcastId é configurado via constante hardcoded por deploy

AC4: Firebase Admin SDK com ADC

Given a necessidade de operações server-side When eu verifico a configuração Then existe src/lib/firebase/admin.ts com inicialização do Firebase Admin SDK And usa Application Default Credentials (ADC) para autenticação And funciona localmente via gcloud auth application-default login And funciona no Cloud Run via service account do serviço

AC5: Configuração centralizada de tenant

Given o modelo white-label When eu verifico a configuração Then existe src/lib/firebase/config.ts com constantes hardcoded:

  • PROJECT_ID - ID do projeto Firebase
  • FIRESTORE_DATABASE_ID - ID do banco Firestore
  • PODCAST_ID - ID do tenant (podcast)

AC6: Firebase Client SDK configurado

Given a necessidade de operações client-side When eu verifico a configuração Then existe src/lib/firebase/client.ts com inicialização do Firebase Client SDK And usa variáveis de ambiente NEXT_PUBLIC_* para config pública

AC7: jwt callback persiste tokens

Given o callback jwt do Auth.js When um usuário faz login Then os tokens são persistidos no Firestore via admin SDK And structured logging registra a operação com podcastId

AC8: Testes unitários

Given testes unitários When eu executo pnpm test Then testes verificam o path correto podcasts/{podcastId}/users/{userId}/tokens/oauth And testes verificam a persistência de tokens And testes verificam a preservação de refresh_token

Dev Notes

Modelo White-Label

Cada podcast é um tenant isolado com deploy independente:

┌─────────────────────────────────────────────────────────────────┐
│ Cloud Run Deploy: iara-pptnc                                    │
│ PODCAST_ID = 'pptnc' (hardcoded em src/lib/firebase/config.ts) │
│ → podcasts/pptnc/users/{userId}/tokens/oauth                   │
│ → podcasts/pptnc/videos/{videoId}                              │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│ Cloud Run Deploy: iara-outro-podcast                            │
│ PODCAST_ID = 'outro-podcast' (hardcoded)                        │
│ → podcasts/outro-podcast/users/{userId}/tokens/oauth           │
│ → podcasts/outro-podcast/videos/{videoId}                      │
└─────────────────────────────────────────────────────────────────┘
  • Mesmo codebase: cada tenant clona e altera apenas PODCAST_ID
  • Mesma base Firestore: isolamento por subcollection
  • Escala horizontal independente: cada Cloud Run service escala separadamente
  • Contas Google separadas: cada tenant tem seu próprio admin

Configuração de Tenant (src/lib/firebase/config.ts)

/** Firebase project ID */
export const PROJECT_ID = 'pptnc-stage'

/** Firestore database ID */
export const FIRESTORE_DATABASE_ID = 'pptnc-stage'

/**
 * Podcast ID for this tenant deployment.
 * CRITICAL: Change this value when deploying a new tenant.
 */
export const PODCAST_ID = 'pptnc'

Firebase Admin SDK com ADC (src/lib/firebase/admin.ts)

import { applicationDefault, getApps, initializeApp } from 'firebase-admin/app'
import { getFirestore } from 'firebase-admin/firestore'
import { FIRESTORE_DATABASE_ID, PROJECT_ID } from './config'

// Autenticação via ADC:
// - Local: gcloud auth application-default login
// - Cloud Run: service account do serviço (automático)
adminApp = initializeApp({
  credential: applicationDefault(),
  projectId: PROJECT_ID,
})

adminDb = getFirestore(adminApp, FIRESTORE_DATABASE_ID)

Token Storage Path

podcasts/{PODCAST_ID}/users/{userId}/tokens/oauth
├── accessToken: string
├── refreshToken: string (NEVER overwrite)
├── expiresAt: number
└── updatedAt: Timestamp

Enforcement Rules Aplicáveis

  1. Rule #3 (Runtime Node): Tokens são acessados apenas server-side via admin SDK
  2. Rule #4 (Field-Level Updates): Usar set({ merge: true }) para não sobrescrever
  3. Rule #8 (PodcastId): Incluir podcastId em toda query Firestore
  4. Rule #9 (Structured Logging): Usar log() com podcastId em todas as operações
  5. Rule #12 (Timestamp SDK): Usar FieldValue.serverTimestamp() no admin SDK
