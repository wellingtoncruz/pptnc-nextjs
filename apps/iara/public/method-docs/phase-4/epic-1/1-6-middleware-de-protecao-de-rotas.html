Story 1.6: Middleware de Proteção de Rotas

Status: done

Story

Como um sistema, Eu quero proteger rotas que requerem autenticação, Para que usuários não autenticados sejam redirecionados ao login.

Acceptance Criteria

AC1: Redirecionamento de usuários não autenticados

Given um usuário não autenticado When ele tenta acessar /videos Then é redirecionado para /login

AC2: Acesso permitido para usuários autenticados

Given um usuário autenticado When ele acessa /videos Then a página é renderizada normalmente

AC3: SSE endpoints sem buffering

Given uma requisição para endpoint SSE (/api/process/*) When o middleware intercepta Then NÃO aplica buffering na response And verifica autenticação sem bloquear o stream

AC4: Rotas públicas de auth

Given uma requisição para /api/auth/* When o middleware intercepta Then permite acesso sem autenticação (rotas públicas)

AC5: Localização correta do middleware

Given a estrutura do projeto Next.js When eu verifico a localização do middleware Then existe src/middleware.ts na raiz de src/ And NÃO está em src/app/middleware.ts

AC6: Matcher configuration

Given o middleware configurado When eu verifico o matcher Then exclui: /_next, /api/auth, assets estáticos (favicon.ico, etc) And protege: /videos, /settings, /api/* (exceto auth)

AC7: Página de login

Given um usuário não autenticado redirecionado When ele chega na página /login Then vê opção de "Entrar com Google" And após login bem-sucedido, é redirecionado para a URL original

AC8: Testes unitários

Given testes para o middleware When eu executo pnpm test Then testes verificam redirecionamento de usuários não autenticados And testes verificam passagem de usuários autenticados And testes verificam exclusão de rotas públicas

Dev Notes

Arquitetura do Middleware no Next.js 15+

O middleware deve estar em src/middleware.ts (na raiz de src/, NÃO em src/app/).

Estrutura correta:

src/
├── middleware.ts    ← AQUI (raiz de src/)
├── app/
│   └── ...

Auth.js v5 no Middleware

Auth.js v5 fornece helper para middleware:

// src/middleware.ts
import { auth } from './lib/auth'

export default auth((req) => {
  const isAuthenticated = !!req.auth
  // ... lógica de redirecionamento
})

export const config = {
  matcher: ['/((?!api/auth|_next/static|_next/image|favicon.ico).*)'],
}

Matcher Configuration

Rotas a EXCLUIR (públicas):

  • /_next/* - Assets do Next.js
  • /api/auth/* - Endpoints de autenticação
  • /favicon.ico - Favicon
  • /login - Página de login

Rotas a PROTEGER:

  • /videos - Lista de vídeos
  • /videos/* - Subpáginas de vídeos
  • /settings - Configurações
  • /api/* (exceto /api/auth/*) - API routes

SSE Endpoints - NFR4

Endpoints SSE (/api/process/*) precisam de tratamento especial:

  • Middleware NÃO pode aplicar buffering
  • Usar NextResponse.next() para passar a request sem modificação
  • Verificar auth mas não bloquear o stream
// Para SSE endpoints
if (req.nextUrl.pathname.startsWith('/api/process')) {
  if (!isAuthenticated) {
    return new NextResponse(
      JSON.stringify({ error: { code: 'AUTH_EXPIRED', message: 'Sessão expirada' } }),
      { status: 401, headers: { 'Content-Type': 'application/json' } }
    )
  }
  return NextResponse.next() // Não aplica buffering
}

Página de Login

// src/app/login/page.tsx
import { signIn } from '@/lib/auth'

export default function LoginPage() {
  return (
    <form action={async () => {
      'use server'
      await signIn('google', { redirectTo: '/videos' })
    }}>
      <button type="submit">Entrar com Google</button>
    </form>
  )
}

Enforcement Rules Aplicáveis

  1. Rule #3 (Runtime Node): Se middleware precisar chamar APIs, verificar runtime
  2. Rule #9 (Structured Logging): Usar log() para erros de auth
  3. NFR4 (Middleware): SSE endpoints não podem ter buffering
