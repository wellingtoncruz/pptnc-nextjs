Retrospective - Epic 11: Melhorias v2.1.0

Date: 2026-02-07 Facilitator: Bob (Scrum Master) Participants: Alice (PO), Charlie (Senior Dev), Dana (QA), Elena (Junior Dev), Wellington (Project Lead) Epic: 11 — Melhorias v2.1.0 (v2.1.0-beta-iara) Previous Retro: Epic 10 — skipped (optional)

Stories Delivered

Story Scope Tests Review Issues
11-1 LinkedIn Profile Scraping BrightData API, subcollection guests, avatar download, fire-and-forget 69 1H, 4M, 2L
11-2 Reabrir Episódio YouTube API verification, state machine reopen, AlertDialog 27 1H, 3M, 2L
11-3 Seção Editorial Route handler, EpisodeCard, EditorialPanel, sidebar, grid 52 1H, 4M, 2L

Successes

  1. Velocidade excepcional — 3 stories com escopos distintos (integração externa, state machine, nova UI) completadas no mesmo dia
  2. Reutilização de infraestrutura — state machine reopen já existia, VideoThumbnail e view switching pattern prontos, schemas Zod reaproveitados
  3. Code review adversarial funcionando — encontrou issues reais (H1) em todas as stories, todos corrigidos antes de done
  4. Story 11-2 executada com precisão — spec → implementação alinhados, reabrir episódio funciona como especificado
  5. Aprendizado incremental entre stories — lição de Timestamp.now() vs FieldValue.serverTimestamp() da 11-2 aplicada corretamente na 11-1

Challenges

  1. Story 11-1 (LinkedIn Scraping) teve bugs evitáveis — fire-and-forget sem dedup (M2), photoPath nunca passado ao upsertGuest (M3), avatar download sem timeout (M4). Implementação task-by-task sem validação do fluxo completo.
  2. Testes pré-existentes quebrados (19-26) em todas as stories — ruído em use-videos, settings-page-client, video-header, users-admin, users, videos-admin, phase-5-title, phase-5b-short-title. Mascara regressões reais.
  3. Documentação desatualizada — story file 11-3 não acompanhou refinamentos (9→16 episódios, 3→4 colunas, variant outline→default, ScrollArea→overflow-y-auto). Code review pegou como H1.

Key Insights

  1. Validação de fluxo end-to-end antes da review é essencial — implementação task-by-task produz código que funciona isoladamente mas falha na integração. Especialmente crítico para integrações externas com custo real (BrightData API paga).
  2. Baseline de testes verde é pré-requisito — começar um epic com falhas pré-existentes prejudica a confiança e pode esconder regressões reais.
  3. Investimento em arquitetura paga dividendos — infraestrutura dos epics 1-5 e 8 acelerou significativamente o Epic 11.
