Story 11.2: Reabrir Episódio para Edição

Status: done

Story

As a produtor de conteúdo, I want reabrir manualmente um vídeo já enviado (status sent) para editar seus metadados, so that eu possa corrigir erros ou atualizar informações sem depender do sync automático.

Acceptance Criteria

  1. AC1 - AlertDialog ao clicar em vídeo sent: Given um vídeo com status sent na lista, When o produtor clica nele, Then exibe AlertDialog com título "Deseja reabrir esse vídeo para edição dos metadados?" e feedback visual "Para o vídeo ser reaberto, é necessário que ele esteja como Privado, Rascunho ou Não listado no YouTube".

  2. AC2 - Verificação YouTube API e reopen bem-sucedido: Given o produtor confirma no AlertDialog, When o sistema verifica via YouTube Data API v3 e o vídeo tem privacyStatus: private (sem publishAt) ou privacyStatus: unlisted, Then o status muda de sent para draft via transition(status, 'reopen'), a lista de vídeos é atualizada, e toast mostra "Vídeo reaberto para edição".

  3. AC3 - Bloqueio para vídeo público: Given o vídeo no YouTube com privacyStatus: public, When a verificação completa, Then exibe mensagem de erro dentro do AlertDialog: "O vídeo não está com o status adequado no YouTube. Não é possível reabrir. Altere o vídeo para Não Listado."

  4. AC4 - Bloqueio para vídeo programado: Given o vídeo no YouTube com privacyStatus: private E publishAt preenchido (agendado/programado), When a verificação completa, Then exibe a mesma mensagem de erro (vídeo programado não pode ser reaberto).

  5. AC5 - Erro na chamada YouTube API: Given erro na chamada à YouTube API, When a verificação falha, Then exibe mensagem de erro no AlertDialog: "Erro ao verificar status do vídeo no YouTube. Tente novamente." e erro logado via structured logging.

  6. AC6 - Loading state: Given o produtor confirma no AlertDialog, When a verificação YouTube está em andamento, Then o botão de confirmar mostra loading state (spinner) e fica desabilitado.

YouTube API - Verificação de Status

O YouTubeClient.getVideoDetails() já busca part=status e retorna privacyStatus. Porém NÃO retorna publishAt (campo de agendamento). Opções:

  1. Criar método dedicado checkVideoEligibility(videoId) no YouTubeClient que retorna { privacyStatus, publishAt?: string, eligible: boolean } — RECOMENDADO
  2. Estender getVideoDetails para incluir publishAt no mapeamento

O campo publishAt está em item.status.publishAt na response da YouTube Data API quando part=status é incluído. O getVideoDetails já pede part=snippet,contentDetails,status,liveStreamingDetails (client.ts:328), então os dados já vêm na response — só falta extraí-los no mapeamento.

Importante: O sync automático (sync-videos.ts:466-467) atualiza os campos youtubePrivacyStatus e visibilityUpdatedAt ao fazer reopen. O Route Handler manual DEVE atualizar os mesmos campos para manter consistência.
