Story 11.3: Seção Editorial

Status: done

Story

As a produtor de conteúdo, I want uma seção editorial com visão dos episódios em grid, so that eu tenha uma visão rápida e visual dos episódios recentes e possa acessar relatórios editoriais futuramente.

Acceptance Criteria

  1. AC1 - Menu Editorial: Given o menu lateral da aplicação, When renderizado, Then exibe nova entrada "Editorial" posicionada entre "Vídeos" e "Usuários", And ao clicar navega para /videos?view=editorial.

  2. AC2 - Grid de Episódios: Given o produtor acessa a view Editorial, When a página carrega, Then exibe grid responsivo com os 16 episódios mais recentes (videoType episode), ordenados do mais recente ao mais antigo.

  3. AC3 - Card do Episódio: Given cada card no grid, When renderizado, Then exibe: thumbnail 16:9 (via VideoThumbnail), título do episódio (CardTitle), descrição truncada (CardDescription line-clamp-2), badge de status no canto superior (CardAction, mesmas cores da lista principal), e botão "Relatório Editorial" full-width no CardFooter (variant="default", desabilitado, tooltip "Em breve").

  4. AC4 - Busca por Título: Given a barra de busca no topo da seção, When o produtor digita um termo, Then filtra client-side por correspondência parcial no título (case-insensitive), And o grid atualiza com os resultados em debounce 300ms, And os detalhes completos dos vídeos filtrados são carregados para montar os cards.

  5. AC5 - Empty State: Given a busca não encontra resultados, When o grid está vazio, Then exibe empty state: "Nenhum episódio encontrado". Given o produtor limpa a barra de busca, When o campo fica vazio, Then volta a exibir os 16 episódios mais recentes.

  6. AC6 - Responsividade: Given a página Editorial em diferentes viewports, When renderizada, Then exibe 4 colunas em desktop (xl), 3 em large (lg), 2 em tablet (md), 1 em mobile.

Dev Notes

Padrão de View Switching (CRÍTICO)

O projeto usa ?view= query params para switching de views, NÃO rotas separadas. Todas as views estão dentro de /videos:

  • /videos → lista de vídeos (default)
  • /videos?view=settings → painel de configurações
  • /videos?view=users → gestão de usuários
  • /videos?view=editorial → NOVA seção editorial

NÃO criar src/app/editorial/page.tsx. Usar o padrão existente em videos-layout.tsx.

Sidebar — Posição do Item Editorial

O array navItems no sidebar.tsx atualmente tem:

  1. Vídeos (/videos) — para todos
  2. Usuários (/videos?view=users) — adminOnly
  3. Configurações (/videos?view=settings) — adminOnly

O item "Editorial" deve ficar entre Vídeos e Usuários (posição 2, index 1).

A condição isActive de Vídeos precisa excluir isEditorialView:

isActive: (pathname === '/videos' || pathname?.startsWith('/videos/')) && !isSettingsView && !isUsersView && !isEditorialView,

VideoThumbnail — Reutilizar Componente Existente

O VideoThumbnail (src/components/ui/video-thumbnail.tsx) já resolve:

  • Fallback chain (custom → hqdefault → default → placeholder)
  • Data URIs (base64 thumbnails)
  • URLs com query params expiráveis (ignora signed URLs)

Para o card editorial, usar com dimensões maiores (aspect 16:9):

<VideoThumbnail
  youtubeId={episode.id}
  thumbnailUrl={episode.thumbnailUrl}
  alt={episode.title}
  width={480}
  height={270}
  className="w-full rounded-t-lg"
/>

Status Badge — Constantes Existentes

As constantes statusColors e statusLabels estão em video-list-item.tsx (linhas ~20-40). Como são constantes locais (não exportadas), há duas opções:

  1. Duplicar no episode-card.tsx (simples, sem risco de regressão)
  2. Extrair para arquivo compartilhado src/lib/video-status.ts

Recomendação: Duplicar — são ~10 linhas e a story 11-3 não deve tocar em video-list-item.tsx.

Endpoint — Abordagem Simplificada

O epic sugere dois endpoints (summary + batch), mas isso adiciona complexidade desnecessária. Um único endpoint GET /api/editorial/episodes que retorna os campos necessários é suficiente (endpoint separado de /api/videos/episodes para evitar conflito com seleção de episódio-pai):

// GET /api/editorial/episodes?limit=16&search=termo
// Response: { data: EpisodeSummary[] }

interface EpisodeSummary {
  id: string
  title: string
  description?: string
  status: VideoStatus
  thumbnailUrl?: string
  publishedAt?: string
}

Query Firestore com select() para projeção de campos (não trazer documento inteiro):

const snapshot = await videosRef
  .where('videoType', '==', 'episode')
  .select('title', 'description', 'status', 'thumbnails', 'storageThumbnailUrl', 'publishedAt')
  .get()

Filtragem por título: Firestore não suporta LIKE. Fazer server-side em memória após query:

const filtered = episodes.filter(e =>
  e.title.toLowerCase().includes(searchTerm.toLowerCase())
)

Busca — Debounce Pattern

Usar o pattern de debounce simples com useEffect:

const [searchInput, setSearchInput] = useState('')
const [debouncedSearch, setDebouncedSearch] = useState('')

useEffect(() => {
  const timer = setTimeout(() => setDebouncedSearch(searchInput), 300)
  return () => clearTimeout(timer)
}, [searchInput])

// Fetch com debouncedSearch como dependência
useEffect(() => {
  fetchEpisodes(debouncedSearch)
}, [debouncedSearch])

Layout — Full Width (sem Master-Detail)

A view editorial usa layout full-width com sidebar, SEM o MasterDetailLayout (sem resizable panels):

if (currentView === 'editorial') {
  return (
    <div className="flex h-screen">
      <div className="shrink-0">
        <Sidebar userName={userName} />
      </div>
      <div className="flex-1 overflow-hidden">
        <EditorialPanel />
      </div>
    </div>
  )
}

Seguir exatamente o padrão de currentView === 'settings' em videos-layout.tsx (linhas 132-143).

Sem Paginação — Design Intencional

O epic especifica sem paginação. O limit=16 mostra os 16 mais recentes (4x4 grid). Quando busca está ativa, mostra todos os resultados sem limit. Nota: A query Firestore carrega todos os episódios em memória — aceitável no volume atual (~50-100 episódios), mas pode precisar de .orderBy().limit() no Firestore se escalar.

Lições das Stories Anteriores (11-1, 11-2)
