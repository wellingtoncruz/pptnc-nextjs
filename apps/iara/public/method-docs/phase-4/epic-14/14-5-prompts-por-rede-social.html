Story 14.5: Prompts por Rede Social por Tipo de Vídeo

Status: done

Story

As a administrador do podcast, I want configurar prompts específicos para cada rede social e tipo de vídeo, so that a IA gere posts otimizados para cada plataforma.

Prerequisites

BLOQUEANTES — Devem estar implementadas ANTES de iniciar esta story:

  • Story 14.2 — SocialNetworkSchema + getSocialNetworks() + GET /api/social-networks
  • Story 14.3 — features.socialMedia no schema
  • Story 14.4 — enabledSocialNetworks[] no schema + accordion condicional + socialNetworks prop no SettingsPageClient

Acceptance Criteria

  1. Schema estendido — Cada tipo de prompt (EpisodePromptsSchema, CutPromptsSchema, ReelPromptsSchema) inclui social: z.record(z.string(), PromptFieldSchema).optional(). A chave do record é o networkId (ex: 'instagram', 'linkedin').

  2. Defaults atualizados — DEFAULT_EPISODE_PROMPTS, DEFAULT_CUT_PROMPTS, DEFAULT_REEL_PROMPTS não incluem campo social (é .optional(), ausência é aceitável). Podcasts existentes sem prompts sociais continuam funcionando.

  3. UI renderiza subseção — Dentro de cada tipo de vídeo (Episódios, Cortes, Reels) no accordion "Prompts por Tipo de Vídeo", há uma subseção "Redes Sociais" que aparece somente quando enabledSocialNetworks.length > 0. Para cada rede habilitada, exibe dois campos: "Descrição do Prompt" e "Saída Esperada", identificados por {icon} {networkName}.

  4. Save funciona — Ao editar um prompt social, o auto-save dispara após 1.5s via PATCH /api/podcast com prompts atualizados. O path no Firestore é prompts.{videoType}.social.{networkId}.{description|expectedOutput}.

  5. Rede desabilitada não aparece — Se uma rede for desabilitada em Configurações → Redes Sociais (Story 14.4), seus prompts NÃO aparecem na UI, mas os dados persistem no Firestore.

  6. Nenhuma rede habilitada — Se enabledSocialNetworks está vazio, a subseção "Redes Sociais" NÃO aparece dentro dos tipos de vídeo.

  7. Testes atualizados — Testes de prompts-settings-form.test.tsx verificam renderização condicional da subseção social e save de prompt social.

Dev Notes

Arquitetura e Padrões

  • z.record() para N redes: Usar z.record(z.string(), PromptFieldSchema) permite adicionar novas redes sem alterar o schema. A chave é o networkId, o valor é { description, expectedOutput }.
  • PromptFieldEditor reutilizável: O componente existente aceita qualquer fieldKey e label. Para social prompts, usar fieldKey={videoType}-social-{networkId} e label={icon} {name}.
  • Auto-save 1.5s via useAutoSave: O PromptFieldEditor já implementa debounce. Cada instância tem seu próprio timer. Não precisa modificar o hook.
  • Ref pattern para stale closures: O handleSavePromptField usa promptsRef para capturar estado mais recente. O path nested social.{networkId} requer spread extra no nível social.
  • fieldName convention: Prompts fixos usam fieldName simples ('critique', 'titles'). Prompts sociais usam 'social.{networkId}' (ex: 'social.instagram'). O handleSavePromptField parseia o prefix 'social.' para construir o nested update.
  • Subseção separada visualmente: A subseção "Redes Sociais" dentro de cada videoType é separada por border-t e tem header <h4> discreto. Isso diferencia visualmente os prompts fixos (fases do Wizard) dos prompts sociais (dinâmicos por rede).
  • Exclude<keyof, 'social'> obrigatório: Ao adicionar social aos schemas, keyof EpisodePrompts inclui 'social'. Mas FIELD_LABELS, EPISODE_FIELDS, etc. mapeiam apenas fields fixos do Wizard. Usar Exclude para excluir 'social' dos type aliases. Sem isso, TypeScript exigirá social em FIELD_LABELS e nos arrays, causando erro de compilação.
  • Graceful degradation: Se socialNetworks prop está vazio mas enabledSocialNetworks tem IDs (dados stale), socialNetworks.find() retorna undefined e o if (!network) return null no render ignora silenciosamente. Comportamento aceitável.

Backward Compatibility

O campo social é .optional() em cada prompt schema. Podcasts existentes sem prompts sociais continuam funcionando — o parse retorna undefined para social, e a UI renderiza campos vazios via ?? DEFAULT_PROMPT_FIELD. Nenhuma migração é necessária.
