Story 14.2: Collection Global socialNetworks + Seed

Status: done

Story

As a sistema, I want uma collection global de redes sociais disponíveis no Firestore, so that novos tenants possam ver e habilitar redes sociais sem alteração de código.

Acceptance Criteria

  1. Schema Zod SocialNetworkSchema — Novo arquivo src/lib/schemas/social.ts com schema validando { id: string, name: string, icon: string, createdAt: Timestamp }. Exportado no barrel src/lib/schemas/index.ts.

  2. Type inferido — Novo arquivo src/types/social.ts com type SocialNetwork = z.infer<typeof SocialNetworkSchema>. Exportado no barrel src/types/index.ts (se existir) ou importável diretamente.

  3. Função getSocialNetworks() — Novo arquivo src/lib/firebase/social-admin.ts com função que retorna SocialNetwork[] validado com Zod, ordenado por name ascendente. Usa safeParse() para resiliência (docs inválidos geram log WARN e são ignorados).

  4. Seed script atualizado — scripts/seed-podcast.ts cria documentos socialNetworks/instagram e socialNetworks/linkedin na collection global. Criação idempotente (verifica existência antes de criar). Executado ANTES da criação do podcast.

  5. Seed idempotente — Se socialNetworks/instagram já existe no Firestore, o seed NÃO sobrescreve. Log informativo: "socialNetworks/instagram already exists, skipping".

  6. Testes — Testes unitários para getSocialNetworks() e para o schema SocialNetworkSchema.

Dev Notes

Arquitetura e Padrões

  • Collection global vs per-podcast: socialNetworks é global (no root do Firestore, não dentro de podcasts/{podcastId}). Isso permite que qualquer podcast habilite redes do catálogo global. NÃO incluir podcastId no path.
  • safeParse() em loops: Para resiliência a schema evolution, usar safeParse() (não parse()) ao iterar documentos. Docs inválidos geram log WARN e são ignorados, sem quebrar a leitura.
  • Seed idempotente: Verificar existing.exists antes de .set(). Para social networks, iterar cada network independentemente (um pode existir e outro não).
  • Seed antes do podcast: A função seedSocialNetworks() deve ser chamada ANTES do check de existência do podcast, porque a collection é global e deve existir independentemente do podcast.
  • Imports: Seguir padrão @/lib/... para imports internos. Zod primeiro, depois Firebase admin, depois schemas locais, depois logger, depois admin db.
  • id não é campo do documento: O id é o Firestore document ID (ex: 'instagram'), injetado no read via { id: doc.id, ...doc.data() }. O .set() no seed NÃO inclui id no data — seguindo padrão de podcasts-admin.ts.
  • Seed script não usa @/ imports: O seed script (scripts/seed-podcast.ts) é standalone, usa imports diretos de firebase-admin/*, variável db module-level, e console.log (não structured logger).
  • Seed não atualiza DEFAULT_PERSONAS: NÃO adicionar socialmedia ao DEFAULT_PERSONAS do seed nesta story. Isso é escopo da Story 14.11 (seed + onboarding).

const existing = await podcastRef.get()
if (existing.exists) {
  console.log(`Podcast already exists. Skipping seed.`)
  return
}

Padrão safeParse em loops (news-admin.ts):

for (const doc of snapshot.docs) {
  const parsed = NewsSchema.safeParse({ id: doc.id, ...doc.data() })
  if (parsed.success) {
    items.push(parsed.data)
  } else {
    log('WARN', 'Invalid news document skipped', { newsId: doc.id, issues: parsed.error.issues })
  }
}

Padrão de collection helper (guests-admin.ts):

function getGuestsCollection(podcastId: string) {
  const db = getAdminDb()
  return db.collection('podcasts').doc(podcastId).collection('guests')
}

TimestampSchema (podcast.ts):

export const TimestampSchema = z.custom<FirestoreTimestamp>(
  (val) => val !== null && typeof val === 'object' && 'toDate' in val,
  'Invalid Firestore Timestamp'

Type inference pattern (types/podcast.ts):

Barrel export pattern (schemas/index.ts):

export { SomeSchema, SOME_CONSTANT } from './some-module'

Learnings da Story 14.1

  • Padrão union type deve ser explícito em todas as interfaces/type annotations
  • .optional() requer fallback (?? DEFAULT_VALUE) nos consumidores
  • Testes usam DEFAULT_* constants do schema — update automático ao alterar constantes
  • Labels PT-BR devem ser verificados contra o código existente (ex: "Resumo / Contexto", não "Currículo")

Backward Compatibility

Esta story cria artefatos novos (schema, firebase admin, seed). Não modifica nenhum artefato existente de forma destrutiva. Podcasts existentes não são afetados — a collection socialNetworks é adicionada ao Firestore de forma aditiva.
