Sucessos

  1. Velocidade excepcional — 13 stories, 100% de conclusão, alta aderência aos requisitos especificados
  2. Reutilização de infraestrutura — callGenAI (Epic 13), llmQueue (Epic 4), schemas Zod, useAutoSave, URL state pattern — nada reinventado
  3. Abstração do variant no VideoListPanel — decisão arquitetural acertada que estimula reuso. Bug do editorial corrigido com 1 linha
  4. Code review adversarial maduro — 50+ issues encontrados e corrigidos, incluindo 3 critical e ~8 high. Processo pega bugs reais
  5. Zero tech debt novo — nenhum item de tech debt criado em 13 stories
  6. Zero incidentes em produção
  7. Progressão natural dos blocos — Config → Backend → Frontend → Infra → UX, cada story com contexto claro

Desafios

  1. Falta de atenção ao UX — Todas as regras de negócio cumpridas corretamente, mas ninguém pensou na experiência do produtor. Layout inicial pobre. Duas stories extras (14.12 + 14.13 = ~15% do épico) gastas exclusivamente em remediação de UX (filtros, sort sent-first, excludeTypes, variant behavior)
  2. AbortController recorrente — Correções de lifecycle em 14.9 e 14.10 (leak de memória no CopyButton, tracking de abort em retry)
  3. Code review cego a UX — Em 50+ issues encontrados, zero eram sobre experiência do usuário. Quality gate puramente técnico
  4. Bug do variant — Vídeos "sent" e "episode" sumiram da aba Vídeos porque variant='editorial' não era explícito. Detectado apenas em uso real no browser, escapou de todos os testes
  5. Build quebrado não detectado — 3 erros de TypeScript strict (null vs undefined, cast de Record com social, useRef sem argumento) passaram no vitest mas quebraram next build

Key Insights

  1. UX não pode ser afterthought — ACs estruturais ("componente renderiza X") produzem código correto mas não necessariamente usável. ACs devem ser orientados ao que o produtor faz, não ao que o componente renderiza
  2. Testes verdes ≠ deploy seguro — vitest run passava mas next build quebrava. Build de produção deve fazer parte da validação obrigatória
  3. Abstração > duplicação — Parametrizar comportamento existente (variant) é superior a criar componentes separados. Responsabilidade bem segregada (VideoListPanel → variant → sentAppearance → VideoListItem)
  4. Lições aplicadas da retro anterior funcionam — 3/4 action items do Epic 11 cumpridos, impacto positivo real: zero fluxos quebrados, stories atualizadas, baseline verde
