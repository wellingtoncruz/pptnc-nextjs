Story 14.12: Ajustes de UX na Social View

Status: done

Story

As a produtor, I want que a seção de Redes Sociais tenha filtros otimizados, layout mais agradável e CTA multi-line, so that eu consiga usar a feature de forma eficiente e prazerosa.

Prerequisites

BLOQUEANTES — Devem estar implementadas ANTES de iniciar esta story:

  • Stories 14.1–14.11 — Todo o épico 14 implementado

Acceptance Criteria

  1. Filtro default "todos" com sent-first — Na social view, o statusFilter default é 'all' (não 'not_sent'). Vídeos com status sent aparecem primeiro na lista, seguidos dos demais. Ambos os grupos ordenados por mais recente (publishedAt desc).

  2. Excluir episódios do filtro de tipo — Na social view, o filtro de tipo de vídeo NÃO exibe a tab "Episódios". Tabs disponíveis: "Todos", "Cortes", "Reels". Nota: "Todos" na social view significa cortes + reels (exclui episódios).

  3. CTA multi-line — O campo CTA no SocialPostEditor é um <Textarea> com auto-resize (mín 2 linhas), não um <Input> single-line. Preserva auto-save e copy-to-clipboard existentes.

  4. Visual polish nas colunas — Cada coluna social tem:

    • Card com rounded-lg border shadow-sm e padding interno
    • Header com fundo sutil colorido por rede (usando a cor/identidade da rede)
    • Ícone da rede em destaque no header (tamanho maior)
    • Labels de seção (CTA, Corpo, Hashtags) com estilo text-xs uppercase tracking-wide text-muted-foreground
    • Hashtags renderizadas como pills/badges com fundo muted
    • Espaçamento generoso entre seções

  5. Testes atualizados — Testes existentes adaptados para os novos behaviors. Novos testes onde necessário.

Tasks / Subtasks

  • Task 1: Filtro default "todos" + sort sent-first na social view (AC: #1)

    • 1.1 Em social-layout.tsx: passar statusFilter='all' como initial option ao useVideos
    • 1.2 Em social-layout.tsx: após receber videos do hook, fazer sort client-side: sent primeiro (por publishedAt desc), depois os demais (por publishedAt desc)
    • 1.3 Passar os vídeos re-ordenados ao VideoListPanel

  • Task 2: Excluir episódios do filtro na social view (AC: #2)

    • 2.4 Filtrar episódios client-side dos videos recebidos (para garantir que "Todos" não inclua episódios)

  • Task 3: CTA multi-line (AC: #3)

Dev Notes

Arquitetura e Padrões

  • Sort client-side: O sort sent-first é feito em social-layout.tsx após receber os videos do useVideos hook. Não alterar o backend nem o hook — manter o re-sort como lógica local da social view. Usar useMemo para memoizar.

  • Excluir episódios: Duas camadas: (1) tabs do VideoListPanel filtradas via excludeTypes prop, (2) videos filtrados client-side para remover episódios. Não alterar a query do backend — manter filtro client-side.

  • CTA textarea: O schema SocialPostUpdateSchema já aceita string sem restrições. Não precisa de mudança no backend. O auto-save continua funcionando porque useAutoSave não se importa se o valor vem de Input ou Textarea.

  • Visual polish: Usar classes existentes do Tailwind/shadcn. Não adicionar CSS customizado. Badge pode usar o componente Badge do shadcn ou simplesmente inline-flex px-2 py-0.5 rounded-full bg-muted text-xs.
