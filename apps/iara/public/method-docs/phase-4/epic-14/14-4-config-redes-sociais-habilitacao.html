Story 14.4: Seção "Redes Sociais" em Configurações (Habilitação por Podcast)

Status: done

Story

As a administrador do podcast, I want habilitar e desabilitar redes sociais individualmente para meu podcast, so that eu escolha em quais redes quero gerar posts.

Acceptance Criteria

  1. Schema enabledSocialNetworks — O PodcastSchema em src/lib/schemas/podcast.ts inclui enabledSocialNetworks: z.array(z.string()).default([]). Backward-compatible (podcasts existentes sem campo recebem array vazio).

  2. API GET social networks — Novo endpoint GET /api/social-networks retorna { data: SocialNetwork[] } lendo da collection global socialNetworks via getSocialNetworks() (criado na Story 14.2).

  3. Accordion condicional — Na tela Configurações, um novo accordion "Redes Sociais" (ID: social_networks) aparece somente quando features.socialMedia === true. Posição: entre "Recursos" e "Duração por Tipo de Vídeo".

  4. Lista de redes com toggles — O accordion lista todas as redes da collection global socialNetworks. Cada rede mostra {icon} {name} com Switch à direita. Switch checked se networkId está em enabledSocialNetworks[].

  5. Toggle salva — Ao ativar uma rede, o networkId é adicionado a enabledSocialNetworks[] e salvo via PATCH /api/podcast com { enabledSocialNetworks: [...] }. Ao desativar, o networkId é removido. Save imediato com optimistic update e rollback on error.

  6. Rede nova aparece automaticamente — Se uma nova rede for adicionada ao catálogo global (via Firestore Console), ela aparece na lista como desabilitada na próxima abertura das Configurações.

  7. Testes — Testes do novo componente social-networks-settings-form.tsx e do endpoint GET /api/social-networks.

Prerequisites

BLOQUEANTES — Devem estar implementadas ANTES de iniciar esta story:

  • Story 14.2 — src/lib/firebase/social-admin.ts com getSocialNetworks() e src/lib/schemas/social.ts com SocialNetworkSchema
  • Story 14.3 — features.socialMedia no PodcastSchema e toggle na UI

export const runtime = 'nodejs'

export async function GET() {
  const session = await auth()
  const authError = requireAuth(session)
  if (authError) return authError

  try {
    const networks = await getSocialNetworks()
    return NextResponse.json({ data: networks })
  } catch (error) {
    log('ERROR', 'Failed to fetch social networks', { error })
    return NextResponse.json(
      { error: { code: 'INTERNAL_ERROR', message: 'Erro ao carregar redes sociais' } },
      { status: 500 }
    )
  }
}

  setSaving(true)
  setError(null)

Dev Notes

Arquitetura e Padrões

  • Optimistic update + rollback: Padrão idêntico ao features-settings-form.tsx. Toggle atualiza estado local, faz PATCH, reverte se falhar.
  • Array replacement: O PATCH envia o array inteiro enabledSocialNetworks: [...]. Firestore substitui o campo por completo (field-level merge). Não é necessário usar arrayUnion/arrayRemove.
  • Accordion condicional: O accordion "Redes Sociais" só renderiza se features.socialMedia === true. Se o admin desabilitar o feature toggle (Story 14.3), a seção desaparece. Os dados em enabledSocialNetworks persistem no Firestore (não são deletados).
  • Fetch client-side: SettingsPanel já é client component. O fetch de social networks segue o mesmo padrão do fetch de podcast (useEffect no mount). Não precisa de Server Component.
  • Endpoint sem admin: GET /api/social-networks requer apenas autenticação (requireAuth), não admin (requireAdmin). O catálogo global é público para qualquer usuário autenticado.
  • socialNetworks prop opcional: O SettingsPageClient recebe socialNetworks? como optional prop. Se o fetch falhar, a prop é undefined/empty e o accordion não renderiza (graceful degradation via socialNetworks && na condição).
