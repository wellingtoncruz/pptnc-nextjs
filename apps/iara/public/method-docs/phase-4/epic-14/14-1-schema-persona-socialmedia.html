Story 14.1: Schema e Persona socialmedia (Gerente de Mídia)

Status: done

Story

As a administrador do podcast, I want configurar uma persona especialista em redes sociais (Gerente de Mídia), so that a IA gere posts com tom e estilo de redação publicitária profissional.

Acceptance Criteria

  1. PersonasSchema estendido — O schema PersonasSchema em src/lib/schemas/podcast.ts inclui a persona socialmedia com os mesmos campos e constraints das existentes (role, objective, resume), usando PersonaSchema existente. Campo .optional() para backward-compatibility.

  2. DEFAULT_PERSONAS atualizado — DEFAULT_PERSONAS inclui socialmedia: { role: '', objective: '', resume: '' }.

  3. UI renderiza terceira persona — Na tela Configurações → Personas do LLM, há três seções: Crítico, Redator, Gerente de Mídia. Cada uma com os 3 campos (Papel, Objetivo, Resumo / Contexto) com auto-save.

  4. Save funciona para socialmedia — Ao editar campos da persona Gerente de Mídia, o auto-save dispara via PATCH /api/podcast com { personas: { ...current, socialmedia: {...} } } e persiste corretamente no Firestore.

  5. Backward-compatible — Podcasts existentes sem personas.socialmedia no Firestore continuam funcionando. O schema faz parse sem erro e a UI renderiza campos vazios para a nova persona.

  6. Testes atualizados — Testes do personas-settings-form.test.tsx verificam renderização e save da terceira persona.

Dev Notes

Arquitetura e Padrões

  • Schema Zod → Type inference: Todos os types são inferidos via z.infer<typeof Schema>. Ao adicionar socialmedia ao PersonasSchema, o tipo Personas atualiza automaticamente.
  • Ref pattern para stale closures: settings-page-client.tsx usa personasRef para evitar closures stales em saves rápidos. O handleSavePersona faz spread do ref atual com a nova persona — esse padrão funciona automaticamente para a terceira persona.
  • Auto-save debounce 1.5s: persona-editor.tsx usa useAutoSave hook. Não é necessário modificar o hook — funciona por instância de componente.
  • Padrão union type: Todo lugar que usa 'critic' | 'writer' deve ser estendido para 'critic' | 'writer' | 'socialmedia'. Locais exatos: PERSONA_LABELS Record type, PersonasSettingsFormProps.onSavePersona, PersonaEditorProps.personaKey, handleSavePersona parâmetro, mockOnSavePersona tipo no teste.
  • Fallback para optional persona: Como socialmedia é .optional(), acessar personas.socialmedia retorna Persona | undefined. Usar personas.socialmedia ?? DEFAULT_PERSONA ao passar initialValue para PersonaEditor. DEFAULT_PERSONA já é exportado de @/lib/schemas/podcast.

Backward Compatibility

A persona socialmedia é .optional() dentro de PersonasSchema (não no campo personas do PodcastSchema, que continua required). Podcasts existentes no Firestore não terão personas.socialmedia — o Zod parse retorna undefined para esse campo, e a UI usa DEFAULT_PERSONA como fallback (campos vazios editáveis). Nenhuma migração de dados é necessária.
