Story 14.8: Seção "Redes Sociais" no Menu Lateral + Sidebar de Vídeos

Status: done

Story

As a produtor, I want acessar a seção de Redes Sociais pelo menu lateral, so that eu possa ver e gerenciar posts sociais dos meus vídeos.

Prerequisites

BLOQUEANTES — Devem estar implementadas ANTES de iniciar esta story:

  • Story 14.3 — Feature toggle socialMedia no FeaturesSchema
  • Story 14.4 — Campo enabledSocialNetworks: string[] no PodcastSchema
  • Story 14.6 — API endpoints GET/PUT para social posts (backend ready)
  • Story 14.7 — POST endpoint de geração LLM (backend ready)

Acceptance Criteria

  1. Item "Redes Sociais" no sidebar — Quando features.socialMedia === true E enabledSocialNetworks.length > 0, exibe item "Redes Sociais" com ícone Share2 (Lucide) entre "Notícias" e "Usuários". Clicar navega para ?view=social. Destaque visual quando view=social está ativo (classe bg-accent).

  2. Ocultação condicional — Quando features.socialMedia === false OU enabledSocialNetworks.length === 0, o item "Redes Sociais" NÃO é exibido no sidebar. Se features é undefined (backward-compat), NÃO exibe (default false).

  3. View social no layout — Quando ?view=social está ativo, exibe layout com sidebar de vídeos à esquerda e área de trabalho à direita. Sidebar reutiliza VideoListPanel com os mesmos filtros de tipo e status.

  4. Sem botão sync — A sidebar de vídeos na seção Redes Sociais NÃO exibe o botão "Verificar novos vídeos". O VideoListPanel deve suportar omissão do botão quando onSync não é fornecido.

  5. Seleção de vídeo — Ao selecionar um vídeo na sidebar, a URL atualiza para ?view=social&selected={videoId}. A área de trabalho à direita carrega o contexto do vídeo selecionado.

  6. Estado vazio — Quando nenhum vídeo está selecionado, a área de trabalho exibe: "Selecione um vídeo para ver os posts sociais" (estado vazio centralizado).

  7. Redirecionamento de feature desabilitada — Se ?view=social está ativo mas features.socialMedia === false, redireciona para /videos (mesmo padrão de editorial/news).

  8. Acessível para todos os roles — O item "Redes Sociais" é visível para todos os usuários autenticados (não é adminOnly), desde que as condições de feature toggle sejam atendidas.

  9. Testes — Testes para sidebar (item visível/oculto por features, backward-compat), videos-layout (view social renderiza, redirecionamento), e social-layout (empty state, renderização com vídeo).

Dev Notes

Arquitetura e Padrões

  • Condição dupla para visibilidade: O item "Redes Sociais" no sidebar requer AMBAS as condições verdadeiras: (1) features.socialMedia === true e (2) enabledSocialNetworks.length > 0. Isso evita exibir um menu para uma seção vazia. Diferente de editorial/news que usam !== false (default true), socialMedia usa === true (default false).

  • PodcastFeatures interface estendida: A interface PodcastFeatures em sidebar.tsx é local (não exportada). Estender com socialMedia?: boolean. A prop enabledSocialNetworks?: string[] é separada (não faz parte de features no Firestore).

  • Fetch único no videos-layout.tsx: O useEffect já faz fetch de /api/podcast e extrai features. Basta também extrair enabledSocialNetworks da mesma response. Não precisa de fetch adicional. A response do endpoint /api/podcast já retorna o podcast completo incluindo enabledSocialNetworks.

  • View routing pattern: Seguir exatamente o padrão de editorial/news no videos-layout.tsx. Cada view é um if (currentView === 'xxx') que retorna layout completo com sidebar. O case social vai entre news e users na ordem do arquivo.

  • VideoListPanel sem sync: O VideoListPanel já aceita onSync como prop opcional (onSync?: () => void). Mas o botão é renderizado incondicionalmente. Basta envolver em {onSync && (...)} para que omitir a prop esconda o botão. Isso é seguro: os testes existentes passam onSync e não serão afetados.

  • SocialLayout como componente simples: Na Story 14.8, a área de trabalho é apenas um placeholder/empty-state. O layout completo de colunas (Story 14.9) e edição (14.10) serão adicionados posteriormente. Manter o componente simples agora.

  • URL state via searchParams: Seleção de vídeo usa ?view=social&selected={videoId} — consistente com enforcement rule #10 (selectedVideoId via URL). O SocialLayout usa useSearchParams para ler e useRouter().push() para navegar.

  • Sem LLMProcessingProvider: Diferente da view de Vídeos, a view social NÃO precisa do LLMProcessingProvider nesta story. O processamento LLM social será adicionado na Story 14.9 quando o auto-generate for implementado. Não antecipar.

  • Sem SyncOverlay e SyncResultModal: A view social não tem operação de sync. Não incluir esses componentes.

SocialLayout — esqueleto (novo componente):

'use client'

import { useSearchParams, useRouter, usePathname } from 'next/navigation'
import { useCallback } from 'react'
import { Share2 } from 'lucide-react'

import { VideoListPanel } from '@/components/videos/video-list-panel'
import { useVideos } from '@/hooks/use-videos'

export function SocialLayout() {
  const searchParams = useSearchParams()
  const router = useRouter()
  const pathname = usePathname()

  const selectedVideoId = searchParams.get('selected')

  const {
    videos, isLoading, error, page, totalPages, setPage,
    typeFilter, setTypeFilter, statusFilter, setStatusFilter,
  } = useVideos()

  const handleVideoSelect = useCallback((videoId: string) => {
    router.push(`${pathname}?view=social&selected=${videoId}`)
  }, [router, pathname])

  return (
    <div className="flex h-full">
      {/* Video sidebar */}
      <div className="w-[380px] shrink-0 border-r border-border">
        <VideoListPanel
          videos={videos}
          selectedVideoId={selectedVideoId}
          onVideoSelect={handleVideoSelect}
          isLoading={isLoading}
          error={error}
          page={page}
          totalPages={totalPages}
          onPageChange={setPage}
          typeFilter={typeFilter}
          onTypeFilterChange={setTypeFilter}
          statusFilter={statusFilter}
          onStatusFilterChange={setStatusFilter}
        />
      </div>

      {/* Work area */}
      <div className="flex-1 flex items-center justify-center">
        {selectedVideoId ? (
          <div className="text-muted-foreground">
            {/* Placeholder — Stories 14.9/14.10 implementam o conteúdo */}
            Posts sociais de {selectedVideoId}
          </div>
        ) : (
          <div className="flex flex-col items-center gap-3 text-muted-foreground">
            <Share2 className="h-12 w-12 opacity-30" />
            <p className="text-sm">Selecione um vídeo para ver os posts sociais</p>
          </div>
        )}
      </div>
    </div>
  )
}

Backward Compatibility

Esta story modifica componentes existentes (sidebar, videos-layout, video-list-panel) de forma aditiva. Nenhum comportamento existente é alterado:

  • PodcastFeatures ganha campo opcional socialMedia — undefined = não exibe (safe)
  • SidebarProps ganha campo opcional enabledSocialNetworks — undefined = não exibe (safe)
  • VideoListPanel — sync button envolvido em {onSync && (...)} — callers existentes passam onSync, então continuam vendo o botão
  • Novos testes são aditivos

Learnings das Stories Anteriores

  • Story 14.3: Default false para socialMedia — diferente de editorial/news (default true). Condição de visibilidade usa === true em vez de !== false
  • Story 14.4: enabledSocialNetworks é z.array(z.string()).optional() no schema — undefined ou [] significam "nenhuma rede habilitada"
  • Story 14.1: localStorage.clear() no beforeEach para evitar leaks entre testes (componentes com useAccordionState ou similar)
  • Story 14.6: context.params é Promise no Next.js 15 — sempre await context.params
  • Story 14.7: Testes com mocks de factories usam vi.fn() com wrappers — não chamar mocks diretamente
