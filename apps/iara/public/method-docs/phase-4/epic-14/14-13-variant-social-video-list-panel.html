Story 14.13: Variant Social no VideoListPanel

Status: done

Story

As a produtor, I want que o painel de vídeos na aba "Redes Sociais" tenha comportamento visual e interativo diferente da aba "Vídeos", so that eu consiga selecionar vídeos "enviados" sem modais desnecessários e com feedback visual adequado ao contexto de divulgação social.

Prerequisites

BLOQUEANTES — Devem estar implementadas ANTES de iniciar esta story:

  • Story 14.12 — Ajustes UX (filtros, layout, CTA multi-line)

Acceptance Criteria

  1. Prop variant no VideoListPanel — O componente VideoListPanel aceita uma prop variant?: 'editorial' | 'social' com default 'editorial'. Quando variant='editorial', todos os comportamentos atuais são preservados inalterados. Quando variant='social', as ACs 2-5 se aplicam.

  2. Feedback visual invertido para vídeos "sent" — Com variant='social':

    • Vídeos sent aparecem com opacidade normal (ativos) e ring de seleção azul quando selecionados
    • Vídeos com outros status (new, draft, processing, ready) aparecem com opacity-60 (sutis)
    • O prop sentAppearance?: 'dimmed' | 'highlighted' é passado do VideoListPanel para cada VideoListItem, derivado do variant

  3. Sem reopen dialog para vídeos "sent" — Com variant='social':

    • Clicar num vídeo sent chama onVideoSelect(videoId) diretamente (não abre ReopenVideoDialog)
    • Navegar por keyboard (ArrowDown/ArrowUp) para um vídeo sent também chama onVideoSelect diretamente
    • Enter/Space num vídeo sent também seleciona diretamente
    • O ReopenVideoDialog NÃO é renderizado quando variant='social'

  4. Toggle "Só novos" oculto — Com variant='social', o switch "Só novos" e seu label não são renderizados. O statusFilter é controlado externamente pelo SocialLayout (já passa 'all').

  5. Testes atualizados — Novos testes verificam ambos os variants em:

    • VideoListPanel: toggle oculto, reopen dialog ausente, sentAppearance derivado
    • VideoListItem: opacidade invertida, seleção direta de sent
    • SocialLayout: passa variant="social" ao VideoListPanel

Tasks / Subtasks

  • Task 1: Prop variant no VideoListPanel (AC: #1, #3, #4)

    • 1.1 Adicionar variant?: 'editorial' | 'social' ao VideoListPanelProps com default 'editorial'
    • 1.2 Derivar sentAppearance do variant: variant === 'social' ? 'highlighted' : 'dimmed'
    • 1.3 Passar sentAppearance ao VideoListItem no map de renderização
    • 1.4 Condicionar renderização do switch "Só novos": variant !== 'social'
    • 1.5 Condicionar renderização do ReopenVideoDialog: variant !== 'social'
    • 1.6 Ajustar keyboard nav (navigateToVideo): quando variant === 'social', vídeos sent chamam onVideoSelect direto (sem reopen)
    • 1.7 Ajustar passagem de onReopenRequest ao VideoListItem: quando variant === 'social', não passar callback

  • Task 2: Prop sentAppearance no VideoListItem (AC: #2, #3)

    • 2.1 Adicionar sentAppearance?: 'dimmed' | 'highlighted' ao VideoListItemProps com default 'dimmed'
    • 2.2 Quando sentAppearance === 'highlighted':
      • Vídeos sent NÃO recebem opacity-60 — ficam visuais normais
      • Vídeos sent selecionados recebem ring-2 ring-blue-400 bg-accent (selection ring)
      • Vídeos NÃO-sent recebem opacity-60 (invertido)
    • 2.3 Quando sentAppearance === 'dimmed' (default): comportamento atual inalterado
    • 2.4 Quando sentAppearance === 'highlighted' e onReopenRequest não é passado: click/Enter/Space num vídeo sent chama onSelect diretamente

  • Task 3: SocialLayout passa variant="social" (AC: #1)

Dev Notes

Arquitetura e Padrões

  • Prop variant com derivação interna: O VideoListPanel recebe variant e deriva internamente sentAppearance, sem expor essa lógica ao chamador. O VideoListItem recebe sentAppearance sem saber sobre variants — responsabilidade segregada.

  • Default 'editorial': CRÍTICO manter default 'editorial' para não quebrar nenhum uso existente. VideoListPanel é usado em:

    • src/app/videos/videos-layout.tsx (aba Vídeos) — sem variant = editorial
    • src/components/social/social-layout.tsx (aba Redes Sociais) — variant="social"

  • Reopen dialog condicional: Não apenas ocultar o dialog — NÃO renderizar o componente ReopenVideoDialog quando variant === 'social'. Isso evita estado residual.

  • Keyboard nav: A função navigateToVideo em video-list-panel.tsx:126-132 precisa ser condicionada pelo variant. Quando social, chamar onVideoSelect direto para vídeos sent.
