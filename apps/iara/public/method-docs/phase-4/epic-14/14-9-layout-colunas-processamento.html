Story 14.9: Layout de Colunas com Exibição e Processamento On-Demand

Status: done

Story

As a produtor, I want ver os posts sociais de um vídeo organizados em colunas por rede social, so that eu compare e revise os posts de cada plataforma lado a lado.

Prerequisites

BLOQUEANTES — Devem estar implementadas ANTES de iniciar esta story:

  • Story 14.6 — API endpoints GET social-posts + PUT (backend ready)
  • Story 14.7 — POST endpoint de geração LLM + fila sequencial (backend ready)
  • Story 14.8 — SocialLayout + sidebar de vídeos + placeholder de área de trabalho

Acceptance Criteria

  1. Colunas por rede habilitada — Ao selecionar um vídeo, a área de trabalho exibe uma coluna de 640px de largura fixa para cada rede em enabledSocialNetworks. Colunas dispostas horizontalmente da esquerda para direita. Altura 100% da área disponível. Quando as colunas excedem a largura visível, barra de rolagem horizontal permite acessar as demais.

  2. Exibição de post existente — Quando a coluna tem post já existente no Firestore (retornado pelo GET), exibe imediatamente: label da rede ({icon} {name}) no topo de forma discreta, CTA como subtítulo da coluna, Body ocupando o espaço principal, Hashtags ao final.

  3. Auto-geração de post ausente — Quando a coluna não tem post no Firestore, exibe spinner centralizado verticalmente com mensagem "Aguarde, gerando seu melhor post para o {networkName}..." e inicia processamento automaticamente via POST /api/videos/{videoId}/social-posts/{networkId}/generate.

  4. Processamento sequencial — Quando múltiplas redes não têm posts, o processamento acontece sequencialmente (não em paralelo). Cada rede mostra spinner independente. Ao completar uma rede, exibe o resultado e inicia a próxima. Sequência segue a ordem das redes em enabledSocialNetworks.

  5. Pré-requisitos do vídeo — Quando o vídeo não tem título, tema ou descrição otimizados, todas as colunas exibem mensagem: "Este vídeo precisa ter título, tema e descrição processados antes de gerar posts para redes sociais." Nenhum processamento é iniciado.

  6. Erro com retry — Quando o LLM retorna erro para uma rede, a coluna exibe mensagem de erro com botão "Tentar novamente". As demais redes continuam processando normalmente. Retry re-envia o POST para aquela rede específica.

  7. Cancelamento ao trocar vídeo — Quando o produtor seleciona outro vídeo durante processamento, os requests em andamento são cancelados via AbortController. O novo vídeo inicia seu próprio ciclo de fetch + auto-geração.

  8. Loading state no fetch inicial — Enquanto o GET /api/videos/{videoId}/social-posts está em andamento, todas as colunas exibem skeleton/spinner até que os posts existentes sejam carregados.

  9. Testes — Testes para useSocialPosts hook (fetch, auto-generation, abort, error), SocialColumnsLayout (rendering, prerequisite check, column display), e SocialPostColumn (post display, spinner, error+retry).

Dev Notes

Arquitetura e Padrões

  • Hook useSocialPosts como coordenador: Este hook é o coração da funcionalidade. Ele gerencia: (1) fetch de posts existentes, (2) identificação de redes faltantes, (3) auto-geração sequencial, (4) cancelamento via AbortController, (5) errors por rede. Não misturar essa lógica nos componentes.

  • Processamento sequencial no frontend: A fila LLM do backend (llmQueue) garante serialização de calls LLM no servidor. Mas o frontend também precisa serializar: processar rede A, esperar resposta, só então processar rede B. Isso é feito via loop for...of com await no hook, não via múltiplos fetch simultâneos.

  • AbortController pattern: Seguir exatamente o padrão de use-videos.ts (linhas 57-128). Ref para o controller, criar novo a cada ciclo de fetch, abort no cleanup do useEffect e ao trocar videoId. Ignorar AbortError no catch.

  • EnabledNetworkInfo type: Tipo auxiliar com { id: string; name: string; icon: string } para evitar múltiplos fetches. O SocialLayout faz fetch único de /api/social-networks, filtra por enabledSocialNetworks (IDs), e passa o array enriquecido para SocialColumnsLayout.

  • Pré-requisitos inline: A verificação de pré-requisitos (título, tema, descrição) é feita no frontend, não precisa de API call. O VideoSummary já contém title, theme, description. Verificar: video.title && video.theme && video.description.

  • ProcessingSpinner reutilizável: Usar o componente existente ProcessingSpinner de src/components/wizard/processing-spinner.tsx para o estado de geração. Customizar apenas a className e o text.

  • Column scroll: Container usa flex overflow-x-auto (horizontal scroll). Cada coluna usa overflow-y-auto (vertical scroll do conteúdo do post). A altura da coluna é h-full (100% do container parent).

  • Sem estado global: Posts são locais ao hook. Não usar Zustand ou Context. O hook é instanciado dentro de SocialColumnsLayout, que só existe quando um vídeo está selecionado. Trocar de vídeo = desmontar e remontar = novo hook = novo fetch.

useSocialPosts hook — esqueleto:

'use client'

import { useCallback, useEffect, useRef, useState } from 'react'

import { log } from '@/lib/logger'
import type { SocialPost } from '@/types/social'

export interface EnabledNetworkInfo {
  id: string
  name: string
  icon: string
}

interface UseSocialPostsResult {
  posts: SocialPost[]
  isLoading: boolean
  isGenerating: boolean
  generatingNetworkId: string | null
  errors: Map<string, string>
  retryNetwork: (networkId: string) => void
}

export function useSocialPosts(
  videoId: string | null,
  enabledNetworks: EnabledNetworkInfo[],
  hasPrerequisites: boolean
): UseSocialPostsResult {
  const [posts, setPosts] = useState<SocialPost[]>([])
  const [isLoading, setIsLoading] = useState(false)
  const [isGenerating, setIsGenerating] = useState(false)
  const [generatingNetworkId, setGeneratingNetworkId] = useState<string | null>(null)
  const [errors, setErrors] = useState<Map<string, string>>(new Map())
  const abortControllerRef = useRef<AbortController | null>(null)

  // Fetch existing posts
  const fetchPosts = useCallback(async (signal: AbortSignal): Promise<SocialPost[]> => {
    if (!videoId) return []
    const response = await fetch(`/api/videos/${videoId}/social-posts`, { signal })
    if (!response.ok) throw new Error('Falha ao carregar posts')
    const { data } = await response.json()
    return data
  }, [videoId])

  // Generate a single post
  const generatePost = useCallback(async (
    networkId: string,
    signal: AbortSignal
  ): Promise<SocialPost> => {
    const response = await fetch(
      `/api/videos/${videoId}/social-posts/${networkId}/generate`,
      { method: 'POST', signal }
    )
    if (!response.ok) {
      const err = await response.json().catch(() => ({}))
      throw new Error(err.error?.message || 'Erro ao gerar post')
    }
    const { data } = await response.json()
    return data
  }, [videoId])

  // Main effect: fetch + auto-generate
  useEffect(() => {
    if (!videoId) {
      setPosts([])
      return
    }

    abortControllerRef.current?.abort()
    const controller = new AbortController()
    abortControllerRef.current = controller

    const run = async () => {
      setIsLoading(true)
      setErrors(new Map())
      setIsGenerating(false)
      setGeneratingNetworkId(null)

      try {
        const existingPosts = await fetchPosts(controller.signal)
        if (controller.signal.aborted) return
        setPosts(existingPosts)
        setIsLoading(false)

        if (!hasPrerequisites) return

        // Identify missing networks
        const existingIds = new Set(existingPosts.map(p => p.networkId))
        const missingNetworks = enabledNetworks.filter(n => !existingIds.has(n.id))

        if (missingNetworks.length === 0) return

        // Sequential generation
        setIsGenerating(true)
        for (const network of missingNetworks) {
          if (controller.signal.aborted) return
          setGeneratingNetworkId(network.id)
          try {
            const newPost = await generatePost(network.id, controller.signal)
            if (controller.signal.aborted) return
            setPosts(prev => [...prev, newPost])
          } catch (err) {
            if (err instanceof Error && err.name === 'AbortError') return
            setErrors(prev => new Map(prev).set(network.id, err instanceof Error ? err.message : 'Erro'))
          }
        }
        setIsGenerating(false)
        setGeneratingNetworkId(null)
      } catch (err) {
        if (err instanceof Error && err.name === 'AbortError') return
        if (!controller.signal.aborted) {
          log('ERROR', 'Failed to load social posts', { videoId, error: err })
          setIsLoading(false)
        }
      }
    }

    run()
    return () => { controller.abort() }
  }, [videoId, enabledNetworks, hasPrerequisites, fetchPosts, generatePost])

  // Retry a specific network
  const retryNetwork = useCallback(async (networkId: string) => {
    if (!videoId) return
    const controller = new AbortController()
    // Clear error for this network
    setErrors(prev => {
      const next = new Map(prev)
      next.delete(networkId)
      return next
    })
    setGeneratingNetworkId(networkId)
    setIsGenerating(true)
    try {
      const newPost = await generatePost(networkId, controller.signal)
      setPosts(prev => [...prev, newPost])
    } catch (err) {
      if (err instanceof Error && err.name !== 'AbortError') {
        setErrors(prev => new Map(prev).set(networkId, err instanceof Error ? err.message : 'Erro'))
      }
    } finally {
      setIsGenerating(false)
      setGeneratingNetworkId(null)
    }
  }, [videoId, generatePost])

  return { posts, isLoading, isGenerating, generatingNetworkId, errors, retryNetwork }
}

import { useMemo } from 'react'
import { AlertCircle } from 'lucide-react'

import { SocialPostColumn } from './social-post-column'
import { useSocialPosts } from '@/hooks/use-social-posts'
import type { EnabledNetworkInfo } from '@/hooks/use-social-posts'
import type { VideoSummary } from '@/types/video'

interface SocialColumnsLayoutProps {
  video: VideoSummary
  enabledNetworks: EnabledNetworkInfo[]
}

export function SocialColumnsLayout({ video, enabledNetworks }: SocialColumnsLayoutProps) {
  const hasPrerequisites = Boolean(video.title && video.theme && video.description)
  const { posts, isLoading, generatingNetworkId, errors, retryNetwork } = useSocialPosts(
    video.id,
    enabledNetworks,
    hasPrerequisites
  )

  if (!hasPrerequisites) {
    return (
      <div className="flex items-center justify-center h-full p-8">
        <div className="flex flex-col items-center gap-3 text-muted-foreground max-w-md text-center">
          <AlertCircle className="h-10 w-10 opacity-40" />
          <p className="text-sm">
            Este vídeo precisa ter título, tema e descrição processados antes de gerar posts para redes sociais.
          </p>
        </div>
      </div>
    )
  }

  const postsMap = useMemo(() => {
    const map = new Map<string, typeof posts[0]>()
    for (const post of posts) {
      map.set(post.networkId, post)
    }
    return map
  }, [posts])

  return (
    <div className="flex h-full overflow-x-auto">
      {enabledNetworks.map(network => (
        <SocialPostColumn
          key={network.id}
          networkId={network.id}
          networkName={network.name}
          networkIcon={network.icon}
          post={postsMap.get(network.id) ?? null}
          isGenerating={generatingNetworkId === network.id}
          isLoading={isLoading}
          error={errors.get(network.id) ?? null}
          onRetry={() => retryNetwork(network.id)}
        />
      ))}
    </div>
  )
}

Stabilidade de enabledNetworks referência

O enabledNetworks array deve ter referência estável para evitar re-renders infinitos no useEffect de useSocialPosts. Usar useMemo no SocialLayout para filtrar e mapear os networks:

const enabledNetworks = useMemo(() => {
  if (!allNetworks || !enabledIds) return []
  return enabledIds
    .map(id => allNetworks.find(n => n.id === id))
    .filter(Boolean) as EnabledNetworkInfo[]
}, [allNetworks, enabledIds])

Retry isolado vs re-fetch global

O retryNetwork no hook gera apenas aquela rede específica, sem re-fetch global. Isso é mais eficiente e não perturba posts já carregados. O AbortController do retry é local (não o ref principal), então trocar de vídeo cancela tanto o ciclo principal quanto retries eventuais (via unmount do componente).
