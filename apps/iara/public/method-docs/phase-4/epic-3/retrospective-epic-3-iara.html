Retrospective - Epic 3: Deteccao de Videos

Project: IAra Epic: 3 - Deteccao de Videos Date: 2026-01-27 Facilitator: Claude Opus 4.5 (SM) Participants: Wellington (PO/User)

Executive Summary

Epic 3 foi completado (6/6 stories), mas com atraso significativo devido a problemas recorrentes: ignorar schema legado existente, problemas de parsing de datas, e multiplos bugs de layout. Uma story intermediaria (3-x) foi necessaria para corrigir incompatibilidades de schema. O code review adversarial encontrou 10 issues, mas varios problemas so foram descobertos em testes manuais pelo usuario.

Tema critico: O agente continua fazendo suposicoes sobre dados existentes em vez de investigar primeiro.

What Went Well

1. Story 3-x: Identificacao e Correcao do Schema Legado

  • Problema de compatibilidade foi eventualmente identificado
  • Story intermediaria criada para resolver
  • Videos legados agora funcionam com o novo sistema

2. Code Review Adversarial

  • 10 issues encontrados e corrigidos
  • Race conditions prevenidas com AbortController
  • Protecao NaN em query params
  • Parsing de datas unificado com helper function

3. Funcionalidades Adicionais Implementadas

  • Paginacao com controles de navegacao
  • Filtros por tipo de video (Tabs)
  • Query Firestore otimizada por videoType
  • Scrollbar customizada no design system

4. Integracao YouTube API

  • Sync de videos funcionando
  • Classificacao automatica por duracao
  • Thumbnails carregando corretamente (apos fix de dominio)

What Didn't Go Well

1. CRITICO: Ignorou Schema Legado Existente

Problema:

  • Firestore ja tinha ~2000 videos do portal-web legado
  • Agente implementou schema novo sem verificar dados existentes
  • Videos existentes tinham publishedAt como ISO 8601 string
  • Novo codigo assumiu Firestore Timestamp

Impacto:

  • Ordenacao de videos completamente quebrada
  • Story 3-x teve que ser criada para corrigir
  • Tempo perdido em debugging

Root Cause:

  • Agente nao investigou dados existentes antes de implementar
  • Assumiu que poderia definir schema livremente

2. CRITICO: Multiplos Bugs de Layout

Problemas encontrados em teste manual:

  1. Botoes desaparecendo:

    • Botao "Verificar novos" sumia ao carregar videos
    • Setas de paginacao desapareciam
    • Causa: overflow nao controlado nos paineis

  2. Scrollbar fora do design:

    • Scrollbar branca em tema dark
    • ScrollArea do shadcn quebrou layout completamente
    • Solucao: CSS nativo com custom-scrollbar class

  3. Largura dos paineis:

    • Coluna de videos muito larga, depois muito pequena
    • Multiplos ajustes necessarios

Impacto:

  • Usuario frustrado: "Conserta uma coisa, quebra outra"
  • Multiplas iteracoes para resolver problemas visuais

3. Ordenacao de Videos Incorreta

Problema:

  • Videos nao ordenados por data de publicacao
  • Parsing de data falhava silenciosamente

Causa:

  • Dados legados: ISO 8601 string ("2024-01-15T10:30:00Z")
  • Dados novos: Firestore Timestamp ({ toDate: () => Date })
  • Codigo so tratava um formato

Correcao:

  • Helper parsePublishedAt() que detecta formato em runtime
  • Validacao de Invalid Date

4. Query Firestore Quebrou ao Otimizar

Problema:

  • Tentativa de otimizar com .where('videoType', '==', type)
  • Tipo TypeScript errado: FirebaseFirestore.Query nao importado
  • App retornando 500 para filtros

Causa:

  • Falta de teste apos mudanca
  • Tipo incorreto passou pelo TypeScript porque era any

5. Referencia a Operacoes DELETE Inexistentes

Problema:

  • Codigo e interfaces incluiam includeDeleted, softDelete, etc.
  • Plataforma NAO tem operacoes de DELETE

Causa:

  • Agente nao verificou contexto do projeto
  • Assumiu que DELETE seria necessario

Action Items para Epic 4

OBRIGATORIO: Investigar Dados Existentes

Antes de implementar QUALQUER schema ou query:

- [ ] Verificar se collection/subcollection ja existe
- [ ] Examinar formato dos dados existentes
- [ ] Documentar variacoes encontradas
- [ ] Perguntar se houver inconsistencias

OBRIGATORIO: Testar Layout Apos Mudancas

- [ ] Testar com dados reais (nao apenas mock)
- [ ] Verificar overflow em todos os containers
- [ ] Testar em diferentes tamanhos de tela
- [ ] Confirmar que elementos nao desaparecem

OBRIGATORIO: Validar Tipos TypeScript

- [ ] Nao usar tipos que nao estao importados
- [ ] Verificar que `any` nao esta mascarando erros
- [ ] Rodar `tsc --noEmit` apos mudancas significativas

NAO ADICIONAR: Features Inexistentes

- [ ] Verificar se feature existe antes de implementar suporte
- [ ] NAO adicionar soft delete, flags de exclusao, etc. sem confirmacao
- [ ] Perguntar: "O sistema tem operacao X?"

Lessons Learned

LL1: Dados Legados Existem - Sempre Verificar

Antes de implementar schemas ou queries, VERIFICAR se dados ja existem na collection. Formatos podem variar. Nunca assumir que pode definir schema livremente.

LL2: Layout Precisa de Teste Visual

Problemas de layout (overflow, scrollbar, tamanhos) so aparecem em teste visual com dados reais. Testes unitarios nao capturam esses problemas.

LL3: Nao Otimizar Prematuramente

Adicionar filtros Firestore-level causou mais problemas que resolveu. A query original funcionava. Otimizacao deve vir com testes adequados.

LL4: Nao Adicionar Codigo para Features Inexistentes

Codigo para soft delete, includeDeleted, etc. foi adicionado sem necessidade. Isso adiciona complexidade e confusao. Implementar apenas o que existe.

LL5: Frustacao do Usuario e Sinal de Alerta

"Conserta uma coisa, quebra outra" indica problema sistemico. Parar e revisar abordagem, nao continuar no mesmo ritmo.
