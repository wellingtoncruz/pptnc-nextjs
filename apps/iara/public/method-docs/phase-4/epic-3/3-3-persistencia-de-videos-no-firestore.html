Story 3.3: Persistência de Vídeos no Firestore

Status: done

Story

As a sistema, I want persistir vídeos detectados no Firestore, so that o histórico e status sejam mantidos entre sessões.

Acceptance Criteria

  1. Given vídeos retornados da YouTube API When eu processo a sincronização Then novos vídeos são criados em podcasts/{podcastId}/videos/{videoId} And cada vídeo é criado com status 'new' (via state machine) And videoType é classificado automaticamente pela duração usando classifyVideoType()

  2. Given um vídeo que já existe no Firestore When a sincronização é executada Then os dados do YouTube são atualizados (título, thumbnail, description) And o status NÃO é alterado (preservar progresso) And updatedAt é atualizado com serverTimestamp()

  3. Given vídeo no YouTube foi deletado When a sincronização é executada Then o vídeo no Firestore é marcado com flag deleted: true And NÃO é removido do banco (soft delete)

  4. Given operação de sincronização When eu chamo POST /api/sync Then retorna { data: { added: number, updated: number, deleted: number } } And usa transição transition('new', 'classify') para novos vídeos

  5. And existe src/lib/firebase/videos.ts com funções CRUD And todas as queries incluem podcastId (enforcement rule #8) And usa updateDoc com fields explícitos (enforcement rule #4) And valida dados com Zod ANTES de persistir (enforcement rule #2)

Dev Notes

Architecture Patterns

  • Firestore subcollection: Videos stored at podcasts/{podcastId}/videos/{videoId}
  • Document ID: Use YouTube videoId as Firestore document ID (natural key)
  • Soft delete: Never physically delete - set deleted: true flag
  • State machine: All new videos start at 'new', transition via transition('new', 'classify')
  • Batch writes: Firestore allows max 500 operations per batch

Enforcement Rules (CRITICAL)

  1. Rule #2: Validate with Zod BEFORE persisting - use VideoCreateSchema.parse(), VideoUpdateSchema.parse()
  2. Rule #4: Use updateDoc with explicit fields, NOT setDoc (preserves existing data)
  3. Rule #3: Route handlers must include export const runtime = 'nodejs'
  4. Rule #8: ALL Firestore queries MUST include podcastId - no orphan documents

Timestamp Handling (Client vs Admin SDK)

// Client SDK (videos.ts):
import { serverTimestamp } from 'firebase/firestore'
await updateDoc(ref, { updatedAt: serverTimestamp() })

// Admin SDK (videos-admin.ts):
import { FieldValue } from 'firebase-admin/firestore'
await ref.update({ updatedAt: FieldValue.serverTimestamp() })

Video Classification

Use classifyVideoType() from @/lib/video-utils:

  • episode: duration >= config.episode.minDuration (default 1200s = 20min)
  • cut: duration >= config.cut.minDuration (default 180s = 3min)
  • reel: duration < 180s

Sync Algorithm

async function syncVideos(podcastId: string, accessToken: string): Promise<SyncResult> {
  // 1. Fetch ALL videos from YouTube (handle pagination)
  const youtubeVideos = await fetchAllYouTubeVideos(accessToken)

  // 2. Fetch existing videos from Firestore
  const firestoreVideos = await getVideosByPodcastAdmin(podcastId)

  // 3. Build maps for comparison
  const youtubeIds = new Set(youtubeVideos.map(v => v.id))
  const firestoreMap = new Map(firestoreVideos.map(v => [v.id, v]))

  // 4. Categorize
  const toCreate = youtubeVideos.filter(v => !firestoreMap.has(v.id))
  const toUpdate = youtubeVideos.filter(v => firestoreMap.has(v.id) && !firestoreMap.get(v.id)!.deleted)
  const toDelete = firestoreVideos.filter(v => !youtubeIds.has(v.id) && !v.deleted)

  // 5. Execute in batches
  await batchWriteVideos({ creates: toCreate, updates: toUpdate, deletes: toDelete })

  return { added: toCreate.length, updated: toUpdate.length, deleted: toDelete.length }
}
