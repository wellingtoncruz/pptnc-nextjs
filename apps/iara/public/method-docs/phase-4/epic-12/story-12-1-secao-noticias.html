Story 12.1: Seção Notícias com Listagem Paginada e Painel de Detalhe

Status: done

Story

As a produtor do podcast, I want uma seção de notícias curadas no IAra com visualização master-detail, so that eu possa acompanhar rapidamente as notícias relevantes ao podcast sem sair da plataforma.

Acceptance Criteria

  1. AC1 - Navegação: Given o produtor está autenticado, When ele visualiza o menu lateral, Then existe um item "Notícias" posicionado entre "Editorial" e "Usuários", And ao clicar navega para a view de notícias (?view=news).

  2. AC2 - Layout Master-Detail: Given o produtor abre a seção Notícias, When a página carrega, Then o layout é dividido em dois painéis de 50% cada (esquerdo: listagem, direito: detalhe), And o painel direito exibe um estado vazio com mensagem "Selecione uma notícia para ver os detalhes".

  3. AC3 - Listagem em Cards: Given o produtor está na seção Notícias, When as notícias são carregadas, Then são exibidas em grid de 2 colunas (2 cards por linha), And cada card exibe: título, descrição (truncada ~2 linhas), nome da fonte e data da notícia, And a listagem é ordenada por importedAt descendente (mais recente primeiro).

  4. AC4 - Paginação Cursor-Based: Given existem mais de 16 notícias, When o produtor visualiza a listagem, Then são exibidas no máximo 16 notícias por página, And existe navegação "Próxima"/"Anterior" no rodapé do painel esquerdo, And a paginação utiliza cursor-based (Firestore startAfter com importedAt) para performance, And NÃO carrega todos os documentos em memória.

  5. AC5 - Seleção e Detalhe: Given o produtor visualiza a listagem de notícias, When ele clica em um card, Then o card selecionado recebe destaque visual (borda/fundo diferenciado), And o painel direito exibe: título (heading), data + fonte com link externo para URL original, resumo completo e comentários.

  6. AC6 - Estados de Loading e Erro: Given o produtor abre a seção Notícias, When os dados estão carregando, Then são exibidos skeletons no painel esquerdo, And quando ocorre erro na API é exibida mensagem de erro amigável em português.

  7. AC7 - API de Listagem: Given uma requisição GET /api/news, When autenticada com parâmetros opcionais cursor e limit, Then retorna lista de notícias da collection /podcasts/{podcastId}/news ordenadas por importedAt DESC, And respeita o limit (default 16, max 50), And quando cursor é fornecido usa startAfter para paginação, And retorna nextCursor (valor de importedAt do último item) quando há mais páginas.

  8. AC8 - Scroll Independente: Given o produtor está na seção Notícias com notícia selecionada, When ele rola o painel esquerdo (listagem), Then o painel direito (detalhe) mantém scroll independente, And vice-versa.

Dev Notes

Padrão de Paginação (NOVO na codebase)

A paginação cursor-based com Firestore é um padrão novo. O editorial atual faz paginação in-memory. Para News, usamos:

// Primeira página
query.orderBy('importedAt', 'desc').limit(16)

// Próxima página
query.orderBy('importedAt', 'desc').startAfter(cursorTimestamp).limit(16)

O cursor é serializado como ISO string na API response e reconvertido para Firestore Timestamp na query.

Navegação "Anterior"

Para paginação "Anterior", manter um stack de cursors (prevCursors). Ao avançar, push do cursor atual. Ao voltar, pop do stack. Primeira página: cursor undefined.

Referências de Padrão

  • Sidebar: src/components/layout/sidebar.tsx — seguir padrão de navItems
  • Layout: src/app/videos/videos-layout.tsx — seguir padrão do EditorialPanel

  • Card: src/components/editorial/episode-card.tsx — shadcn Card usage
  • Admin: src/lib/firebase/videos-admin.ts — Firestore admin pattern
  • Schema: src/lib/schemas/video.ts — Zod schema pattern
