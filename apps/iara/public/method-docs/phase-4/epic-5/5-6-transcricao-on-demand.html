Story 5.6: Transcrição On-Demand

Status: done

Story

As a produtor, I want que a transcrição seja baixada apenas quando eu selecionar um vídeo para processar, So that o sync seja rápido e não esgote a quota da YouTube API.

Contexto

O sync atual baixa transcrições via YouTube Captions API durante a sincronização, consumindo 200 units por transcrição. Com limite de 10.000 units/dia, isso permite apenas 50 transcrições diárias. Se o produtor fizer múltiplos syncs ou tiver muitos vídeos novos, a quota esgota rapidamente.

Solução: Lazy loading de transcrições - baixar apenas quando o produtor selecionar um vídeo para processar no Wizard.

Acceptance Criteria

  1. AC1: Sync sem transcrição

    • Given o processo de sync executado
    • When novos vídeos são detectados
    • Then apenas metadados são salvos (sem transcrição)
    • And o sync completa rapidamente
    • And campos transcriptionSRT e transcriptionTXT ficam vazios

  2. AC2: Loader de transcrição no Wizard

    • Given um vídeo selecionado para processamento
    • When transcriptionSRT ou transcriptionTXT estão vazios
    • Then exibe componente TranscriptionLoader ANTES do Wizard
    • And mostra spinner com "Estamos transcrevendo o seu vídeo..."

  3. AC3: Download bem-sucedido

    • Given o TranscriptionLoader ativo
    • When a transcrição é baixada com sucesso
    • Then SRT e TXT são salvos no Firestore
    • And o Wizard inicia automaticamente
    • And transcrição fica disponível para todas as fases

  4. AC4: Transcrição indisponível (processando)

    • Given o TranscriptionLoader ativo
    • When YouTube retorna que transcrição não está disponível
    • Then exibe mensagem "Esse vídeo ainda está em processamento pelo YouTube, tente novamente em alguns minutos"
    • And exibe botão "Voltar"
    • And botão redireciona para Home (/videos)

  5. AC5: Erro de quota

    • Given o TranscriptionLoader ativo
    • When YouTube retorna erro 429 (quota exceeded)
    • Then exibe mensagem "Limite de requisições atingido, tente novamente mais tarde"
    • And exibe botão "Voltar"

  6. AC6: Outros erros

    • Given o TranscriptionLoader ativo
    • When ocorre erro de rede ou outro erro
    • Then exibe mensagem genérica de erro
    • And exibe botão "Tentar novamente"
    • And exibe botão "Voltar"

Dev Notes

Arquitetura Atual vs Proposta

ANTES (Eager Loading):
Sync → Busca vídeos → Baixa transcrições → Salva tudo
Problema: Consome quota mesmo para vídeos nunca processados

DEPOIS (Lazy Loading):
Sync → Busca vídeos → Salva metadados (SEM transcrição)
Seleção → Check transcrição → Se vazio, TranscriptionLoader → Wizard
Benefício: Só gasta quota quando REALMENTE precisa

Fluxo de Seleção de Vídeo

User seleciona vídeo na lista
         ↓
    video.transcriptionSRT existe?
         ↓
    ┌────┴────┐
   SIM       NÃO
    ↓         ↓
 Wizard   TranscriptionLoader
              ↓
         POST /api/videos/[videoId]/transcription
              ↓
         YouTube Captions API
              ↓
         ┌────┴────┐
      SUCCESS    ERROR
         ↓          ↓
      Salva     Mensagem de erro
      Firestore + Botão Voltar
         ↓
      Wizard

Modificação no Wizard Orchestrator

// wizard-orchestrator.tsx

export function WizardOrchestrator({ video, ... }: Props) {
  const router = useRouter()
  const { refresh } = useVideos()

  // Check se precisa baixar transcrição
  if (!video.transcriptionSRT || !video.transcriptionTXT) {
    return (
      <TranscriptionLoader
        video={video}
        onSuccess={() => refresh()}  // Recarrega video com transcrição
        onCancel={() => router.push('/videos')}
      />
    )
  }

  // ... resto do Wizard
}
