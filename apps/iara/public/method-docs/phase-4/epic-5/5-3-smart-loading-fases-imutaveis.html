Story 5.3: Smart Loading de Fases Imutaveis

Status: done

Story

As a produtor, I want que o wizard reutilize dados ja processados e me direcione para a fase correta, so that eu nao perca tempo reprocessando fases ja completas e tenha uma experiencia fluida.

Acceptance Criteria

  1. AC1: Skip LLM para Fases Imutaveis com Dados

    • Given uma fase imutavel (1, 2, 3, 4) sendo carregada
    • When o campo de persistencia ja esta preenchido no video:
      • Fase 1: video.critique existe
      • Fase 2: video.editingIssues existe
      • Fase 3: video.riskAndCompliance existe
      • Fase 4: video.chapters existe
    • Then NAO dispara chamada LLM
    • And carrega dados do Firestore diretamente na Console Area
    • And exibe alert de sucesso com dados recuperados
    • NOTE: Esta logica JA EXISTE no orchestrator atual para fases 1-4

  2. AC2: Validacao de Criterios ao Abrir Video

    • Given um video sendo aberto no wizard
    • When o wizard inicializa
    • Then valida criterios de avanco de todas as fases (1-8)
    • And determina quais fases estao completas baseado nos dados do Firestore

  3. AC3: Navegacao para Fase Pendente

    • Given validacao de fases concluida
    • When existem fases incompletas
    • Then produtor e direcionado para a primeira fase ainda nao completada
    • And fases anteriores completas ficam navegaveis mas nao reprocessam

  4. AC4: Excecao Fases 2 e 3 - Confirmacao de Revisao

    • Given fase 2 (Edicao) ou fase 3 (Compliance)
    • When dados existem no Firestore (editingIssues ou riskAndCompliance)
    • Then fase NAO e marcada como completa automaticamente
    • And fase fica marcada como "pendente de revisao"
    • And se dados existem, NAO chama LLM novamente
    • And exibe dados existentes + Alert Box para confirmacao
    • And somente apos produtor confirmar via Alert, fase e marcada completa

  5. AC5: Persistencia do Estado de Revisao

    • Given produtor confirma revisao da fase 2 ou 3
    • When clica em "Sim, revisei" no Alert
    • Then video.reviewedPhases e atualizado com o numero da fase
    • And campo persiste no Firestore
    • And proxima vez que abrir, fase ja esta marcada como completa

Phase Validation Module

// src/lib/wizard/phase-validation.ts

import type { Video } from '@/types/video'
import type { WizardPhase } from './types'

export interface PhaseValidation {
  phase: WizardPhase
  /** Fase tem todos os criterios satisfeitos (incluindo revisao se aplicavel) */
  isComplete: boolean
  /** Dados da fase existem no Firestore */
  hasData: boolean
  /** Fase 2 ou 3 - requer confirmacao de revisao */
  requiresReview: boolean
  /** Produtor ja confirmou revisao (para fases 2 e 3) */
  isReviewed: boolean
}

/**
 * Mapeamento de fase -> campo de dados no Video
 */
const DATA_FIELDS: Record<WizardPhase, keyof Video | null> = {
  1: 'critique',
  2: 'editingIssues',
  3: 'riskAndCompliance',
  4: 'chapters',
  5: 'title',        // Fase 5-7: reprocessaveis, nao bloqueiam
  6: 'description',
  7: 'tags',
  8: null,           // Fase 8: check status === 'sent'
}

/**
 * Valida completude de uma fase especifica.
 */
export function validatePhaseCompletion(video: Video, phase: WizardPhase): PhaseValidation {
  const field = DATA_FIELDS[phase]
  const requiresReview = phase === 2 || phase === 3
  const isReviewed = video.reviewedPhases?.includes(phase) ?? false

  // Fase 8: check if video was sent
  if (phase === 8) {
    return {
      phase,
      isComplete: video.status === 'sent',
      hasData: video.status === 'sent',
      requiresReview: false,
      isReviewed: false,
    }
  }

  // Outras fases: check if data field exists
  const hasData = field ? hasValue(video[field]) : false

  // Fases 5-7 sao reprocessaveis - considerar completas se tem dados
  // Fases 1-4 sao imutaveis:
  //   - Fase 1, 4: completa se tem dados
  //   - Fase 2, 3: completa se tem dados E foi revisada
  const isComplete = requiresReview
    ? hasData && isReviewed
    : hasData

  return { phase, isComplete, hasData, requiresReview, isReviewed }
}

/**
 * Retorna a primeira fase incompleta (1-8).
 * Se todas completas, retorna 8.
 */
export function getFirstIncompletePhase(video: Video): WizardPhase {
  for (let phase = 1; phase <= 8; phase++) {
    const validation = validatePhaseCompletion(video, phase as WizardPhase)
    if (!validation.isComplete) return phase as WizardPhase
  }
  return 8
}

/**
 * Retorna validacao de todas as fases.
 */
export function getAllPhaseValidations(video: Video): PhaseValidation[] {
  return ([1, 2, 3, 4, 5, 6, 7, 8] as WizardPhase[]).map(phase =>
    validatePhaseCompletion(video, phase)
  )
}

/**
 * Helper para verificar se um valor existe e nao e vazio.
 */
function hasValue(value: unknown): boolean {
  if (value === undefined || value === null) return false
  if (typeof value === 'string') return value.trim().length > 0
  if (Array.isArray(value)) return value.length > 0
  return true
}

API Route - Reviewed Phases

// src/app/api/videos/[videoId]/reviewed-phases/route.ts

import { NextRequest, NextResponse } from 'next/server'
import { getServerSession } from 'next-auth'
import { authOptions } from '@/lib/auth'
import { updateVideo } from '@/lib/firestore/videos'
import { log } from '@/lib/logger'

export async function PUT(
  request: NextRequest,
  { params }: { params: Promise<{ videoId: string }> }
) {
  const { videoId } = await params
  const session = await getServerSession(authOptions)

  if (!session?.user?.id) {
    return NextResponse.json({ error: { message: 'Unauthorized' } }, { status: 401 })
  }

  try {
    const { phase } = await request.json()

    if (typeof phase !== 'number' || ![2, 3].includes(phase)) {
      return NextResponse.json(
        { error: { message: 'Invalid phase - must be 2 or 3' } },
        { status: 400 }
      )
    }

    // Usar arrayUnion para adicionar fase ao array
    await updateVideo(session.user.id, videoId, {
      reviewedPhases: admin.firestore.FieldValue.arrayUnion(phase)
    })

    log('INFO', 'Phase marked as reviewed', { videoId, phase, userId: session.user.id })

    return NextResponse.json({ success: true })
  } catch (error) {
    log('ERROR', 'Failed to mark phase as reviewed', { videoId, error })
    return NextResponse.json(
      { error: { message: 'Failed to update reviewed phases' } },
      { status: 500 }
    )
  }
}

Orchestrator - Navegacao Automatica

// wizard-orchestrator.tsx - ADICIONAR apos linha 91 (useEffect de video sync)

/**
 * Navigate to first incomplete phase on mount.
 * Only runs once when video loads.
 */
const initialNavigationRef = useRef<string | null>(null)

useEffect(() => {
  // Skip if we've already navigated for this video
  if (initialNavigationRef.current === video.id) {
    return
  }
  initialNavigationRef.current = video.id

  const firstIncomplete = getFirstIncompletePhase(video)

  // Only navigate if not already on the correct phase
  if (wizard.currentPhase !== firstIncomplete) {
    log('INFO', 'Auto-navigating to first incomplete phase', {
      videoId: video.id,
      from: wizard.currentPhase,
      to: firstIncomplete,
    })
    wizard.goToPhase(firstIncomplete)
  }
}, [video, wizard])

Consideracoes de Implementacao

  1. Backward Compatibility: reviewedPhases e opcional, videos antigos funcionam normalmente
  2. Fases 5-7: Sao reprocessaveis, entao nao precisam de confirmacao de revisao
  3. Performance: Evita chamadas LLM desnecessarias, melhora UX significativamente
  4. Estado Local vs Firestore: reviewedPhases persiste no Firestore para manter estado entre sessoes

Fluxo de Usuario

  1. Usuario abre video no wizard
  2. getFirstIncompletePhase(video) calcula onde comecar
  3. Se fase 1-4 tem dados:
    • Exibe dados do cache (sem LLM)
    • Se fase 2 ou 3: mostra ReviewConfirmationAlert
    • Usuario confirma revisao -> persiste em reviewedPhases
  4. Botao "Avancar" habilitado somente apos confirmacao (fases 2, 3)
  5. Proxima vez que abrir video, fases confirmadas nao pedem revisao novamente

describe('validatePhaseCompletion', () => {

    expect(result.isReviewed).toBe(true)
