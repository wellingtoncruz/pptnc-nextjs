Story 5.4: Auto-Retry em PARSE_ERROR

Status: done

Story

As a produtor, I want que o sistema tente novamente automaticamente quando o LLM retornar um JSON mal-formado, so that eu não precise clicar em "Tentar novamente" manualmente para erros transitórios.

Acceptance Criteria

  1. AC1: Retry Automático em PARSE_ERROR

    • Given uma chamada LLM para qualquer fase (1-7)
    • When o LLM retorna resposta mas o JSON está mal-formado (PARSE_ERROR)
    • Then o sistema tenta automaticamente até 3 vezes
    • And cada tentativa usa o mesmo prompt
    • And há um delay de 1 segundo entre tentativas
    • And log indica qual tentativa está sendo feita

  2. AC2: Sucesso em Tentativa Subsequente

    • Given uma chamada LLM que falhou com PARSE_ERROR na primeira tentativa
    • When a segunda ou terceira tentativa retorna JSON válido
    • Then o resultado é retornado normalmente
    • And log indica que sucesso foi na tentativa N

  3. AC3: Falha Após Todas as Tentativas

    • Given uma chamada LLM que falhou com PARSE_ERROR
    • When todas as 3 tentativas falham
    • Then retorna o erro PARSE_ERROR ao usuário
    • And mensagem indica que tentou 3 vezes sem sucesso
    • And log inclui detalhes de todas as tentativas

  4. AC4: Sem Retry para Outros Erros

    • Given uma chamada LLM que falha com outro tipo de erro (TIMEOUT, RATE_LIMIT, etc.)
    • When o erro é diferente de PARSE_ERROR
    • Then NÃO faz retry automático
    • And retorna o erro imediatamente
    • And comportamento atual é preservado

  5. AC5: Feedback Visual Durante Retry (opcional)

    • Given uma chamada LLM em retry
    • When o spinner está visível no console
    • Then o texto do spinner pode indicar "Tentativa X de 3..."
    • And usuário sabe que o sistema está tentando novamente

Tasks / Subtasks

  • Task 1: Implementar Retry Logic no Client (AC: 1, 2, 3, 4)

    • 1.1: Adicionar constantes MAX_PARSE_RETRIES = 3 e RETRY_DELAY_MS = 1000 em types.ts
    • 1.2: Modificar callVertexAIWithAttachment para implementar loop de retry
    • 1.3: Criar função helper shouldRetry(error): boolean que retorna true apenas para PARSE_ERROR
    • 1.4: Implementar delay de 1s entre tentativas usando await new Promise(resolve => setTimeout(resolve, RETRY_DELAY_MS))
    • 1.5: Adicionar logs detalhados para cada tentativa (WARN no retry, ERROR se falhou todas)
    • 1.6: Retornar resultado da primeira tentativa bem-sucedida

  • Task 2: Melhorar Mensagem de Erro (AC: 3)

    • 2.1: Atualizar mensagem de PARSE_ERROR para incluir contagem de tentativas
    • 2.2: Formato: "Erro ao parsear resposta após 3 tentativas. O LLM retornou dados em formato inválido."

  • Task 3: Testes (AC: 1-4)

Dev Notes

Arquitetura Atual (client.ts)

O erro de PARSE_ERROR ocorre nas linhas 226-234 de callVertexAIWithAttachment:

// Parse JSON with robust extraction (handles markdown code blocks, extra text, etc.)
const data = parseJSONFromLLM<T>(text)
if (data === null) {
  // Log raw response for debugging
  log('ERROR', 'Failed to parse JSON from LLM response', {
    rawResponseLength: text.length,
    rawResponsePreview: text.substring(0, 500),
    rawResponseEnd: text.length > 500 ? text.substring(text.length - 200) : undefined,
  })
  throw new LLMError('PARSE_ERROR', 'Erro ao parsear JSON da resposta', false)
}

Solução Implementada

A lógica de retry foi implementada DENTRO de callVertexAIWithAttachment:

// src/lib/llm/types.ts
export const MAX_PARSE_RETRIES = 3
export const RETRY_DELAY_MS = 1000

// src/lib/llm/client.ts - Principais características:
// 1. Timeout timer é cancelado com clearTimeout após sucesso ou erro
// 2. Retry acontece apenas para PARSE_ERROR (via continue no loop)
// 3. Outros erros (TIMEOUT, RATE_LIMIT) falham imediatamente
// 4. O attachment base64 é reutilizado em todas as tentativas

Por que retry DENTRO de callVertexAIWithAttachment?

  1. Eficiência: O arquivo de transcrição já está carregado em base64
  2. Atomicidade: O retry é transparente para o caller
  3. Simplicidade: Não precisa propagar estado de retry para camadas superiores
  4. Memory safety: Timeout timers são sempre cancelados com clearTimeout

Erros que NÃO devem ter retry

  • TIMEOUT: Pode indicar problema persistente, retry pode piorar
  • RATE_LIMIT: Retry imediato vai agravar o problema
  • INVALID_RESPONSE: Não tem conteúdo para tentar novamente
  • MISSING_TRANSCRIPT: Erro de configuração, não transitório
  • MISSING_CONTEXT: Erro de configuração, não transitório

Testing Patterns

// client.test.ts

describe('PARSE_ERROR retry', () => {
  beforeEach(() => {
    vi.useFakeTimers()
  })

  afterEach(() => {
    vi.useRealTimers()
  })

  it('retries on PARSE_ERROR and succeeds on second attempt', async () => {
    const parseJsonMock = vi.spyOn(parseJson, 'parseJSONFromLLM')
      .mockReturnValueOnce(null)  // First attempt fails
      .mockReturnValueOnce({ critique: 'Good!' })  // Second succeeds

    const resultPromise = callLLM(1, mockVideo)

    // Advance timer for retry delay
    await vi.advanceTimersByTimeAsync(RETRY_DELAY_MS)

    const result = await resultPromise

    expect(result.success).toBe(true)
    expect(parseJsonMock).toHaveBeenCalledTimes(2)
  })

  it('fails after MAX_PARSE_RETRIES attempts', async () => {
    vi.spyOn(parseJson, 'parseJSONFromLLM').mockReturnValue(null)

    const resultPromise = callLLM(1, mockVideo)

    // Advance timers for all retries
    for (let i = 0; i < MAX_PARSE_RETRIES - 1; i++) {
      await vi.advanceTimersByTimeAsync(RETRY_DELAY_MS)
    }

    const result = await resultPromise

    expect(result.success).toBe(false)
    expect(result.error?.code).toBe('PARSE_ERROR')
    expect(result.error?.message).toContain('3 tentativas')
  })

  it('does not retry on TIMEOUT error', async () => {
    const generateMock = vi.fn().mockRejectedValue(
      new LLMError('TIMEOUT', 'Timeout', true)
    )
    vi.spyOn(model, 'generateContent').mockImplementation(generateMock)

    const result = await callLLM(1, mockVideo)

    expect(result.success).toBe(false)
    expect(result.error?.code).toBe('TIMEOUT')
    expect(generateMock).toHaveBeenCalledTimes(1) // No retry
  })

  it('waits RETRY_DELAY_MS between attempts', async () => {
    const parseJsonMock = vi.spyOn(parseJson, 'parseJSONFromLLM')
      .mockReturnValueOnce(null)
      .mockReturnValueOnce(null)
      .mockReturnValueOnce({ critique: 'Good!' })

    const startTime = Date.now()
    const resultPromise = callLLM(1, mockVideo)

    // First retry
    await vi.advanceTimersByTimeAsync(RETRY_DELAY_MS)
    // Second retry
    await vi.advanceTimersByTimeAsync(RETRY_DELAY_MS)

    await resultPromise

    expect(parseJsonMock).toHaveBeenCalledTimes(3)
  })
})
