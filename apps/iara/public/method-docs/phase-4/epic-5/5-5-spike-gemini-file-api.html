Story 5.5: Spike - Gemini File API para Reutilização de Transcrição

Status: done

Story

As a desenvolvedor, I want investigar se o Gemini File API pode ser usado para fazer upload da transcrição uma vez e reutilizá-la em múltiplas chamadas LLM, so that possamos reduzir latência, custo de tokens e complexidade nas chamadas das fases 1-7.

Acceptance Criteria (Spike)

  1. AC1: Documentar API do Gemini File

    • Pesquisar documentação oficial (Vertex AI e Gemini API)
    • Verificar se @google-cloud/vertexai SDK suporta File API
    • Documentar: endpoints, autenticação, limites, custos, TTL

  2. AC2: Prova de Conceito (se API disponível)

    • Criar script de teste para upload de arquivo
    • Testar chamada generateContent com file URI
    • Medir: tempo de upload, tempo de resposta, tokens usados

  3. AC3: Análise de Trade-offs e Recomendação

    • Documentar prós, contras, riscos
    • Estimar esforço de implementação completa
    • Fazer recomendação final: IMPLEMENT, DEFER, ou DISCARD

Objetivo

Investigar viabilidade e beneficios de usar a Gemini File API para reutilizar arquivos de transcricao (SRT/TXT) entre chamadas LLM do mesmo video.

Hipotese

Ao fazer upload do arquivo de transcricao uma unica vez e reutilizar o file_id nas chamadas subsequentes (fases 1-7), podemos:

  • Reduzir consumo de tokens (transcricao nao e re-tokenizada)
  • Reduzir trafego de rede (upload unico)
  • Melhorar latencia das chamadas

Questoes a Investigar

  1. API Compatibility

    • A Vertex AI (usado atualmente) suporta File API ou apenas a API direta do Gemini?
    • Qual endpoint usar: files.create ou media.upload?
    • Como referenciar arquivo em generateContent?

  2. Economia Real

    • Arquivos uploadados contam tokens no upload ou apenas na geracao?
    • Qual o custo comparativo: inline vs file reference?
    • Ha cache de tokens no lado do Gemini?

  3. Limitacoes

    • TTL dos arquivos (documentacao menciona 48h)
    • Tamanho maximo de arquivo
    • Rate limits de upload
    • Regiao/disponibilidade

  4. Implementacao

    • Como gerenciar file_id entre chamadas?
    • Quando invalidar/re-upload (troca de video, expiracao)?
    • Impacto na arquitetura atual (inline attachment)

Tasks / Subtasks

  • Task 1: Pesquisar Documentação (AC: 1)

    • 1.1: Pesquisar Gemini File API na documentação oficial
    • 1.2: Verificar se Vertex AI SDK (@google-cloud/vertexai) suporta File API
    • 1.3: Documentar: endpoints, autenticação, limites de tamanho, TTL

  • Task 2: Prova de Conceito (AC: 2) - se API disponível N/A - Vertex AI não suporta Files API

  • Task 3: Análise e Recomendação (AC: 3)

Spike Output (Janeiro 2026)

Descobertas

1. Diferença Crítica: Gemini API vs Vertex AI

Aspecto Gemini API (direta) Vertex AI (usado pelo IAra)
Files API Sim, dedicada Não existe
Upload de arquivos files.create endpoint Via GCS bucket
Referência em prompts files/{file_id} URI gs://bucket/path URI
TTL automático 48 horas N/A (gerenciado por você)
SDK @google/genai @google-cloud/vertexai

Conclusão: O Gemini API (ai.google.dev) possui uma Files API dedicada, mas o Vertex AI (usado pelo IAra) NÃO possui esta funcionalidade.

2. Vertex AI - Suporte a Arquivos

O SDK @google-cloud/vertexai suporta FileDataPart com a seguinte interface:

// node_modules/@google-cloud/vertexai/build/src/types/content.d.ts
export interface FileData {
  mimeType: string;
  fileUri: string;  // Deve ser gs:// ou URL HTTP pública
}
export interface FileDataPart extends BasePart {
  fileData: FileData;
}

O fileUri aceita:

  • gs://bucket-name/path/to/file - Google Cloud Storage
  • URL HTTP/HTTPS pública

NÃO aceita: URIs do tipo files/{file_id} como a Gemini API direta.

3. Gemini API Files API (Referência)

Para completude, documentamos a Files API da Gemini API direta:

Limite Valor
Tamanho máximo por arquivo 2 GB
Storage total por projeto 20 GB
TTL (Time-to-Live) 48 horas (não configurável)
Formatos suportados text/, image/, audio/, video/, application/pdf 
# Exemplo Gemini API (NÃO compatível com Vertex AI)
import google.generativeai as genai
file = genai.upload_file("transcription.txt")
model.generate_content([file, "Analise esta transcrição"])

4. Alternativa com GCS para Vertex AI

Para reutilizar arquivos no Vertex AI, seria necessário:

  1. Criar bucket GCS no projeto
  2. Upload via Cloud Storage SDK:
    import { Storage } from '@google-cloud/storage'
const storage = new Storage()
await storage.bucket('iara-transcriptions').upload(localPath)
  3. Referência no prompt:
    parts.push({
  fileData: {
    fileUri: 'gs://iara-transcriptions/video-123.txt',
    mimeType: 'text/plain',
  }
})
  4. Gerenciar limpeza (lifecycle policies ou cron job)

Análise de Trade-offs

Prós (se implementado via GCS)

  • Transcrição carregada uma vez por vídeo
  • Menor tráfego de rede nas fases 2-7
  • Potencial economia de tokens (a verificar)

Contras

  • Infraestrutura adicional: Bucket GCS, permissões IAM
  • Complexidade operacional: Lifecycle policies, limpeza
  • Custo de storage: ~$0.02/GB/mês (mínimo, mas existe)
  • Latência de upload: Upload para GCS antes da primeira chamada
  • Gerenciamento de estado: Saber se arquivo já existe no bucket
  • Sem garantia de economia: Tokens podem ser contados da mesma forma

Riscos

  • Não há documentação clara se referência por GCS economiza tokens vs inline
  • Complexidade desnecessária para o tamanho atual das transcrições (~50-200KB)
  • Custo-benefício questionável dado overhead de infraestrutura

Total 8-13h

Recomendação Final (Janeiro 2026)

Decisão: DISCARD

Justificativa:

  1. API não disponível: O Vertex AI (usado pelo IAra) não possui a Files API que motivou este spike. A alternativa (GCS) requer infraestrutura adicional significativa.

  2. Custo-benefício desfavorável: Para transcrições de ~50-200KB, o overhead de criar/gerenciar bucket GCS não justifica o potencial benefício.

  3. Economia incerta: Não há confirmação de que usar fileUri vs inlineData economiza tokens ou reduz latência significativamente.

  4. Implementação atual funciona bem: O approach de inline attachment com arquivo temporário local atende as necessidades atuais sem dependências externas.

  5. Complexidade desnecessária: Adicionar GCS introduz ponto de falha adicional, custos recorrentes, e necessidade de gerenciamento de lifecycle.

Reavaliação (Fevereiro 2026) — Party-Mode

Descoberta Crítica

O SDK @google-cloud/vertexai foi deprecated em Jun 2025 com remoção prevista para Jun 2026. O substituto oficial é @google/genai que:

  1. Suporta ambos Gemini API e Vertex AI com a mesma interface
  2. Possui módulo ai.files para upload e reutilização de arquivos
  3. Retorna file_uri reutilizável em múltiplas chamadas generateContent
  4. TTL de 48h (suficiente para sessão de processamento de vídeo)

Recomendação Atualizada

Decisão atualizada: DISCARD → DEFER (vinculado à migração obrigatória do SDK)

O file reuse deixa de ser um esforço isolado e passa a ser uma story dentro do epic de migração de SDK, que é obrigatório antes de Jun 2026.
