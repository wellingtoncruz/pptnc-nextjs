Story 5.2: Correcao Phase 8 - Dados do Resumo

Status: done

Story

As a produtor, I want ver os dados reais de descricao, tags e capitulos no resumo da Fase 8, so that eu possa revisar o conteudo antes de enviar ao YouTube.

Acceptance Criteria

  1. AC1: Exibicao da Descricao Completa

    • Given o Wizard na Fase 8
    • When a fase e renderizada
    • Then o campo "Descricao" mostra o conteudo de video.description
    • And se video.description estiver vazio, mostra placeholder "Descricao nao definida"
    • And preview truncado em 200 caracteres com "..." se maior

  2. AC2: Exibicao das Tags

    • Given o Wizard na Fase 8
    • When a fase e renderizada
    • Then o campo "Tags" mostra as tags de video.tags
    • And exibe contagem: "X tags"
    • And se video.tags estiver vazio/undefined, mostra "0 tags"

  3. AC3: Exibicao dos Capitulos

    • Given o Wizard na Fase 8
    • When a fase e renderizada
    • Then o campo "Capitulos" mostra os capitulos de video.chapters
    • And exibe contagem: "X capitulos"
    • And se video.chapters estiver vazio/undefined, mostra "0 capitulos"

  4. AC4: Dados Salvos ao Avancar Fases

    • Given o usuario na Fase 6 (Descricao) ou Fase 7 (Tags)
    • When clica em "Avancar"
    • Then os dados sao salvos em videoData MESMO se nao editou manualmente
    • And os dados persistem ate a Fase 8

  5. AC5: Chapters Atualizados no VideoData

    • Given a Fase 4 (Capitulos) processada com sucesso
    • When LLM retorna chapters
    • Then videoData.chapters e atualizado com os chapters
    • And chapters aparecem na Fase 8

Tasks / Subtasks

  • Task 1: Corrigir Phase6Description - Salvar ao Avancar (AC: 4)

    • 1.1: Modificar handleAdvanceClick para SEMPRE chamar onDescriptionChange
    • 1.2: Remover condicao if (debounceTimerRef.current) que impedia salvamento
    • 1.3: Atualizar testes para nova logica async

  • Task 2: Corrigir Phase7Tags - Salvar ao Avancar (AC: 4)

    • 2.1: Modificar handleAdvanceClick para chamar onTagsChange antes de avancar
    • 2.2: Tornar funcao async para aguardar salvamento
    • 2.3: Atualizar testes para nova logica async

  • Task 3: Corrigir Orchestrator - Atualizar VideoData com Chapters (AC: 5)

    • 3.1: Apos setChaptersResult, tambem chamar setVideoData com chapters
    • 3.2: Garantir que chapters da API sao refletidos no estado local

  • Task 4: Testes (AC: 1-5)

    • 4.1: Atualizar testes de Phase6Description com act() e waitFor()
    • 4.2: Atualizar testes de Phase7Tags com waitFor()
    • 4.3: Verificar que mock de onDescriptionChange e onTagsChange sao chamados

Dev Notes

Causa Raiz Identificada

O bug ocorre porque:

  1. Phase6Description: onDescriptionChange so era chamado se usuario editasse (ativando debounce timer). Se aceitasse descricao do LLM sem editar, dados nao eram salvos em videoData.

  2. Phase7Tags: onTagsChange so era chamado ao adicionar/remover tags. Se aceitasse tags do LLM sem modificar, dados nao eram salvos em videoData.

  3. Orchestrator/Chapters: Apos setChaptersResult, videoData.chapters nao era atualizado.

Fluxo de Dados Corrigido

Phase 6 → handleAdvanceClick → onDescriptionChange → setVideoData({ description })
Phase 7 → handleAdvanceClick → onTagsChange → setVideoData({ tags })
Phase 4 → processPhase4Chapters → setChaptersResult + setVideoData({ chapters })
Phase 8 → videoData tem todos os campos → exibe corretamente

Codigo da Correcao - Phase6Description

// ANTES (bugado)
const handleAdvanceClick = async () => {
  if (!canAdvance) return
  if (debounceTimerRef.current) {  // <-- So salva se tinha timer!
    clearTimeout(debounceTimerRef.current)
    await onDescriptionChange?.(description)
  }
  wizard.completePhaseAndAdvance(6, { description })
}

// DEPOIS (corrigido)
const handleAdvanceClick = async () => {
  if (!canAdvance) return
  if (debounceTimerRef.current) {
    clearTimeout(debounceTimerRef.current)
  }
  // SEMPRE salva antes de avancar
  try {
    await onDescriptionChange?.(description)
  } catch {
    // Error handled by onDescriptionChange
  }
  wizard.completePhaseAndAdvance(6, { description })
}
