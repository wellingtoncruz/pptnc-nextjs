Story 2.6: Correcoes Schema Podcast e Autenticacao

Status: done

Story

Como um usuario e desenvolvedor, Eu quero corrigir o bug de duplicacao de usuarios e reestruturar o schema de prompts e personas, Para que a autenticacao funcione corretamente e os prompts atendam aos requisitos de negocio.

Context

Problemas Identificados na Retrospectiva do Epic 2

  1. Bug de Autenticacao: Login/logoff cria novo usuario ao inves de atualizar tokens existentes
  2. Schema de Prompts Incorreto: Implementado 1:1 (um prompt por tipo) quando deveria ser multiplos prompts por tipo
  3. Personas Ausentes: Faltam personas (critico, redator) no nivel do podcast

Divergencia Arquitetural

O schema atual de prompts:

prompts: { episode: string, cut: string, reel: string }

Deveria ser multiplos prompts por tipo, cada um com description e expectedOutput.

Acceptance Criteria

AC1: Fix Usuario Duplicado

Given um usuario ja autenticado anteriormente When ele faz login novamente Then o documento existente em podcasts/{podcastId}/users/{userId} e atualizado And NAO e criado um novo documento And os tokens OAuth sao atualizados na subcollection tokens/oauth

AC2: Persistir Nome e Avatar

Given um usuario fazendo login via Google OAuth When o login e bem sucedido Then os campos name e picture do Google sao persistidos no documento do usuario And esses campos sao atualizados a cada login (podem mudar no Google)

AC3: Novo Schema de Prompts por Tipo

Given o documento do podcast When eu acesso prompts Then a estrutura e:

prompts: {
  episode: {
    critique: { description: string, expectedOutput: string },
    editing: { description: string, expectedOutput: string },
    compliance: { description: string, expectedOutput: string },
    titles: { description: string, expectedOutput: string },
    description: { description: string, expectedOutput: string },
    tags: { description: string, expectedOutput: string },
  },
  cut: {
    titles: { description: string, expectedOutput: string },
    thumbs: { description: string, expectedOutput: string },
    description: { description: string, expectedOutput: string },
    tags: { description: string, expectedOutput: string },
  },
  reel: {
    titles: { description: string, expectedOutput: string },
    description: { description: string, expectedOutput: string },
    tags: { description: string, expectedOutput: string },
  }
}

AC4: Schema de Personas

Given o documento do podcast When eu acesso personas Then a estrutura e:

personas: {
  critic: { role: string, objective: string, resume: string },
  writer: { role: string, objective: string, resume: string },
}

And personas sao campos do podcast (nivel geral, nao por tipo de video)

AC5: UI de Configuracao de Prompts Atualizada

Given a tela de configuracoes (/settings) When o usuario acessa a secao de prompts Then ve os prompts organizados por tipo de video (Episode, Cut, Reel) And dentro de cada tipo, ve os prompts especificos (critique, editing, etc) And cada prompt tem campos para description e expectedOutput And auto-save funciona para cada campo

AC6: UI de Configuracao de Personas

Given a tela de configuracoes (/settings) When o usuario acessa a secao de personas Then ve duas personas: Critico e Redator And cada persona tem campos para role, objective, resume And auto-save funciona para cada campo

AC7: Validacao Zod Atualizada

Given os novos schemas When dados sao validados Then PodcastSchema valida a nova estrutura de prompts e personas And PodcastUpdateSchema permite updates parciais And testes unitarios cobrem os novos schemas

AC8: Migracao do Documento Existente

Given o documento de podcast existente no ambiente de desenvolvimento When a aplicacao inicia Then o documento e atualizado para o novo schema (manual ou via script) And subcollections (videos) NAO sao afetadas

Logica de Upsert no Login

// Em src/lib/auth.ts ou callbacks
async function handleSignIn(user, account) {
  const userRef = doc(db, `podcasts/${PODCAST_ID}/users/${user.id}`)
  const userDoc = await getDoc(userRef)

  if (userDoc.exists()) {
    // UPDATE: usuario existente
    await updateDoc(userRef, {
      name: user.name,
      picture: user.image,
      updatedAt: serverTimestamp(),
    })
  } else {
    // CREATE: novo usuario
    await setDoc(userRef, {
      id: user.id,
      email: user.email,
      name: user.name,
      picture: user.image,
      role: 'viewer', // default role
      createdAt: serverTimestamp(),
      updatedAt: serverTimestamp(),
    })
  }

  // Tokens em subcollection separada (ja existente)
  await saveUserTokens(user.id, account)
}
