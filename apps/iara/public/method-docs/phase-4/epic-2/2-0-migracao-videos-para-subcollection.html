Story 2.0: Migracao de Videos para Subcollection

Status: done

Story

Como um sistema, Eu quero migrar a collection legada videos para a subcollection podcasts/{podcastId}/videos, Para que o modelo de dados esteja alinhado com a arquitetura white-label desde o inicio.

Context

Problema

O portal PPTNC existente usa uma flat entity videos/{videoId}. A arquitetura do IAra define subcollections podcasts/{podcastId}/videos/{videoId} para suportar white-label.

Ambos os sistemas (Portal e IAra) operam na mesma base Firestore. Esta migracao prepara a base de desenvolvimento (pptnc-stage) para o padrao correto.

Decisao Arquitetural

Per architecture-iara.md:

podcasts/{podcastId}/videos/{videoId}
├── youtubeId: string
├── title: string
├── ...

Impacto

  • Portal PPTNC producao: Continua lendo de videos/ (nao afetado)
  • Portal PPTNC stage: Pode ser atualizado para ler da subcollection apos migracao
  • IAra: Vai criar novos videos ja na subcollection correta (Epic 3)

Acceptance Criteria

AC1: Script de migracao criado

Given a collection legada videos no Firestore When eu executo o script de migracao Then todos os documentos sao copiados para podcasts/pptnc/videos/{videoId} And o campo podcastId: 'pptnc' e adicionado em cada documento And os documentos originais NAO sao deletados (soft migration)

AC2: Validacao de contagem

Given a migracao executada When eu verifico as contagens Then o numero de documentos em podcasts/pptnc/videos e igual ao numero em videos And um log de validacao e gerado

AC3: Preservacao de dados

Given cada documento migrado When eu comparo com o original Then todos os campos originais estao preservados And campos adicionados: podcastId, migratedAt And campo id do documento e preservado (mesmo videoId)

AC4: Idempotencia

Given o script executado multiplas vezes When um documento ja existe na subcollection Then o documento NAO e sobrescrito And um log indica "documento ja migrado"

AC5: Relatorio de migracao

Given a migracao completa When o script finaliza Then exibe relatorio:

  • Total de documentos na origem
  • Documentos migrados (novos)
  • Documentos ja existentes (skipped)
  • Erros (se houver)

Estrutura do Script

// scripts/migrate-videos-to-subcollection.ts
import { initializeApp, cert, getApps } from 'firebase-admin/app'
import { getFirestore, FieldValue } from 'firebase-admin/firestore'

const PODCAST_ID = 'pptnc'
const SOURCE_COLLECTION = 'videos'
const TARGET_PATH = `podcasts/${PODCAST_ID}/videos`

async function migrate() {
  const db = getFirestore()

  // 1. Read all source documents
  const sourceSnapshot = await db.collection(SOURCE_COLLECTION).get()
  console.log(`Found ${sourceSnapshot.size} documents in ${SOURCE_COLLECTION}`)

  let migrated = 0
  let skipped = 0
  let errors = 0

  for (const doc of sourceSnapshot.docs) {
    const targetRef = db.collection(TARGET_PATH).doc(doc.id)
    const targetDoc = await targetRef.get()

    if (targetDoc.exists) {
      console.log(`SKIP: ${doc.id} already exists`)
      skipped++
      continue
    }

    try {
      await targetRef.set({
        ...doc.data(),
        podcastId: PODCAST_ID,
        migratedAt: FieldValue.serverTimestamp(),
      })
      console.log(`MIGRATED: ${doc.id}`)
      migrated++
    } catch (error) {
      console.error(`ERROR: ${doc.id}`, error)
      errors++
    }
  }

  // Report
  console.log('\n=== MIGRATION REPORT ===')
  console.log(`Source documents: ${sourceSnapshot.size}`)
  console.log(`Migrated: ${migrated}`)
  console.log(`Skipped: ${skipped}`)
  console.log(`Errors: ${errors}`)
}

Enforcement Rules Aplicaveis

  1. Rule #8 (podcastId em queries): Adicionar podcastId em cada documento migrado
  2. Rule #9 (Structured Logging): Usar logs estruturados para rastreabilidade
  3. Rule #4 (No setDoc sem merge): Usar set() apenas para novos documentos

Seguranca

  • Script roda com credenciais de desenvolvedor (ADC)
  • Nao deleta documentos originais
  • Idempotente - pode ser executado multiplas vezes sem risco

Rollback

Se necessario reverter:

  1. Documentos originais em videos/ permanecem intactos
  2. Deletar documentos em podcasts/pptnc/videos/ se necessario
