Story 2.2: Firestore Collection e Operações de Podcast

Status: done

Story

Como um sistema, Eu quero operações CRUD para podcasts no Firestore, Para que as configurações sejam persistidas e recuperadas corretamente.

Acceptance Criteria

AC1: getPodcast retorna documento validado

Given um usuário autenticado When eu chamo getPodcast(podcastId) Then retorna o documento do podcast validado com Zod And inclui podcastId em toda query (enforcement rule #8)

AC2: updatePodcast com field-level merge

Given um podcast existente When eu chamo updatePodcast(podcastId, data) Then apenas os campos fornecidos são atualizados (field-level merge) And updatedAt é atualizado com serverTimestamp() ou FieldValue.serverTimestamp() And NÃO usa setDoc sem merge (enforcement rule #4)

AC3: createPodcast com validação Zod

Given um usuário administrador When eu chamo createPodcast(data) Then um novo documento é criado em podcasts/{podcastId} And os dados são validados com Zod ANTES de salvar (enforcement rule #2) And createdAt e updatedAt são definidos

AC4: Client SDK para leitura

Given operação de leitura do podcast (Client Component) When eu uso o client SDK Then importo de firebase/firestore And uso serverTimestamp() para timestamps

AC5: Admin SDK para Route Handlers

Given operação de escrita em Route Handler When eu uso o admin SDK Then importo de firebase-admin/firestore And uso FieldValue.serverTimestamp() (não serverTimestamp())

AC6: Structured logging

Given qualquer operação de podcast When ocorre erro ou evento importante Then usa log() de lib/logger.ts (enforcement rule #9) And nunca usa console.log

AC7: Testes unitários

Given testes para as funções de podcast When eu executo pnpm test Then testes cobrem getPodcast, updatePodcast, createPodcast And testes mockam Firestore (não usam emulator para unit tests)

Padrão de Implementação - Client

// src/lib/firebase/podcasts.ts
import { doc, getDoc, updateDoc, serverTimestamp } from 'firebase/firestore'

import { db } from './client'
import { PODCAST_ID } from './config'
import { PodcastSchema, PodcastUpdateSchema } from '@/lib/schemas'
import { log } from '@/lib/logger'
import type { Podcast, PodcastUpdate } from '@/types/podcast'

export async function getPodcast(podcastId: string): Promise<Podcast | null> {
  const docRef = doc(db, 'podcasts', podcastId)
  const docSnap = await getDoc(docRef)

  if (!docSnap.exists()) {
    return null
  }

  const data = { id: docSnap.id, ...docSnap.data() }
  return PodcastSchema.parse(data)
}

export async function updatePodcast(
  podcastId: string,
  data: PodcastUpdate
): Promise<void> {
  // Validar ANTES de persistir
  const validated = PodcastUpdateSchema.parse(data)

  const docRef = doc(db, 'podcasts', podcastId)
  await updateDoc(docRef, {
    ...validated,
    updatedAt: serverTimestamp(),
  })
}

Padrão de Implementação - Admin

// src/lib/firebase/podcasts-admin.ts
import { FieldValue } from 'firebase-admin/firestore'

import { adminDb } from './admin'
import { PodcastCreateSchema, PodcastUpdateSchema } from '@/lib/schemas'
import { log } from '@/lib/logger'
import type { Podcast, PodcastCreate, PodcastUpdate } from '@/types/podcast'

export async function createPodcastAdmin(
  podcastId: string,
  data: PodcastCreate
): Promise<Podcast> {
  // Validar ANTES de persistir
  const validated = PodcastCreateSchema.parse(data)

  const docRef = adminDb.collection('podcasts').doc(podcastId)
  const now = FieldValue.serverTimestamp()

  await docRef.set({
    ...validated,
    createdAt: now,
    updatedAt: now,
  })

  // Buscar documento criado para retornar com timestamps resolvidos
  const created = await docRef.get()
  return { id: created.id, ...created.data() } as Podcast
}

Enforcement Rules Aplicáveis

  1. Rule #2 (Zod Validation): Validar com Zod ANTES de persistir
  2. Rule #4 (Field-Level Updates): Usar updateDoc, nunca setDoc sem merge
  3. Rule #8 (PodcastId): Incluir podcastId em toda query
  4. Rule #9 (Structured Logging): Usar log(), nunca console.log
  5. Rule #11 (Import Type): Usar import type para types
  6. Rule #12 (Timestamp SDK): Client usa serverTimestamp(), Admin usa FieldValue.serverTimestamp()
