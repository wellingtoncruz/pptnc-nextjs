Story 2.4: Configuracao de Prompts por Tipo de Video

Status: done

Story

Como um usuario, Eu quero configurar prompts diferentes para cada tipo de video, Para que a IA gere metadados otimizados para episodios, cortes e reels.

Acceptance Criteria

AC1: Visualizacao de Prompts

Given a tela de configuracoes When o usuario expande a secao "Prompts" Then ve tres areas de texto:

  • Prompt para Episodios
  • Prompt para Cortes
  • Prompt para Reels

AC2: Informacoes do Prompt

Given cada area de prompt When o usuario visualiza Then ve o prompt atual (ou placeholder se vazio) And ve contador de caracteres And ve dica sobre variaveis disponiveis: {title}, {transcript}, {duration}

AC3: Auto-Save de Prompts

Given o usuario edita um prompt When ele modifica o texto Then o auto-save e acionado apos 1.5s de inatividade And ve indicador "Salvando..." durante a operacao And ve indicador "Salvo" apos sucesso

AC4: Validacao de Tamanho

Given um prompt muito longo (> 10000 caracteres) When o usuario tenta salvar Then ve erro de validacao inline And a operacao de save e bloqueada

AC5: Visualizacao de Duracao

Given a configuracao de duracao por tipo When o usuario visualiza Then ve os ranges de duracao para classificacao:

  • Episodio: > 20 minutos (1200s)
  • Corte: 3-20 minutos (180s - 1199s)
  • Reel: < 3 minutos (0s - 179s) And pode editar os limites de duracao

AC6: Validacao de Duracao

Given o usuario edita limites de duracao When valores invalidos sao inseridos (negativos, sobrepostos) Then ve erro de validacao inline And a operacao de save e bloqueada

PromptEditor Component Pattern

// src/components/settings/prompt-editor.tsx
'use client'

import { useState } from 'react'
import { z } from 'zod'

import { Textarea } from '@/components/ui/textarea'
import { Label } from '@/components/ui/label'
import { useAutoSave } from '@/hooks/use-auto-save'
import { MAX_PROMPT_LENGTH } from '@/lib/schemas/podcast'
import { SaveStatusIndicator } from './save-status-indicator'

const PromptSchema = z.string().max(MAX_PROMPT_LENGTH)

interface PromptEditorProps {
  type: 'episode' | 'cut' | 'reel'
  label: string
  initialValue: string
  onSave: (value: string) => Promise<void>
}

export function PromptEditor({ type, label, initialValue, onSave }: PromptEditorProps) {
  const [value, setValue] = useState(initialValue)
  const [validationError, setValidationError] = useState<string | null>(null)

  const { saveStatus, save } = useAutoSave(
    value,
    async (val) => {
      setValidationError(null)
      const result = PromptSchema.safeParse(val)
      if (!result.success) {
        setValidationError(result.error.issues[0]?.message || 'Valor invalido')
        // Return early - validation errors are expected, not save failures
        return
      }
      await onSave(val)
    },
    1500
  )
  // ... render
}

Enforcement Rules Aplicaveis

  1. Rule #2 (Zod Validation): Validar prompts com Zod ANTES de salvar
  2. Rule #4 (Field-Level Updates): Usar prompts.episode, prompts.cut, etc.
  3. Rule #6 (File Naming): kebab-case para arquivos
  4. Rule #9 (Structured Logging): Usar log() para erros
  5. Rule #11 (Import Type): Usar import type quando aplicavel

Learnings from Story 2-3

  1. Serialization: Timestamps precisam ser convertidos para ISO strings antes de passar para Client Components
  2. API Route Pattern: Usar /api/podcast com PATCH para updates
  3. Zod v4: Usar err.issues[0]?.message (nao err.errors)
  4. Test Utils: Importar de @/test-utils, nao @testing-library/react
  5. act() Warnings: Envolver operacoes async em act() nos testes
