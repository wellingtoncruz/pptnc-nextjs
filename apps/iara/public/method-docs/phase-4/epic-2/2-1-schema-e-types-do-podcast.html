Story 2.1: Schema e Types do Podcast

Status: done

Story

Como um desenvolvedor, Eu quero schemas Zod e types TypeScript para o Podcast, Para que os dados sejam validados em runtime e tipados em compile time.

Acceptance Criteria

AC1: PodcastSchema com campos obrigatorios

Given a necessidade de validar dados de podcast When eu importo os schemas de src/lib/schemas/podcast.ts Then tenho acesso ao PodcastSchema com os campos:

  • id: string
  • name: string
  • channelId: string
  • ownerId: string
  • prompts: { episode: string, cut: string, reel: string }
  • videoTypes: { episode: VideoTypeConfig, cut: VideoTypeConfig, reel: VideoTypeConfig }
  • createdAt: Timestamp
  • updatedAt: Timestamp

AC2: Validacao de dados invalidos

Given dados invalidos de podcast When eu valido com PodcastSchema.parse(data) Then lanca ZodError com mensagens descritivas

AC3: Validacao de dados validos

Given dados validos de podcast When eu valido com PodcastSchema.parse(data) Then retorna o objeto tipado Podcast

AC4: Type inference do Zod

And existe src/types/podcast.ts com type Podcast inferido do Zod And usa z.infer<typeof PodcastSchema> para gerar types

AC5: VideoTypeConfig schema

And existe VideoTypeConfig para configuracao de duracao por tipo com:

  • minDuration: number (em segundos)
  • maxDuration: number | null (null = sem limite)

AC6: Valores default para videoTypes

And valores default para videoTypes:

  • episode: minDuration 1200s (20min), maxDuration null
  • cut: minDuration 180s (3min), maxDuration 1199s
  • reel: minDuration 0, maxDuration 179s

AC7: Schemas auxiliares

And existem schemas separados:

  • PodcastSchema - schema completo para leitura
  • PodcastCreateSchema - schema para criacao (sem id, createdAt, updatedAt)
  • PodcastUpdateSchema - schema parcial para atualizacao

AC8: Testes unitarios

Given testes para os schemas When eu executo pnpm test Then testes cobrem validacao de dados validos And testes cobrem validacao de dados invalidos (campos faltando, tipos errados) And testes cobrem valores default de videoTypes

Dev Notes

Firestore Schema Reference (Architecture)

Per architecture-iara.md, o schema do Firestore para podcasts e:

podcasts/{podcastId}
├── name: string
├── channelId: string
├── prompts: { episode: string, cut: string, reel: string }
├── compliancePrompt: string
├── videoTypes: { episode: { minDuration }, cut: {...}, reel: {...} }
└── createdAt: Timestamp

ATENCAO ARQUITETURAL: O schema Zod DEVE corresponder EXATAMENTE ao schema do Firestore documentado na arquitetura. Se houver duvida, ESCALAR antes de implementar.

Zod + Firestore Timestamp Pattern

import { z } from 'zod'
import type { Timestamp } from 'firebase/firestore'

// Para Timestamps do Firestore, usar z.custom
const TimestampSchema = z.custom<Timestamp>((val) => {
  return val && typeof val === 'object' && 'toDate' in val
}, 'Invalid Firestore Timestamp')

// Ou para maior flexibilidade em testes:
const TimestampSchema = z.union([
  z.custom<Timestamp>((val) => val && 'toDate' in val),
  z.date(),
  z.null(),
])

Type Inference Pattern

// src/lib/schemas/podcast.ts
export const PodcastSchema = z.object({
  id: z.string(),
  name: z.string().min(1),
  // ...
})

// src/types/podcast.ts
import { z } from 'zod'
import { PodcastSchema, PodcastCreateSchema, PodcastUpdateSchema } from '@/lib/schemas/podcast'

export type Podcast = z.infer<typeof PodcastSchema>
export type PodcastCreate = z.infer<typeof PodcastCreateSchema>
export type PodcastUpdate = z.infer<typeof PodcastUpdateSchema>

VideoTypeConfig Duracao em Segundos

Duracoes sao armazenadas em segundos:

  • 20 minutos = 1200 segundos
  • 3 minutos = 180 segundos
  • 179 segundos = 2:59 (< 3 min)
  • 1199 segundos = 19:59 (< 20 min)

Enforcement Rules Aplicaveis

  1. Rule #2 (Zod Validation): Validar com Zod todo dado antes de persistir
  2. Rule #6 (kebab-case files): Arquivos em kebab-case (podcast.ts, video-type-config.ts)
  3. Rule #11 (import type): Usar import type para imports que sao apenas type annotation
