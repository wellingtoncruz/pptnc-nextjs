Story 13.1: Spike — PoC do @google/genai com Vertex AI backend

Status: ready-for-dev

Story

Como tech lead do IAra, Eu quero validar que o SDK @google/genai funciona com Vertex AI backend em todos os padrões que o IAra utiliza, Para que possamos migrar do @google-cloud/vertexai (deprecated, remoção Jun 2026) com confiança.

Contexto

Situação Atual

  • O IAra usa @google-cloud/vertexai@^1.10.0 em 2 arquivos de produção:
    • src/lib/llm/client.ts — Singleton VertexAI, getGenerativeModel, generateContentStream, inlineData, systemInstruction, thinkingConfig
    • src/app/api/wizard/phase/5b/route.ts — Duplica init do VertexAI, generateContent (unário), inlineData
  • Mocks em 2 arquivos de teste: llm.test.ts (indireto) e route.test.ts (direto)
  • O SDK deprecated será removido em Jun 2026

SDK Novo — @google/genai

  • Substituto oficial do Google (suporta Gemini API e Vertex AI)
  • Inicialização: new GoogleGenAI({ vertexai: true, project, location })
  • API unificada: ai.models.generateContent(...) e ai.models.generateContentStream(...)
  • Respostas simplificadas: response.text ao invés de response.candidates[0].content.parts[0].text
  • systemInstruction vai em config ao invés de nos contents
  • thinkingConfig vai em config (campo tipado, sem workaround as Record<string, unknown>)
  • ai.files.upload(...) para Files API (bônus — Story 13.5)

Acceptance Criteria

AC1: Script PoC executa com sucesso

Given o SDK @google/genai instalado no projeto When o script PoC é executado com tsx scripts/spike-genai-poc.ts Then ele completa sem erros e imprime os resultados de cada validação

AC2: Streaming funciona com thinkingConfig

Given o SDK configurado com vertexai: true e ADC When generateContentStream é chamado com thinkingConfig: { thinkingBudget: 24576 } Then o stream retorna chunks iteráveis e a resposta final contém texto válido

AC3: Attachment inlineData funciona

Given uma transcrição codificada em base64 When enviada como inlineData com mimeType: 'text/plain' Then o modelo processa o conteúdo e retorna resposta válida

AC4: systemInstruction funciona

Given um system prompt definido When passado via config: { systemInstruction } na chamada Then o modelo respeita o system prompt na resposta

AC5: Response parsing é compatível

Given uma chamada bem-sucedida When a resposta é recebida Then response.text retorna o texto gerado And response.usageMetadata contém promptTokenCount, candidatesTokenCount, totalTokenCount

AC6: Unary call funciona

Given uma chamada unária (não-streaming) When generateContent é chamado Then a resposta contém texto e usage metadata

AC7: JSON responseMimeType funciona

Given responseMimeType: 'application/json' na config When o modelo gera uma resposta Then o texto retornado é JSON parseável

AC8: Documento de decisão

Given o spike completo When os resultados são compilados Then um documento resume: GO/NO-GO, diferenças de API encontradas, workarounds necessários, e status do suporte a ai.files

Dev Notes

Execução do Script

cd apps/iara
npx tsx scripts/spike-genai-poc.ts

Requer ADC configurado:

gcloud auth application-default login

Estrutura esperada do script

import { GoogleGenAI } from '@google/genai'

const ai = new GoogleGenAI({
  vertexai: true,
  project: 'pptnc-stage',
  location: 'us-east1',
})

// Validação 1: Unary + JSON + thinkingConfig
const response = await ai.models.generateContent({
  model: 'gemini-2.5-flash',
  contents: 'Retorne um JSON com { "status": "ok" }',
  config: {
    responseMimeType: 'application/json',
    maxOutputTokens: 65536,
    temperature: 0.7,
    thinkingConfig: { thinkingBudget: 24576 },
    systemInstruction: 'Você é um assistente de testes.',
  },
})

console.log('Text:', response.text)
console.log('Usage:', response.usageMetadata)

Diferenças-chave já conhecidas (da documentação oficial)

  1. Model não é singleton — passado por chamada, não por getGenerativeModel()
  2. systemInstruction simplificado — string direta em config, não { role: 'system', parts: [{ text }] }
  3. Response flattened — response.text ao invés de response.candidates[0].content.parts[0].text
  4. thinkingConfig tipado — sem necessidade de as Record<string, unknown>
  5. Streaming — for await (const chunk of response) com chunk.text
  6. Config object — generationConfig vira config com campos diretos

Riscos a verificar

  • undici workaround: O SDK antigo usa fetch do Node que tem timeout de 5min. O novo SDK pode ter HTTP client próprio.
  • usageMetadata field names: Confirmar se são idênticos ou se mudaram (ex: candidatesTokenCount → outputTokenCount?)
  • ai.files via Vertex AI: O Spike 5.5 anterior concluiu que o Vertex AI SDK antigo NÃO suportava Files API. O novo SDK pode suportar.
  • finishReason format: Confirmar se mantém o mesmo enum (STOP, MAX_TOKENS, etc.)

Timebox

2-4h. Se encontrar problemas não-triviais, documentar e reavaliar.
