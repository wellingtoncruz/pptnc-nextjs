Story 13.10: Fix transição draft→ready na Fase 8 para cuts/reels

Status: review

Story

Como um produtor de podcast, Eu quero que ao completar todas as fases do wizard para cortes e reels, o vídeo transite automaticamente para status "ready" ao chegar na Fase 8, Para que eu possa publicar o vídeo no YouTube sem precisar navegar para outro vídeo e voltar.

Contexto

Fluxo Atual (Bug)

  1. Produtor abre um vídeo tipo cut com status new
  2. Segue o fluxo: Fase 0 → 5 → 5B → 6 → 7 → "Avançar" → Fase 8
  3. Na Fase 8, botão "Enviar para o YouTube" está desabilitado
  4. Erro ao tentar enviar: "Video com status 'draft' não pode ser enviado"
  5. Workaround: Navegar para outro vídeo e voltar → status corrige para "ready"

Causa Raiz

O estado local (videoData.status) fica dessincronizado com o Firestore.

O servidor (AUTO-DRAFT em videos-admin.ts:449-458) transiciona new → draft silenciosamente quando qualquer fase salva dados no Firestore. Porém as respostas das APIs de fase não retornam o status atualizado, então o videoData.status no React permanece 'new'.

Quando currentPhase chega em 8, o efeito AUTO-READY verifica:

if (videoData.status !== 'draft') return  // ← 'new' !== 'draft' → true → RETURN EARLY!

O guard falha porque o estado local é 'new', mesmo que o Firestore já tenha 'draft'. A transição para 'ready' nunca acontece.

A mensagem de erro "Video com status 'draft' não pode ser enviado" vem da rota YouTube API (/api/youtube/videos/[videoId]/route.ts:87) que lê o status diretamente do Firestore (onde é 'draft'), não do estado local.

Por que funciona ao navegar para outro vídeo e voltar

Ao retornar, fetchFreshVideoData() busca dados frescos do Firestore (onde status já é 'draft'), o videoData é atualizado com o status correto, e o efeito AUTO-READY dispara normalmente.

Acceptance Criteria

AC1: Transição automática para ready ao chegar na Fase 8

Given um vídeo tipo cut ou reel com status new no Firestore When o produtor completa todas as fases e o wizard chega na Fase 8 Then o status do vídeo é atualizado para ready no Firestore e no estado local And o botão "Enviar para o YouTube" fica habilitado

AC2: Compatibilidade com vídeos já em draft

Given um vídeo tipo cut ou reel que já está com status draft no Firestore When o wizard chega na Fase 8 Then o status do vídeo é atualizado para ready (comportamento existente preservado)

AC3: Não afetar vídeos em outros estados

Given um vídeo com status ready, sending ou sent When o wizard está na Fase 8 Then o status não é alterado

AC4: Compatibilidade com episódios

Given um vídeo tipo episode com status new When o produtor completa todas as fases 1-7 e chega na Fase 8 Then o status transita para ready (mesmo fix se aplica a episódios)

Tasks / Subtasks

  • Task 1: Adicionar efeito CLIENT-SIDE AUTO-DRAFT (AC: 1, 2, 3, 4)

    • 1.1 Novo useEffect que espelha o comportamento do servidor: quando o wizard avança além da primeira fase, transiciona videoData.status de 'new' para 'draft' localmente
    • 1.2 Manter o guard original do AUTO-READY (videoData.status !== 'draft') inalterado
    • 1.3 AUTO-READY continua funcionando: agora recebe 'draft' corretamente → PATCH { status: 'ready' } → sucesso

  • Task 2: Adicionar testes (AC: 1, 2, 3, 4)

    • 2.1 Teste: cut phase 7 → phase 8 via COMPLETE_PHASE_AND_ADVANCE (machine.test.ts)
    • 2.2 Teste: reel phase 7 → phase 8 via COMPLETE_PHASE_AND_ADVANCE (machine.test.ts)
    • 2.3 Teste: fluxo completo de cut (0→5→5B→6→7→8) atinge phase 8
    • 2.4 Teste: fluxo completo de reel (0→5→6→7→8) atinge phase 8

  • Task 3: Validação manual (AC: 1)

    • 3.1 Testar fluxo completo com vídeo cut (0 → 5 → 5B → 6 → 7 → 8 → Publicar)
    • 3.2 Testar fluxo completo com vídeo reel (0 → 5 → 6 → 7 → 8 → Publicar)

Dev Notes

Diagnóstico Detalhado

Caminho do bug:

  1. videos-admin.ts:449-458 — AUTO-DRAFT: quando qualquer fase salva dados no Firestore, o status muda new → draft no servidor
  2. As APIs de fase (PUT /api/videos/{id}/title, etc.) não retornam o status atualizado
  3. videoData.status permanece 'new' no estado React
  4. Quando Phase 7 chama completePhaseAndAdvance(7, { tags }), o reducer seta currentPhase = 8
  5. O efeito AUTO-READY dispara, verifica videoData.status !== 'draft' → 'new' !== 'draft' → true → return early
  6. O vídeo fica em 'draft' no Firestore sem nunca chegar a 'ready'
  7. Ao tentar publicar, YouTube API lê 'draft' do Firestore → canTransition('draft', 'send') → false → erro

Solução implementada: CLIENT-SIDE AUTO-DRAFT

// wizard-orchestrator.tsx — NOVO efeito ANTES do AUTO-READY
useEffect(() => {
  if (videoData.status !== 'new') return
  if (videoDataReadyFor !== video.id) return

  // First phase: episode starts at 1, cut/reel start at 0
  const firstPhase = video.videoType === 'episode' ? 1 : 0

  // If wizard has advanced past the first phase, data was saved → server did AUTO-DRAFT
  if (wizard.currentPhase === firstPhase) return

  setVideoData(prev => prev.status === 'new' ? { ...prev, status: 'draft' } : prev)
}, [wizard.currentPhase, videoData.status, videoDataReadyFor, video.id, video.videoType])

Fluxo corrigido (cut com status 'new'):

  1. Mount → fetchFreshVideoData() → videoData.status = 'new'
  2. TranscriptionLoader → videoDataReadyFor = video.id
  3. Phase 0 completa → currentPhase = 5
  4. CLIENT-SIDE AUTO-DRAFT: status === 'new', 5 !== 0 → setVideoData({ status: 'draft' })
  5. Re-render: videoData.status = 'draft'
  6. User continua: Phase 5 → 5B → 6 → 7
  7. Phase 7 completa → currentPhase = 8
  8. AUTO-READY: status === 'draft' → guard passa → PATCH { status: 'ready' } → sucesso

Alternativa considerada e descartada

Alterar o guard do AUTO-READY para aceitar 'new' além de 'draft'. Descartada porque:

  • É uma gambiarra que mascara o problema real (estado local dessincronizado)
  • Viola o princípio de que o AUTO-READY só deve atuar sobre vídeos em 'draft'
  • Envia PATCH { status: 'ready' } para vídeos com status 'new' no Firestore, o que é semanticamente incorreto
