Story 13.3: Refatorar Phase 5B route — eliminar SDK duplicado

Status: done

Story

Como tech lead do IAra, Eu quero refatorar a route phase/5b/route.ts para usar a infraestrutura compartilhada do client.ts, Para que a dependência do SDK @google-cloud/vertexai seja eliminada da route e o código LLM fique centralizado.

Contexto

Situação Atual

  • src/app/api/wizard/phase/5b/route.ts é a ÚNICA route que importa @google-cloud/vertexai diretamente
  • Duplica init do SDK: new VertexAI({ project, location }) + getGenerativeModel()
  • Duplica readFileAsBase64() (já existe em client.ts)
  • Usa model.generateContent() (unary, não streaming) — sem retry automático
  • Implementa timeout via Promise.race manual
  • Phase 5B é exclusiva para vídeos do tipo cut — gera shortTitles para thumbnails
  • Prompt building usa podcast.prompt.cut.thumbs (lógica específica, não genérica)

Abordagem

Exportar callGenAI do client.ts como função de baixo nível. A route 5B mantém sua própria lógica de prompt building (é específica de cut/thumbs) mas delega a chamada LLM para callGenAI, que já oferece:

  • Streaming (mantém conexão ativa durante thinking)
  • Retry automático para PARSE_ERROR (3 tentativas)
  • thinkingConfig tipado
  • Extração de usage metadata
  • Logging de diagnóstico

Isso elimina:

  • Import de @google-cloud/vertexai na route
  • Função getModel() duplicada
  • Função readFileAsBase64() duplicada
  • Timeout manual via Promise.race
  • Constantes DEFAULT_MODEL, PHASE_5B_TIMEOUT duplicadas

Arquivos Envolvidos

Arquivo Mudança
src/lib/llm/client.ts Minor — Exportar callGenAI
src/lib/llm/index.ts Minor — Re-exportar callGenAI
src/app/api/wizard/phase/5b/route.ts Major — Refatorar para usar callGenAI

NOTA: Testes NÃO são modificados nesta story (será Story 13.4).

Acceptance Criteria

AC1: SDK deprecated removido da route

Given o arquivo route.ts de Phase 5B When o dev revisa os imports Then não existe nenhum import de @google-cloud/vertexai And não existe VertexAI, GenerativeModel, nem Part no arquivo And não existe getModel() nem readFileAsBase64() no arquivo

AC2: callGenAI exportado e usado

Given a function callGenAI em client.ts When a route 5B faz uma chamada LLM Then usa callGenAI<Phase5BResponse>(systemPrompt, userPrompt, timeout, attachmentPath) And callGenAI é exportado de client.ts e re-exportado em index.ts

AC3: Prompt building preservado

Given a lógica de prompt de Phase 5B When um cut video é processado Then buildPhase5BPrompt() continua construindo o system prompt usando podcast.prompt.cut.thumbs And o fallback BASE_SYSTEM_PROMPT_5B continua funcionando quando podcast não está configurado And additionalContext continua sendo adicionado ao system prompt

AC4: Streaming e retry automáticos

Given uma chamada LLM via Phase 5B When o modelo processa com streaming Then usa streaming (via callGenAI) ao invés de unary generateContent And retry automático para PARSE_ERROR funciona (3 tentativas) And o timeout manual via Promise.race é removido

AC5: Response e persistência preservados

Given uma resposta bem-sucedida do LLM When os short titles são gerados Then data.shortTitles é validado como array And suggestedShortTitles é persistido no Firestore via updateVideoAdmin And a response JSON tem o mesmo formato: { data, usage }

AC6: Error handling preservado

Given um erro durante processamento When a route trata o erro Then erros de validação (Zod) retornam 400 And erros LLM retornam 500 (ou 429 para RATE_LIMIT) And o formato da response de erro é preservado: { error: { code, message, retryable? } }

AC7: API pública preservada

Given o frontend chamando POST /api/wizard/phase/5b When o request é enviado com { videoId, additionalContext? } Then o contrato de request e response é idêntico ao anterior And nenhuma mudança é necessária no frontend

AC8: Build passa

Given a refatoração completa When tsc --noEmit roda no escopo de apps/iara Then compila sem novos erros de tipo

Antes (route 5B):

import { GenerativeModel, VertexAI } from '@google-cloud/vertexai'
import type { Part } from '@google-cloud/vertexai'

// Duplicated SDK init
function getModel(): GenerativeModel {
  const vertexAI = new VertexAI({ project: PROJECT_ID, location: GCP_REGION })
  return vertexAI.getGenerativeModel({ model, generationConfig })
}

// Duplicated file reading
async function readFileAsBase64(filePath: string): Promise<string> { ... }

// Unary call + manual timeout
const result = await Promise.race([
  model.generateContent({ contents, systemInstruction }),
  timeoutPromise,
])
const text = response.candidates?.[0]?.content?.parts?.[0]?.text

Depois (route 5B):

import { callGenAI, createTranscriptionFile, cleanupTranscriptionFile } from '@/lib/llm'

// Shared infrastructure — streaming, retry, parsing
const transcriptionFilePath = await createTranscriptionFile(transcription, 5)
try {
  const { data, usage } = await callGenAI<Phase5BResponse>(
    systemPrompt,
    userPrompt,
    120000,
    transcriptionFilePath
  )
  // validate + persist + return
} finally {
  await cleanupTranscriptionFile(transcriptionFilePath)
}

callGenAI já faz:

  1. Streaming com chunks (keep-alive durante thinking)
  2. Retry automático para PARSE_ERROR (3 tentativas)
  3. thinkingConfig com budget 24576
  4. Extração de usage metadata
  5. Logging diagnóstico completo
  6. Parsing JSON robusto (via parseJSONFromLLM)

O que a route 5B MANTÉM:

  • buildPhase5BPrompt() — lógica específica de cut/thumbs
  • BASE_SYSTEM_PROMPT_5B — fallback prompt
  • Validação de videoType === 'cut'
  • Validação de transcription
  • Persistência de suggestedShortTitles
