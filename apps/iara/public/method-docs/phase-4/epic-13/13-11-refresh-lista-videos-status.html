Story 13.11: Refresh da lista de vídeos ao alterar status

Status: ready-for-dev

Story

Como um produtor de podcast, Eu quero que a lista de vídeos (coluna esquerda) atualize automaticamente quando o status de um vídeo muda no wizard, Para que eu veja o estado correto de cada vídeo sem precisar recarregar a página.

Contexto

Fluxo Atual (Bug)

  1. Produtor seleciona um vídeo e completa todas as fases do wizard
  2. Na Fase 8, status transiciona draft → ready (via AUTO-READY)
  3. A lista de vídeos à esquerda não atualiza — continua mostrando "draft"
  4. Ao clicar "Enviar para o YouTube", status transiciona ready → sent
  5. A lista continua sem atualizar — mostra "ready" ou "draft"
  6. Somente ao recarregar a página ou trocar filtros a lista reflete o estado correto

Padrão Correto Existente

O ReopenVideoDialog já implementa o padrão correto:

  1. Dialog chama onSuccess(videoId) após reopen bem-sucedido
  2. VideoListPanel.handleReopenSuccess() chama onVideoReopened?.()
  3. onVideoReopened está bindado a refresh() do useVideos() no VideosLayout
  4. refresh() re-fetcha /api/videos → lista atualiza

Causa Raiz

O WizardOrchestrator não recebe callback para notificar o layout de mudanças de status. As transições acontecem internamente:

  • AUTO-READY: setVideoData({ status: 'ready' }) — atualiza estado local apenas
  • handleSendToYouTube: setVideoData({ status: 'sent' }) — atualiza estado local apenas

Nenhuma dessas transições notifica VideosLayout para chamar refresh().

Cadeia de Componentes

VideosLayout (tem refresh() via useVideos)
  ├── VideoListPanel ← recebe onVideoReopened=refresh ✓
  │     └── ReopenVideoDialog ← chama onSuccess → refresh() ✓
  └── VideoDetailPanel ← NÃO recebe callback ❌
        └── WizardOrchestrator ← NÃO recebe callback ❌

Acceptance Criteria

AC1: Refresh ao transicionar para ready (AUTO-READY)

Given um vídeo selecionado no wizard com status draft When o wizard chega na Fase 8 e AUTO-READY transiciona para ready Then a lista de vídeos à esquerda é atualizada e mostra o status ready

AC2: Refresh ao enviar para YouTube (sent)

Given um vídeo na Fase 8 com status ready When o produtor clica "Enviar para o YouTube" e o envio é bem-sucedido Then a lista de vídeos à esquerda é atualizada e mostra o status sent

AC3: Não afetar transições que falham

Given um vídeo na Fase 8 When o envio para o YouTube falha Then a lista de vídeos não é atualizada (evita refresh desnecessário)

AC4: Compatibilidade com reopen existente

Given o padrão existente de refresh via onVideoReopened When a nova callback é adicionada Then o comportamento de reopen continua funcionando normalmente

Tasks / Subtasks

  • Task 1: Threading do callback pelo component tree (AC: 1, 2, 3, 4)

    • 1.1 Adicionar prop onVideoStatusChange?: () => void em WizardOrchestratorProps
    • 1.2 Adicionar prop onVideoStatusChange?: () => void em VideoDetailPanelProps
    • 1.3 VideoDetailPanel repassa onVideoStatusChange para WizardOrchestrator
    • 1.4 VideosLayout passa refresh como onVideoStatusChange para VideoDetailPanel

  • Task 2: Chamar callback nas transições de status (AC: 1, 2, 3)

    • 2.1 No efeito AUTO-READY: chamar onVideoStatusChange?.() após PATCH bem-sucedido
    • 2.2 Em handleSendToYouTube: chamar onVideoStatusChange?.() após status atualizado para sent
    • 2.3 NÃO chamar em caso de erro/falha

  • Task 3: Validação manual (AC: 1, 2, 3)

    • 3.1 Verificar que ao completar fases e chegar na 8, a lista atualiza para "ready"
    • 3.2 Verificar que ao enviar para YouTube, a lista atualiza para "sent"
    • 3.3 Verificar que ao falhar o envio, a lista NÃO é atualizada

Dev Notes

Implementação

Mudanças nos 3 arquivos (props threading):

// 1. wizard-orchestrator.tsx — adicionar prop
interface WizardOrchestratorProps {
  video: Video
  className?: string
  onVideoStatusChange?: () => void  // NEW
}

// 2. video-detail-panel.tsx — adicionar prop e repassar
interface VideoDetailPanelProps {
  videoId?: string | null
  video?: VideoDetail | VideoSummary | null
  onVideoStatusChange?: () => void  // NEW
}
// Em VideoDetailPanel: <WizardOrchestrator ... onVideoStatusChange={onVideoStatusChange} />

// 3. videos-layout.tsx — passar refresh
<VideoDetailPanel
  videoId={selectedVideoId}
  video={selectedVideo}
  onVideoStatusChange={refresh}  // NEW
/>

Mudanças no WizardOrchestrator (chamar callback):

// AUTO-READY — após PATCH bem-sucedido (~linha 688)
.then((response) => {
  if (response.ok) {
    setVideoData((prev) => ({ ...prev, status: 'ready' }))
    onVideoStatusChange?.()  // ← NEW: refresh lista
    log('INFO', 'Video status updated to ready', { videoId: video.id })
  }
})

// handleSendToYouTube — após status 'sent' (~linha 2270)
setVideoData(prev => ({ ...prev, status: 'sent' }))
onVideoStatusChange?.()  // ← NEW: refresh lista

Por que NÃO usar AUTO-DRAFT (new→draft) como trigger

A transição new → draft é uma operação de sincronização de estado local (CLIENT-SIDE AUTO-DRAFT). Não há PATCH envolvido — o servidor já fez a transição silenciosamente. Chamar refresh() aqui seria redundante pois o servidor já tem 'draft'. A lista eventualmente mostrará o status correto quando o usuário trocar de filtro/página.
