Epic 13: Hardening v2.2.0 — SDK, Neutralidade, Correções e Onboarding

Status: backlog

Objetivo

Preparar o IAra para ser deployável como white-label para qualquer podcast, migrando o SDK deprecated do Vertex AI, eliminando hardcodes de tenant, corrigindo bugs do wizard e melhorando configurações, e documentando o processo de onboarding completo para novos podcasts.

Contexto

Quatro necessidades convergem neste epic:

  1. SDK Deprecated: O @google-cloud/vertexai foi deprecated em Jun 2025 com remoção prevista para Jun 2026. O substituto oficial @google/genai suporta Vertex AI + Files API (ai.files).

  2. Neutralidade de Tenant: O PODCAST_ID está hardcoded em src/lib/firebase/config.ts e importado em 29+ API routes. Para deploys white-label, precisa ser externalizado como env var de runtime.

  3. Correções e Melhorias: Bugs no wizard (estado draft→ready para cuts/reels), lista de vídeos com status desatualizado, e melhorias na área de configurações (host name, feature toggles).

  4. Onboarding: Não existe documentação de como instalar e configurar o IAra para um novo podcast. O processo de seed, configuração de prompts, OAuth e deploy precisa ser documentado passo-a-passo.

Escopo

Incluído nesta Epic

  • Migração completa de @google-cloud/vertexai para @google/genai
  • Spike de validação do novo SDK (streaming, thinkingConfig, Files API)
  • Refatoração da Phase 5B route para usar callLLM compartilhado
  • Externalização de PODCAST_ID como env var de runtime
  • Externalização de PROJECT_ID, GCP_REGION, FIRESTORE_DATABASE_ID como env vars
  • Parametrização do cloudbuild.yaml para deploy multi-pod
  • Parametrização do seed-podcast.ts para aceitar argumentos
  • Assertion de startup validando env vars obrigatórias
  • Fix: transição draft→ready na Fase 8 para cuts/reels
  • Fix: refresh da lista de vídeos ao alterar status
  • Feature: campo "nome do host" nas configurações + inclusão nos prompts
  • Feature: seção "Features" para habilitar/desabilitar menus opcionais
  • Documentação step-by-step de onboarding em PT-BR
  • Implementação de ai.files para reutilização de transcrição (bônus, se spike positivo)
  • Remoção do pacote @google-cloud/vertexai do package.json

Fora de Escopo (Futuras Epics)

  • Multi-tenancy dinâmico (subdomain-based routing, single service)
  • Self-service onboarding (SaaS)
  • Billing por tenant
  • Dashboard administrativo multi-tenant
  • Portal-web (apps/web) multi-pod
  • Firestore Security Rules para isolamento cross-tenant

Decisões Técnicas

Decisão Escolha Justificativa
Approach multi-pod White-label (1 deploy = 1 pod) Simplicidade, sem routing complexo, mesma imagem Docker
PODCAST_ID Env var runtime (process.env) Mesma imagem Docker serve qualquer pod, sem rebuild
PROJECT_ID e outros Env vars com fallback hardcoded Backward-compatible, não quebra deploys existentes
SDK destino @google/genai v1.41.0+ Substituto oficial, suporta Vertex AI + Files API
Phase 5B Refatorar para usar callLLM Elimina duplicação de init do SDK
Files API Implementar se spike positivo Bônus: reutilização de transcrição entre fases
Documentação Markdown PT-BR no repo Acessível ao produtor, versionada com o código
AUTH_SECRET Único por deploy Segurança: sessões não vazam entre pods
Startup validation Assert em config.ts Fail-fast se env var obrigatória estiver faltando
Refresh da lista Callback de refresh do layout Padrão já usado no reopen-video-dialog
Feature toggles Campo features no documento podcast Persistido no Firestore, verificado no sidebar e middleware
Versão alvo v2.2.0-beta-iara (minor) Não é major — sem breaking changes na API ou dados

Story 13.10: Fix transição draft→ready na Fase 8 para cuts/reels

Bug: Ao completar o fluxo do wizard para cuts/reels, o vídeo permanece em status "draft" na Fase 8, impedindo "Enviar para o YouTube". Só funciona se navegar para outro vídeo e voltar.

Causa raiz: O efeito AUTO-READY em wizard-orchestrator.tsx (linhas 611-669) verifica wizard.currentPhase !== 8, mas para cuts/reels o currentPhase pode não estar sincronizado com 8 durante o fluxo normal. A lógica de hydration em machine.ts calcula firstIncompletePhase = 8 corretamente, mas o currentPhase não é atualizado quando currentPhase === firstIncompletePhase (a comparação 8 > 8 é false).

Arquivos:

  • src/components/wizard/wizard-orchestrator.tsx — efeito AUTO-READY (~linha 611)
  • src/lib/wizard/machine.ts — action HYDRATE_FROM_VIDEO_DATA (~linha 451)

Fix sugerido: Modificar o efeito AUTO-READY para verificar se todas as fases do videoType estão completadas, não apenas currentPhase === 8. Alternativa: garantir que currentPhase seja atualizado para 8 quando todos os phases estão completos no HYDRATE.

Esforço: 2-3h

Story 13.11: Refresh da lista de vídeos ao alterar status

Bug: A coluna de vídeos (esquerda) não atualiza quando o status de um vídeo muda (ex: draft→ready, ready→sent). O produtor vê estados desatualizados.

Causa raiz: O useVideos() hook usa fetch() manual sem auto-revalidation. O handleSendToYouTube no wizard-orchestrator atualiza o Firestore e o estado local, mas não notifica o videos-layout.tsx para chamar refresh(). O padrão correto já existe no reopen-video-dialog.tsx que chama onSuccess() → refresh().

Arquivos:

  • src/components/wizard/wizard-orchestrator.tsx — handleSendToYouTube (~linha 2142)
  • src/app/videos/videos-layout.tsx — refresh() do useVideos()
  • src/hooks/use-videos.ts — hook de fetch

Fix sugerido: Propagar callback onVideoStatusChanged do layout para o wizard-orchestrator. Chamar refresh() quando:

  1. Vídeo é enviado para o YouTube (sent)
  2. Status transiciona para "ready" (auto-ready)
  3. Qualquer PATCH em /api/videos/[videoId] que altere status

Esforço: 2-3h

**Host:** ${podcast.hostName || 'Não informado'}
**Convidados:** ${video.guests?.map(...)}

Esforço: 2-3h

Story 13.13: Configurações — seção Features (toggle de menus opcionais)

Feature: Nova seção "Recursos" (Features) nas configurações onde o admin pode habilitar/desabilitar entradas de menu opcionais. Menus opcionais: Editorial e Notícias.

Comportamento:

  • Por padrão, features começam habilitadas
  • Desabilitar uma feature: remove do menu lateral e restringe a rota (retorna 404 ou redirect)
  • Persistido no documento podcast no Firestore

Arquivos:

  • src/lib/schemas/podcast.ts — adicionar:
    features: z.object({
  editorial: z.boolean().default(true),
  news: z.boolean().default(true),
}).optional()
  • src/components/settings/settings-page-client.tsx — nova seção accordion "Recursos"
  • src/components/settings/features-settings-form.tsx — novo arquivo com toggles Switch
  • src/components/layout/sidebar.tsx — condicional: mostrar "Editorial" e "Notícias" apenas se habilitados
  • src/app/videos/videos-layout.tsx — verificar feature habilitada antes de renderizar EditorialPanel e NewsPanel

Schema no Firestore:

// podcasts/{podcastId}
{
  features: {
    editorial: true,   // default
    news: true,        // default
  }
}

Esforço: 3-4h
