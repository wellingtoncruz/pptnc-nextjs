Story 9.6: Botão Re-sync Completo

Status: done

Story

As a administrador do podcast, I want poder executar um re-sync completo dos vídeos do YouTube, so that eu possa atualizar metadados de vídeos existentes quando necessário (títulos, descrições, thumbnails).

Acceptance Criteria

AC1: API POST /api/sync/full

DADO um admin autenticado
QUANDO eu chamar POST /api/sync/full
ENTÃO o sistema deve:
  - Buscar TODOS os vídeos do canal (não apenas novos)
  - Atualizar metadados de vídeos existentes (title, description, thumbnail)
  - NÃO alterar campos gerenciados pelo IAra (status, processedContent, etc.)
  - Retornar estatísticas: { total, updated, added, unchanged }

DADO um usuário não-admin
QUANDO ele chamar POST /api/sync/full
ENTÃO deve retornar 403 Forbidden

DADO que não há token OAuth válido
QUANDO admin chamar POST /api/sync/full
ENTÃO deve retornar 401 com mensagem clara sobre reconexão

AC2: Componente ResyncSection na página de Configurações

DADO a página de Configurações aberta
QUANDO eu visualizar a seção "Sincronização"
ENTÃO deve haver um Card com:
  - Título "Re-sincronização Completa"
  - Descrição explicando o que faz e o custo de quota
  - Botão "Executar Re-sync Completo"
  - Badge ou texto indicando "Alta Quota"

AC3: Diálogo de confirmação antes do re-sync

DADO que cliquei em "Executar Re-sync Completo"
QUANDO a ação for disparada
ENTÃO deve abrir AlertDialog com:
  - Título: "Confirmar Re-sync Completo"
  - Descrição: Explicar que consome alta quota da API YouTube
  - Informar quantidade estimada de requisições (baseado em total de vídeos)
  - Botões: "Cancelar" e "Confirmar Re-sync"

DADO que o AlertDialog está aberto
QUANDO eu clicar em "Cancelar"
ENTÃO o diálogo deve fechar sem executar ação

AC4: Feedback visual durante e após re-sync

DADO que confirmei o re-sync
QUANDO a API estiver processando
ENTÃO o botão deve mostrar estado de loading (spinner + "Sincronizando...")
E os outros botões da página devem estar desabilitados

DADO que o re-sync terminou com sucesso
QUANDO a API retornar
ENTÃO deve mostrar Alert de sucesso com estatísticas:
  - "X vídeos atualizados"
  - "Y novos vídeos importados"
  - "Z vídeos sem alterações"

DADO que o re-sync falhou
QUANDO a API retornar erro
ENTÃO deve mostrar Alert de erro com a mensagem
E o botão deve voltar ao estado normal

AC5: Proteção contra execuções simultâneas

DADO que um re-sync está em andamento
QUANDO outro admin tentar iniciar re-sync
ENTÃO deve retornar 409 Conflict
E mensagem "Re-sync já em andamento, aguarde"

DADO que um re-sync terminou
QUANDO outro re-sync for solicitado
ENTÃO deve permitir normalmente

Dev Notes

DIFERENÇA CRÍTICA: SYNC vs FULL-SYNC

Aspecto Sync Regular (/api/sync) Full Sync (/api/sync/full)
Quando usar Buscar novos vídeos Atualizar metadados existentes
Quota Baixa (só IDs novos) Alta (todos os vídeos)
O que atualiza Adiciona novos Atualiza metadados de todos
Frequência Automática/frequente Manual/raro
Acesso Qualquer admin Apenas admin (com confirmação)

Campos que o FULL-SYNC pode atualizar (YouTube → Firestore)

Lock de Execução (Evitar Concorrência)

Usar documento no Firestore como lock:

// Path: podcasts/{podcastId}/locks/full-sync
interface SyncLock {
  inProgress: boolean
  startedAt: Timestamp
  startedBy: string // userId
}

// Antes de iniciar:
const lockRef = doc(db, `podcasts/${podcastId}/locks/full-sync`)
const lockDoc = await getDoc(lockRef)

if (lockDoc.exists() && lockDoc.data().inProgress) {
  const started = lockDoc.data().startedAt.toDate()
  const minutesAgo = (Date.now() - started.getTime()) / 60000

  // Timeout de 30 minutos (para locks órfãos)
  if (minutesAgo < 30) {
    throw new Error('Re-sync já em andamento')
  }
}

// Adquirir lock
await setDoc(lockRef, {
  inProgress: true,
  startedAt: serverTimestamp(),
  startedBy: userId,
})

try {
  // Executar full sync
} finally {
  // Liberar lock
  await setDoc(lockRef, { inProgress: false })
}

// - 4 calls para videos.list (200 / 50 = 4)
// - Total: ~5 quota units
