Story 9.5: Ações de Gestão de Usuários

Status: review

Story

As a administrador do podcast, I want poder promover, rebaixar e remover usuários, so that eu possa gerenciar quem tem acesso administrativo ao sistema.

Acceptance Criteria

AC1: API PUT /api/users/[userId]/role

DADO um admin autenticado
QUANDO eu chamar PUT /api/users/{userId}/role com body { role: 'admin' | 'user' }
ENTÃO o role do usuário deve ser atualizado
E deve retornar o usuário atualizado

DADO um admin tentando alterar seu próprio role
QUANDO eu chamar PUT /api/users/{meuId}/role
ENTÃO deve retornar 400 Bad Request
E mensagem "Não é possível alterar seu próprio role"

DADO apenas 1 admin no sistema
QUANDO eu tentar rebaixar esse admin para 'user'
ENTÃO deve retornar 400 Bad Request
E mensagem "Deve existir pelo menos um administrador"

DADO um usuário não-admin
QUANDO ele chamar PUT /api/users/[userId]/role
ENTÃO deve retornar 403 Forbidden

AC2: API DELETE /api/users/[userId]

DADO um admin autenticado
QUANDO eu chamar DELETE /api/users/{userId}
ENTÃO o usuário deve ser soft-deleted (deleted=true)
E deve retornar 200 com { success: true }

DADO um admin tentando se auto-remover
QUANDO eu chamar DELETE /api/users/{meuId}
ENTÃO deve retornar 400 Bad Request
E mensagem "Não é possível remover a si mesmo"

DADO apenas 1 admin no sistema
QUANDO eu tentar remover esse admin
ENTÃO deve retornar 400 Bad Request
E mensagem "Não é possível remover o único administrador"

DADO um usuário não-admin
QUANDO ele chamar DELETE /api/users/[userId]
ENTÃO deve retornar 403 Forbidden

AC3: Botões de ação no UserCard

DADO a lista de usuários renderizada
QUANDO eu visualizar um card de usuário que NÃO sou eu
ENTÃO deve haver um menu de ações (DropdownMenu ou IconButton)
COM opções:
  - "Promover a Admin" (se role='user')
  - "Rebaixar a Usuário" (se role='admin')
  - "Remover usuário"

DADO que sou o usuário atual (isCurrentUser=true)
QUANDO eu visualizar meu card
ENTÃO NÃO deve haver botões de ação

AC4: Diálogo de confirmação para ações destrutivas

DADO que cliquei em "Rebaixar a Usuário" ou "Remover usuário"
QUANDO a ação for disparada
ENTÃO deve abrir um AlertDialog de confirmação
COM título descritivo da ação
E botão "Cancelar" e "Confirmar"

DADO que cliquei em "Promover a Admin"
QUANDO a ação for disparada
ENTÃO pode executar diretamente (ou com confirmação simples)

AC5: Feedback visual das ações

DADO uma ação em andamento
QUANDO a API estiver sendo chamada
ENTÃO o botão deve mostrar estado de loading
E outros botões devem estar desabilitados

DADO uma ação bem-sucedida
QUANDO a API retornar sucesso
ENTÃO a lista deve ser atualizada (mutate SWR)
E deve mostrar toast de sucesso

DADO uma ação com erro
QUANDO a API retornar erro
ENTÃO deve mostrar toast de erro com a mensagem

Dev Notes

REGRAS DE NEGÓCIO CRÍTICAS

  1. Admin NÃO pode alterar seu próprio role - Previne lock-out acidental
  2. Admin NÃO pode se auto-remover - Previne perda de acesso
  3. Deve existir pelo menos 1 admin - Sistema nunca fica sem administrador
  4. Soft-delete - Usuários removidos podem ser reativados no próximo login
