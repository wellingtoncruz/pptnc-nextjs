Story 4.4: Fase 2 - Checagem de Edição (Tipo 2)

Status: done

Story

As a produtor, I want verificar se há falhas de edição perceptíveis no vídeo, so that posso corrigir antes de publicar.

Acceptance Criteria

  1. AC1: Processamento Automático ao Entrar na Fase

    • Given o Wizard na Fase 2
    • When a fase inicia
    • Then processamento LLM é iniciado automaticamente
    • And Área de Interatividade mostra loading state

  2. AC2: Exibição de Falhas Identificadas

    • Given falhas de edição identificadas pelo LLM
    • When renderizadas na Área de Interatividade
    • Then cada falha mostra:
      • Timestamp clicável (formato MM:SS ou HH:MM:SS)
      • Descrição da falha
    • And clicar no timestamp faz seek no player in-page para o ponto exato (UX improvement: não abre nova aba)

  3. AC3: Exibição de Sucesso (Sem Falhas)

    • Given nenhuma falha identificada pelo LLM
    • When renderizado
    • Then mostra Card de sucesso: "Parabéns, não há falhas de edição que eu possa identificar."

  4. AC4: Console Area com Feedback

    • Given o processamento LLM em andamento
    • When a fase está processando
    • Then Console Area mostra:
      • Spinner: "Verificando se existem falhas de edição perceptíveis..."
    • And após retorno mostra Alert:
      • Título: "Checagem de Edição"
      • Texto: "Verifique acima se existem trechos que você deveria verificar. Obs: Nada substitui a revisão humana, ok?"

  5. AC5: Persistência no Firestore

    • Given o retorno do LLM com sucesso
    • When os dados são persistidos
    • Then campo editingIssues é salvo na raiz do objeto video
    • And estrutura: Array<{ timestamp: string, description: string }>

  6. AC6: Critérios de Avanço com Confirmação

    • Given os critérios de avanço da Fase 2
    • When o botão "Avançar" é clicado
    • Then valida:
      • Retorno do LLM com sucesso ✓
      • Campo editingIssues persistido ✓
    • And se houver falhas: Alert Dialog "Tem certeza que deseja continuar?"
    • And se produtor confirmar "Sim", avança para Fase 3
    • And se "Não", permanece na Fase 2

  7. AC7: Comportamento Fase Tipo 2 (Imutável)

    • Given esta é uma fase Tipo 2 (Imutável)
    • When renderizada após completada
    • Then NÃO mostra input de override nem botão de reprocessar
    • And resultado é exibido em modo read-only

  8. AC8: Tratamento de Erros

    • Given a chamada LLM falha
    • When erro é recebido
    • Then Console Area mostra Alert de erro com mensagem amigável
    • And permite tentar novamente (botão retry habilitado)

Dev Notes

Architecture Patterns

  • Fase Tipo 2 (Imutável): Uma vez processada, não pode ser reprocessada. O componente deve detectar phases[2].status === 'completed' e renderizar em modo read-only.
  • Processamento Automático: Diferente da Fase 1, a Fase 2 inicia processamento automaticamente ao entrar, sem botão manual.
  • Console Pattern: Usar wizard.addSpinner() ao iniciar, wizard.removeSpinner() ao finalizar, wizard.addAlert() para resultado.
  • Confirmação de Avanço: Alert Dialog do shadcn/ui para confirmar continuação se houver falhas identificadas.

2. Timestamps - In-Page Player Control

Clickable timestamps should seek the in-page YouTube player, NOT open new tabs. This provides better UX as users stay on the same page.

Components involved:

  • youtube-context.tsx - Player state management (seekTo, registerStartPlayback)
  • youtube-embed.tsx - Embed with 800ms seekTo delay fix
  • video-preview.tsx - Integrates embed with context
  • clickable-timestamp.tsx - Calls youtube.seekTo(seconds)

3. Timestamps - Context Offset (30 seconds)

IMPORTANTE para revisores: Timestamps de críticas/problemas devem dar 30 segundos de contexto.

Ao clicar em um timestamp, o vídeo busca 30 segundos ANTES do momento marcado. Isso permite que o revisor ouça o contexto antes da crítica apontada pelo LLM.

// Em clickable-timestamp.tsx
export const TIMESTAMP_CONTEXT_OFFSET_SECONDS = 30

// Seek position = timestamp - 30s (mínimo 0)
const seekSeconds = applyContextOffset
  ? Math.max(0, seconds - TIMESTAMP_CONTEXT_OFFSET_SECONDS)
  : seconds

Uso:

  • Com offset (padrão): <ClickableTimestamp timestamp="05:30" /> → busca 05:00
  • Sem offset (capítulos): <ClickableTimestamp timestamp="05:30" applyContextOffset={false} /> → busca 05:30

Pattern: @pattern TIMESTAMP_CONTEXT_OFFSET

CRITICAL: The 800ms seekTo Fix

// In youtube-embed.tsx - onStateChange handler
if (event.data === 1) { // Video started playing
  if (pendingSeekRef.current !== undefined) {
    const seekTime = pendingSeekRef.current
    pendingSeekRef.current = undefined

    // Wait 800ms for YouTube to establish stable connection
    // Without this delay, seekTo to distant positions causes infinite buffering
    setTimeout(() => {
      playerRef.current.seekTo(seekTime, true)
    }, 800)
  }
}

Timestamp Parsing

// Converter timestamp string para segundos
function parseTimestampToSeconds(timestamp: string): number {
  const parts = timestamp.split(':').map(Number)
  if (parts.length === 2) {
    // MM:SS
    return parts[0] * 60 + parts[1]
  } else if (parts.length === 3) {
    // HH:MM:SS
    return parts[0] * 3600 + parts[1] * 60 + parts[2]
  }
  return 0
}

// Gerar URL do YouTube
function getYouTubeTimestampUrl(videoId: string, timestamp: string): string {
  const seconds = parseTimestampToSeconds(timestamp)
  return `https://youtu.be/${videoId}?t=${seconds}`
}
