Story 4.7: Fase 5 - Titulo (Tipo 1)

Status: done

Story

As a produtor, I want escolher o melhor titulo entre 5 sugestoes geradas pela IA, so that o video tenha um titulo otimizado para SEO e engajamento.

Acceptance Criteria

  1. AC1: Processamento Automatico ao Entrar na Fase

    • Given o Wizard na Fase 5
    • When a fase inicia
    • Then processamento LLM e iniciado automaticamente
    • And Area de Interatividade mostra loading state

  2. AC2: Exibicao de 5 Titulos para Selecao

    • Given titulos gerados pelo LLM
    • When renderizados na Area de Interatividade
    • Then mostra lista de 5 titulos como radio buttons
    • And produtor pode selecionar UM titulo
    • And selecao e salva com auto-save

  3. AC3: Input de Complemento de Prompt

    • Given a fase renderizada
    • When o produtor visualiza
    • Then ve input de texto para {additionalContext}
    • And input tem placeholder com dica de uso
    • And input tem maximo de 200 caracteres

  4. AC4: Botao Revalidar com Confirmacao

    • Given o botao "Revalidar" clicado
    • When com complemento de prompt preenchido
    • Then Alert Dialog solicita confirmacao
    • And mensagem informa que fases 6 e 7 serao marcadas para revalidacao
    • And se confirmado: nova chamada LLM com {additionalContext} no prompt
    • And fases 6 e 7 sao marcadas com needsRevalidation: true (dados preservados)

  5. AC5: Console Area com Feedback

    • Given o processamento LLM em andamento
    • When a fase esta processando
    • Then Console Area mostra:
      • Spinner: "Pensando em boas sugestoes de titulo..."
    • And apos retorno mostra Alert:
      • Titulo: "Titulos"
      • Texto: "Escolha o melhor titulo para o video, ou me de uma dica para eu poder ajudar melhor."

  6. AC6: Persistencia no Firestore

    • Given titulo selecionado pelo produtor
    • When salvo
    • Then campo title e persistido na raiz do objeto video
    • And dado e usado na Fase 6 para gerar descricao (SEO chain)

  7. AC7: Criterios de Avanco

    • Given os criterios de avanco da Fase 5
    • When o botao "Avancar" e clicado
    • Then valida:
      • Retorno do LLM com sucesso
      • Campo title persistido (titulo selecionado)
    • And se todos atendidos, avanca para Fase 6
    • And se algum faltar, botao permanece desabilitado

  8. AC8: Comportamento Fase Tipo 1 (Reprocessavel)

    • Given esta e uma fase Tipo 1 (Reprocessavel)
    • When renderizada
    • Then mostra input de additionalContext
    • And mostra botao "Revalidar"
    • And permite reprocessamento multiplo

  9. AC9: Tratamento de Erros

    • Given a chamada LLM falha
    • When erro e recebido
    • Then Console Area mostra Alert de erro com mensagem amigavel
    • And permite tentar novamente (botao retry habilitado)

  10. AC10: Exibicao com Dados Persistidos

    • Given titulo ja selecionado anteriormente (video.title existe)
    • When a fase e aberta
    • Then exibe os titulos da ultima geracao (se disponiveis)
    • Or processa novamente se nao houver cache
    • And titulo selecionado aparece marcado

Dev Notes

Architecture Patterns

  • Fase Tipo 1 (Reprocessavel): Pode ser reprocessada com additionalContext. O componente permite reprocessar com novo prompt.
  • Processamento Automatico: Igual as Fases 2-4, inicia processamento automaticamente ao entrar, sem botao manual.
  • Console Pattern: Usar wizard.addSpinner() ao iniciar, wizard.removeSpinner() ao finalizar, wizard.addAlert() para resultado.
  • SEO Chain: O titulo selecionado sera usado pela Fase 6 (Descricao) e Fase 7 (Tags).
  • needsRevalidation: Ao revalidar, fases seguintes sao marcadas mas dados NAO sao apagados.

Key Difference from Type 2 Phases

Phases 1-4 (Type 2 - Immutable):

  • No additionalContext input
  • No Revalidar button
  • Process once only

Phase 5 (Type 1 - Reprocessable):

  • Shows additionalContext input
  • Shows Revalidar button
  • Can reprocess multiple times
  • Revalidation marks subsequent phases (6, 7) with needsRevalidation

needsRevalidation Implementation

When user clicks "Revalidar" and confirms:

  1. Call LLM with additionalContext appended to prompt
  2. Mark phases 6 and 7 with needsRevalidation: true
  3. Do NOT clear data from phases 6 and 7 (preserve existing data)
  4. When user navigates to phase 6 or 7 with needsRevalidation:
    • Show option: "Manter dados existentes" or "Revalidar com LLM"
    • If keep: unmark needsRevalidation, advance
    • If revalidate: call LLM again
// In orchestrator, when revalidating phase 5:
const handleRevalidatePhase5 = async (additionalContext: string) => {
  // Mark subsequent phases for revalidation
  wizard.setPhaseStatus(6, 'pending') // or add needsRevalidation flag
  wizard.setPhaseStatus(7, 'pending')

  // Call LLM with additional context
  await processPhase5Titles(additionalContext)
}

Similarity with Phase 4 (but Type 1)

Phase 5 follows similar auto-processing pattern as Phase 4:

  • Processes automatically on phase entry
  • Shows loading state
  • Displays results
  • Has advance button

Differences:

  • Type 1: Shows additionalContext input and Revalidar button
  • Persists selected title, not just LLM result
  • Selection via radio buttons instead of just display
  • Revalidation marks subsequent phases
