Story 4.0b: Inputs de Contexto para Processamento

Status: done

Story

As a produtor de conteúdo, I want informar contexto adicional sobre o episódio antes do processamento de IA, so that a IA tenha informações relevantes sobre tema, co-host e convidados para gerar metadados de qualidade.

Acceptance Criteria

AC1: Formulário de Contexto para Episodes

  1. Given um vídeo do tipo episode selecionado para processamento When eu clico no botão "Processar" no painel de detalhes Then um modal/drawer abre solicitando inputs de contexto And vejo o formulário com os campos:

    • Tema geral do Episódio (textarea, obrigatório)
    • Seção Co-host (opcional, colapsável)
    • Seção Convidados (1-3 obrigatórios)

  2. Given o formulário de contexto aberto When eu visualizo a seção de Co-host Then vejo campos para:

    • Nome (text input)
    • Cargo (text input)
    • Empresa (text input)
    • LinkedIn URL (text input com validação de URL) And a seção é opcional (pode ficar vazia)

  3. Given o formulário de contexto aberto When eu visualizo a seção de Convidados Then vejo um convidado já expandido com campos:

    • Nome (obrigatório)
    • Cargo (obrigatório)
    • Empresa (obrigatório)
    • LinkedIn URL (obrigatório, validação de URL) And botão "Adicionar convidado" visível (máximo 3) And pelo menos 1 convidado é obrigatório

  4. Given tenho 1 convidado preenchido When clico em "Adicionar convidado" Then novo formulário de convidado aparece (até limite de 3) And cada convidado pode ser removido (exceto se for o último)

  5. Given formulário com campos obrigatórios não preenchidos When clico em "Iniciar Processamento" Then validação inline mostra erros nos campos faltantes And o processamento NÃO inicia

AC2: Seleção de Episode Origem para Cut/Reel

  1. Given um vídeo do tipo cut ou reel selecionado para processamento When eu clico no botão "Processar" Then um modal/drawer abre com seletor de "Episode Origem" And vejo dropdown com lista de episodes do mesmo podcast And apenas episodes com contexto definido (campo theme preenchido) aparecem And seleção é obrigatória

  2. Given o seletor de Episode Origem When eu seleciono um episode Then os dados do episode (tema, co-host, convidados) são exibidos como preview And esses dados serão herdados automaticamente

  3. Given nenhum episode com contexto disponível When eu tento processar um cut/reel Then mensagem informa: "Nenhum episódio com contexto disponível. Processe um episódio primeiro." And link para a lista de episodes é oferecido

AC3: Persistência de Contexto

  1. Given os inputs de contexto preenchidos corretamente When eu clico em "Iniciar Processamento" Then os dados são salvos no documento do vídeo em campos flat (theme, guests, parentEpisodeId) And o processamento SSE inicia (funcionalidade da próxima story)

  2. Given um episode com contexto já salvo (campo theme definido) When eu visualizo seus detalhes Then vejo badge/indicador "Contexto definido" And posso editar o contexto antes de reprocessar

  3. Given um cut/reel com parentEpisodeId When os dados são salvos Then o campo parentEpisodeId (root level) referencia o episode origem And os dados do episode NÃO são duplicados no cut/reel

AC4: Schema do Contexto (Legacy Compatible)

  1. Given o schema de Video no Firestore When contexto é salvo Then segue a estrutura flat (compatível com portal-web):
    // Root level fields (NOT nested in contextInputs)
theme?: string              // Tema do episódio
parentEpisodeId?: string    // Para cut/reel - referência ao episode
guests?: Array<{            // Legacy portal-web structure
  name: string              // Co-host when present is guests[0]
  role: string
  company: string
  linkedin: string          // Note: 'linkedin' not 'linkedinUrl'
  photo?: string
}>

Dev Notes

Decisões de Implementação

  • Modal vs Drawer: Usar Dialog do shadcn/ui para formulário de contexto (melhor UX para formulários complexos)
  • Validação: Usar react-hook-form + zod para validação do formulário
  • URL de LinkedIn: Validar formato básico de URL, não precisa validar se é LinkedIn real
  • Episode Origem: Buscar apenas episodes do mesmo podcastId que tenham contextInputs definido

Schema Zod (referência)

// Legacy-compatible guest schema (portal-web structure)
const GuestSchema = z.object({
  name: z.string().min(1, 'Nome é obrigatório'),
  role: z.string().min(1, 'Cargo é obrigatório'),
  company: z.string().min(1, 'Empresa é obrigatória'),
  linkedin: z.string().url('URL inválida'),  // Note: 'linkedin' not 'linkedinUrl'
  photo: z.string().optional(),
})

// UI form validation schema (not for persistence)
const EpisodeContextFormSchema = z.object({
  theme: z.string().min(1, 'Tema é obrigatório'),
  hasCoHost: z.boolean().default(false),
  coHost: GuestSchema.optional(),
  guests: z.array(GuestSchema).min(1, 'Pelo menos 1 convidado é obrigatório').max(3),
})

// On save, coHost is merged into guests[0] and saved flat:
// - theme: string (root level)
// - guests: Guest[] (root level, coHost as guests[0] if present)
// - parentEpisodeId: string (root level, for cuts/reels)

Legacy Schema Compatibility (REFACTOR)

Refactored to use legacy schema structure instead of nested contextInputs object:

Before (WRONG):

contextInputs?: {
  theme?: string
  coHost?: Person
  guests: Person[]
  parentEpisodeId?: string
}

After (CORRECT - Legacy compatible):

// Root level fields
theme?: string              // Episode theme
parentEpisodeId?: string    // For cuts/reels
guests?: Guest[]            // Legacy structure: {name, role, company, linkedin, photo}
                           // Co-host when present is guests[0]

The GuestSchema matches the legacy portal-web structure:

  • name: string (required)
  • role: string (required)
  • company: string (required)
  • linkedin: string URL (required) - note: NOT linkedinUrl
  • photo: string (optional)

Form uses EpisodeContextFormSchema for UI validation only, then transforms to flat structure on save.
