Story 4.5: Fase 3 - Análise de Risco e Conformidade (Tipo 2)

Status: done

Story

As a produtor, I want identificar riscos de compliance antes de publicar, so that posso revisar conteúdo sensível e evitar problemas.

Acceptance Criteria

  1. AC1: Processamento Automático ao Entrar na Fase

    • Given o Wizard na Fase 3
    • When a fase inicia
    • Then processamento LLM é iniciado automaticamente
    • And Área de Interatividade mostra loading state

  2. AC2: Exibição de Riscos Identificados

    • Given riscos de compliance identificados pelo LLM
    • When renderizados na Área de Interatividade
    • Then cada risco mostra:
      • Timestamp clicável (formato MM:SS ou HH:MM:SS)
      • Tipo de risco (menção de marca, linguagem sensível, claims não verificados, etc.)
      • Descrição do risco
    • And clicar no timestamp faz seek no player in-page para o ponto exato

  3. AC3: Exibição de Sucesso (Sem Riscos)

    • Given nenhum risco identificado pelo LLM
    • When renderizado
    • Then mostra Card de sucesso: "Não me parece haver riscos de compliance."

  4. AC4: Console Area com Feedback

    • Given o processamento LLM em andamento
    • When a fase está processando
    • Then Console Area mostra:
      • Spinner: "Verificando se existem pontos polêmicos ou riscos de conformidade..."
    • And após retorno mostra Alert:
      • Título: "Riscos e Conformidade"
      • Texto: "Verifique acima se existem trechos que você deveria verificar."

  5. AC5: Persistência no Firestore

    • Given o retorno do LLM com sucesso
    • When os dados são persistidos
    • Then campo riskAndCompliance é salvo na raiz do objeto video
    • And estrutura: Array<{ timestamp: string, risk: string, description: string }>

  6. AC6: Critérios de Avanço com Confirmação

    • Given os critérios de avanço da Fase 3
    • When o botão "Avançar" é clicado
    • Then valida:
      • Retorno do LLM com sucesso ✓
      • Campo riskAndCompliance persistido ✓
    • And se houver riscos: Alert Dialog "Tem certeza que deseja continuar?"
    • And se produtor confirmar "Sim", avança para Fase 4
    • And se "Não", permanece na Fase 3

  7. AC7: Comportamento Fase Tipo 2 (Imutável)

    • Given esta é uma fase Tipo 2 (Imutável)
    • When renderizada após completada
    • Then NÃO mostra input de override nem botão de reprocessar
    • And resultado é exibido em modo read-only

  8. AC8: Tratamento de Erros

    • Given a chamada LLM falha
    • When erro é recebido
    • Then Console Area mostra Alert de erro com mensagem amigável
    • And permite tentar novamente (botão retry habilitado)

Dev Notes

Architecture Patterns

  • Fase Tipo 2 (Imutável): Uma vez processada, não pode ser reprocessada. O componente deve detectar phases[3].status === 'completed' e renderizar em modo read-only.
  • Processamento Automático: Igual à Fase 2, inicia processamento automaticamente ao entrar, sem botão manual.
  • Console Pattern: Usar wizard.addSpinner() ao iniciar, wizard.removeSpinner() ao finalizar, wizard.addAlert() para resultado.
  • Confirmação de Avanço: Alert Dialog do shadcn/ui para confirmar continuação se houver riscos identificados.

UX Patterns (Reutilizar de Story 4-4)

1. Console Area - Reverse Order + Animation

Messages should be displayed with newest at top. New alerts should have attention animation.

See: src/components/wizard/console-area.tsx

2. Timestamps - In-Page Player Control

Clickable timestamps should seek the in-page YouTube player, NOT open new tabs.

// Reutilizar ClickableTimestamp de Story 4-4
import { ClickableTimestamp } from './clickable-timestamp'

3. Timestamps - Context Offset (30 seconds)

IMPORTANTE para revisores: Timestamps de críticas/problemas devem dar 30 segundos de contexto.

Ao clicar em um timestamp, o vídeo busca 30 segundos ANTES do momento marcado. Isso permite que o revisor ouça o contexto antes da crítica apontada pelo LLM.

// Em clickable-timestamp.tsx
export const TIMESTAMP_CONTEXT_OFFSET_SECONDS = 30

// Seek position = timestamp - 30s (mínimo 0)
const seekSeconds = applyContextOffset
  ? Math.max(0, seconds - TIMESTAMP_CONTEXT_OFFSET_SECONDS)
  : seconds

Uso:

  • Com offset (padrão): <ClickableTimestamp timestamp="05:30" /> → busca 05:00
  • Sem offset (capítulos): <ClickableTimestamp timestamp="05:30" applyContextOffset={false} /> → busca 05:30

Pattern: @pattern TIMESTAMP_CONTEXT_OFFSET
