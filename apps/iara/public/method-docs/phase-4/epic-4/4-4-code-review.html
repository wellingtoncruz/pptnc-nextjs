Code Review: Story 4-4 (Fase 2 - Checagem de Edição)

Reviewer: Claude Opus 4.5 (Adversarial Senior Developer Review) Date: 2026-01-28 Story Status: Review Test Results: 38/38 wizard tests passing (67 total wizard tests passing per story)

Executive Summary

Story 4-4 implements Phase 2 of the wizard (Checagem de Edição - Tipo 2 Imutável). The implementation is largely correct and follows the established patterns from Phase 1. However, I found 6 specific issues that need attention, ranging from minor to medium severity.

Issues Found

Issue 1: Schema Mismatch Between LLM Prompt and Type Definition (MEDIUM)

Location: src/lib/llm/prompts.ts:27-38 vs src/lib/llm/types.ts:28-48

Problem: The BASE_SYSTEM_PROMPTS for Phase 2 requests a JSON schema with issue and severity fields:

// In prompts.ts BASE_SYSTEM_PROMPTS[2]:
{
  "timestamp": 00:00,
  "issue": "Descrição do problema",
  "severity": "minor" | "major"
}

But the actual Phase2Response type and EditingIssue interface expect:

// In types.ts:
interface EditingIssue {
  timestamp: string    // "HH:MM:SS" or "MM:SS"
  description: string  // NOT "issue"
}

The PHASE_JSON_SCHEMAS[2] has the correct schema, but BASE_SYSTEM_PROMPTS[2] is outdated and inconsistent.

Impact: If the podcast doesn't have custom prompts configured and falls back to BASE_SYSTEM_PROMPTS, the LLM may return { issue, severity } instead of { description }, causing parse errors or missing data.

Fix Required: Update BASE_SYSTEM_PROMPTS[2] to match PHASE_JSON_SCHEMAS[2]:

2: `Você é um editor de vídeo experiente...
{
  "hasIssues": true/false,
  "issues": [
    {
      "timestamp": "00:05:30",
      "description": "Descrição do problema"
    }
  ]
}`

Issue 2: Missing Test for Error State / Retry Functionality (MEDIUM)

Location: src/components/wizard/phases/phase-2-edit-check.test.tsx

Problem: AC8 specifies:

"Given a chamada LLM falha, When erro é recebido, Then Console Area mostra Alert de erro com mensagem amigável, And permite tentar novamente (botão retry habilitado)"

The current test file has 15 tests but none test the error state or retry button behavior. The test suite covers:

  • Loading state (3 tests)
  • Success state - no issues (3 tests)
  • Issues found state (4 tests)
  • Confirmation dialog (3 tests)
  • Single issue grammar (2 tests)

Missing:

  • Error state rendering
  • Retry button functionality
  • Error message display

Fix Required: Add tests for AC8:

describe('Error state', () => {
  it('displays error state when phase has error', () => { ... })
  it('enables retry button when error occurs', () => { ... })
  it('shows friendly error message in Console Area', () => { ... })
})

Issue 3: ClickableTimestamp Doesn't Handle Missing YouTube Context Gracefully (LOW)

Location: src/components/wizard/phases/clickable-timestamp.tsx:85-98

Problem: When youtube context is null (outside of YouTubeProvider), clicking the button does nothing silently:

const handleClick = () => {
  if (youtube) {
    youtube.seekTo(seconds)
    // scroll...
  }
  // No else branch - silent failure
}

Impact: Low - the component is always used within WizardLayout which wraps with YouTubeProvider. However, for defensive programming and potential reuse, it should at least log a warning.

Fix Suggested: Add optional fallback or warning:

const handleClick = () => {
  if (youtube) {
    youtube.seekTo(seconds)
    // scroll...
  } else {
    console.warn('ClickableTimestamp: YouTubeContext not available')
  }
}

Issue 4: Potential Memory Leak in Console Animation Timer (LOW)

Location: src/components/wizard/console-area.tsx:42-47

Problem: The useEffect that clears animation IDs after 1.5s returns a cleanup, but the effect runs whenever messages changes. If messages change rapidly, multiple timers could be created:

useEffect(() => {
  if (messages.length > prevMessagesLengthRef.current) {
    // ...
    const timer = setTimeout(() => {
      setNewMessageIds(new Set())
    }, 1500)
    return () => clearTimeout(timer)
  }
  prevMessagesLengthRef.current = messages.length
}, [messages])

The issue is that prevMessagesLengthRef.current is updated AFTER the conditional check, so if messages decrease then increase rapidly, the comparison could be stale.

Impact: Very low - in practice, messages only grow during wizard processing. But the logic could be cleaner.

Fix Suggested: Move ref update inside the conditional or use a more robust approach:

useEffect(() => {
  const prevLength = prevMessagesLengthRef.current
  prevMessagesLengthRef.current = messages.length // Update immediately

  if (messages.length > prevLength) {
    // ...
  }
}, [messages])

Issue 5: API Route Test Timeouts (Pre-existing, Not Story 4-4)

Location: src/app/api/wizard/phase/[phase]/route.test.ts

Problem: 15 tests are timing out in this file. However, this is a pre-existing issue not caused by Story 4-4 changes. The route.test.ts file is missing mocks for getPodcastAdmin which was added to the route:

// In route.ts:119
const podcast = await getPodcastAdmin(PODCAST_ID)

// In route.test.ts - NO mock for getPodcastAdmin
vi.mock('@/lib/firebase/videos-admin', () => ({
  getVideoAdmin: vi.fn(),
  // Missing: getPodcastAdmin mock
}))

Impact: Tests hang waiting for unmocked async call.

Fix Required: Add mock for getPodcastAdmin:

vi.mock('@/lib/firebase/podcasts-admin', () => ({
  getPodcastAdmin: vi.fn().mockResolvedValue(null),
}))

Issue 6: VideoPreview Missing Title Prop From Video Data (LOW)

Location: src/components/wizard/wizard-layout.tsx:60-63

Problem: VideoPreview is called without the title prop from video data:

<VideoPreview
  videoId={wizard.state.videoId}
  className="max-w-2xl w-full"
/>

The title prop defaults to 'YouTube video player' in VideoPreview, which is used for the aria-label. Should pass the actual video title for better accessibility.

Impact: Low - accessibility could be improved.

Fix Suggested: Pass video data through wizard state or layout props:

<VideoPreview
  videoId={wizard.state.videoId}
  title={videoData?.title}
  thumbnailUrl={videoData?.thumbnails?.high?.url}
  className="max-w-2xl w-full"
/>
