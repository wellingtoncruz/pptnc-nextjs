Story 4.6: Fase 4 - Capítulos (Tipo 2)

Status: done

Story

As a produtor, I want uma sugestão de divisão de capítulos por assuntos, so that o vídeo tenha navegação otimizada no YouTube.

Acceptance Criteria

  1. AC1: Processamento Automático ao Entrar na Fase

    • Given o Wizard na Fase 4
    • When a fase inicia
    • Then processamento LLM é iniciado automaticamente
    • And Área de Interatividade mostra loading state

  2. AC2: Exibição de Capítulos Gerados

    • Given capítulos gerados pelo LLM
    • When renderizados na Área de Interatividade
    • Then cada capítulo mostra:
      • Timestamp clicável (formato MM:SS ou HH:MM:SS)
      • Título do capítulo
    • And primeiro capítulo SEMPRE começa em 00:00
    • And clicar no timestamp faz seek no player in-page para o ponto exato
    • And timestamps de capítulos NÃO usam context offset (applyContextOffset={false})

  3. AC3: Exibição com Lista Vazia

    • Given nenhum capítulo retornado pelo LLM (edge case)
    • When renderizado
    • Then mostra mensagem informativa com opção de retry

  4. AC4: Console Area com Feedback

    • Given o processamento LLM em andamento
    • When a fase está processando
    • Then Console Area mostra:
      • Spinner: "Fazendo a separação de capítulos..."
    • And após retorno mostra Alert:
      • Título: "Capítulos"
      • Texto: Lista de capítulos com timestamps (formato "00:00 Título")

  5. AC5: Persistência no Firestore

    • Given o retorno do LLM com sucesso
    • When os dados são persistidos
    • Then campo chapters é salvo na raiz do objeto video
    • And estrutura: Array<{ timestamp: string, title: string }>

  6. AC6: Critérios de Avanço com Aprovação

    • Given os critérios de avanço da Fase 4
    • When o botão "Avançar" é clicado
    • Then valida:
      • Retorno do LLM com sucesso ✓
      • Campo chapters persistido ✓
    • And Alert Dialog "Aprova os capítulos?"
    • And se produtor confirmar "Sim, aprovar", avança para Fase 5
    • And se "Não, revisar", permanece na Fase 4

  7. AC7: Comportamento Fase Tipo 2 (Imutável)

    • Given esta é uma fase Tipo 2 (Imutável)
    • When renderizada após completada
    • Then NÃO mostra input de override nem botão de reprocessar
    • And resultado é exibido em modo read-only

  8. AC8: Tratamento de Erros

    • Given a chamada LLM falha
    • When erro é recebido
    • Then Console Area mostra Alert de erro com mensagem amigável
    • And permite tentar novamente (botão retry habilitado)

Dev Notes

Architecture Patterns

  • Fase Tipo 2 (Imutável): Uma vez processada, não pode ser reprocessada. O componente deve detectar phases[4].status === 'completed' e renderizar em modo read-only.
  • Processamento Automático: Igual às Fases 2 e 3, inicia processamento automaticamente ao entrar, sem botão manual.
  • Console Pattern: Usar wizard.addSpinner() ao iniciar, wizard.removeSpinner() ao finalizar, wizard.addAlert() para resultado.
  • Aprovação de Capítulos: Alert Dialog do shadcn/ui para aprovar capítulos antes de avançar.

UX Patterns (Reutilizar de Stories Anteriores)

1. Console Area - Reverse Order + Animation

Messages should be displayed with newest at top. New alerts should have attention animation.

// In console-area.tsx - JÁ IMPLEMENTADO
const reversedMessages = [...messages].reverse()

See: src/components/wizard/console-area.tsx

2. Timestamps - In-Page Player Control

Clickable timestamps should seek the in-page YouTube player, NOT open new tabs.

// Reutilizar ClickableTimestamp
import { ClickableTimestamp } from './clickable-timestamp'

3. Timestamps - NO Context Offset for Chapters

IMPORTANTE: Capítulos NÃO usam offset de contexto. O usuário quer ir direto para o início do capítulo.

// Para capítulos, usar applyContextOffset={false}
<ClickableTimestamp
  videoId={videoId}
  timestamp={chapter.timestamp}
  applyContextOffset={false}  // CRÍTICO: sem offset para capítulos
/>

Pattern: @pattern TIMESTAMP_NO_OFFSET_FOR_CHAPTERS

Response Schema (Phase4Response)

interface Chapter {
  timestamp: string    // Format: "MM:SS" or "HH:MM:SS" - DEVE SER STRING
  title: string        // Título do capítulo (max 50 chars)
}

interface Phase4Response {
  chapters: Chapter[]  // Array de capítulos, primeiro sempre em 00:00
}

ATENÇÃO: O schema atual em types.ts tem timestamp: number. Precisa ser alterado para timestamp: string para consistência com as outras fases.

// Início do processamento
const spinnerId = wizard.addSpinner(4, 'Fazendo a separação de capítulos...')

wizard.removeSpinner(spinnerId)

// Após erro
wizard.removeSpinner(spinnerId)
wizard.addAlert(4, 'Erro', errorMessage, 'error')
