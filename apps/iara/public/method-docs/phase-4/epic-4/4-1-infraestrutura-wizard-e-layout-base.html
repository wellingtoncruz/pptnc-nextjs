Story 4.1: Infraestrutura do Wizard e Layout Base

Status: done

Story

As a desenvolvedor, I want uma infraestrutura de Wizard com state machine e layout definido, so that o fluxo de 8 fases seja consistente e gerenciável.

Acceptance Criteria

AC1: State Machine do Wizard

  1. Given a necessidade de gerenciar o Wizard When eu importo o estado de src/lib/wizard/machine.ts Then tenho acesso à state machine com tipos:

    type WizardPhase = 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8
type PhaseStatus = 'pending' | 'loading' | 'completed' | 'error'

interface WizardState {
  currentPhase: WizardPhase
  phases: Record<WizardPhase, {
    status: PhaseStatus
    data: unknown
    error: string | null
  }>
}

  2. Given uma fase reprocessada (ex: Fase 5) When o usuário confirma reprocessamento Then fases 6, 7, 8 são invalidadas (status → pending, data → null)

AC2: Layout do Wizard

  1. Given o layout do Wizard When renderizado Then mostra:

    • Top half: Video preview (esquerda) + Painel interativo (direita)
    • Bottom half: Console area (scroll vertical, empilha alerts)
    • Header: Breadcrumb com 8 fases e indicadores de estado

  2. Given o breadcrumb do Wizard When renderizado Then mostra indicadores:

    • ✓ Verde: fase completa
    • ● Azul pulsante: fase em progresso (loading)
    • ○ Cinza: fase pendente
    • ⚠ Amarelo: fase com erro

AC3: Console Area

  1. Given a console area When uma fase processa Then empilha mensagens (Spinner durante loading, Alert após resultado) And mantém histórico (não limpa alerts anteriores) And tem scroll vertical quando necessário

AC4: Hook useWizard

  1. Given a necessidade de gerenciar o Wizard em componentes When eu uso useWizard(videoId) Then tenho acesso a:
    • state: WizardState atual
    • currentPhase: fase atual
    • goToPhase(phase): navegar para fase
    • setPhaseStatus(phase, status): atualizar status
    • setPhaseData(phase, data): salvar dados da fase
    • invalidateFromPhase(phase): invalidar fases a partir de X
