Story 1.1: Infraestrutura Base para Cut/Reel

Status: done

Story

As a desenvolvedor, I want preparar a infraestrutura de tipos, schemas e constantes para suportar os tipos de vídeo cut e reel, so that o fluxo do wizard possa ser estendido para esses novos tipos sem modificar o comportamento do episode.

Acceptance Criteria

AC1: Novos campos no VideoSchema

DADO que o schema Video existe
QUANDO eu adicionar os campos para cut/reel
ENTÃO os seguintes campos devem existir:
  - suggestedShortTitles: z.array(z.string()).optional()
  - shortTitle: z.string().optional()
E o campo existente parentEpisodeId deve ser mantido
E todos os testes existentes devem continuar passando

AC2: Mapeamento de fases por tipo de vídeo

DADO que existe WIZARD_PHASES = [1,2,3,4,5,6,7,8]
QUANDO eu criar o mapeamento por tipo
ENTÃO deve existir:
  - PHASES_BY_VIDEO_TYPE.episode = [1, 2, 3, 4, 5, 6, 7, 8]
  - PHASES_BY_VIDEO_TYPE.cut = [0, 5, '5B', 6, 7, 8]
  - PHASES_BY_VIDEO_TYPE.reel = [0, 5, 6, 7, 8]

AC3: Tipagem para novas fases

DADO que WizardPhase = 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8
QUANDO eu estender para suportar fase 0 e 5B
ENTÃO deve existir ExtendedWizardPhase = 0 | 1 | 2 | 3 | 4 | 5 | '5B' | 6 | 7 | 8
E a tipagem antiga deve continuar funcionando para episode

AC4: Metadata para novas fases

DADO que existe PHASE_METADATA para fases 1-8
QUANDO eu adicionar metadata para fase 0 e 5B
ENTÃO deve existir:
  - PHASE_METADATA[0] = { label: 'Vídeo Pai', type: 'immutable', ... }
  - PHASE_METADATA['5B'] = { label: 'Título Curto', type: 'reprocessable', ... }

AC5: Função helper para obter fases por tipo

DADO um videoType
QUANDO eu chamar getPhasesForVideoType(videoType)
ENTÃO deve retornar o array correto de fases para aquele tipo

AC6: Testes de regressão

DADO todas as alterações de infraestrutura
QUANDO eu rodar os testes
ENTÃO todos os testes existentes do wizard devem passar
E novos testes para o mapeamento devem existir

Dev Notes

REGRA DE OURO - CRÍTICA

O fluxo de episode NÃO PODE ser modificado. Esta story adiciona APENAS infraestrutura:

  • Novos tipos e constantes
  • Novos campos opcionais nos schemas
  • Novos helpers que NÃO são usados pelo código existente de episode

O código existente do wizard (machine.ts, wizard-orchestrator.tsx, etc.) NÃO deve ser alterado nesta story.

Estrutura Atual dos Arquivos

src/lib/wizard/
├── types.ts      # WizardPhase, PhaseState, WizardState, etc.
├── constants.ts  # WIZARD_PHASES, PHASE_METADATA
└── machine.ts    # createInitialWizardState, wizardReducer

src/lib/schemas/
└── video.ts      # VideoSchema, VideoTypeSchema

Padrões de Código Existentes

  1. Tipos: Usar z.infer<typeof Schema> para inferir tipos de Zod
  2. Constantes: Arrays as const e Records tipados
  3. Helpers: Funções puras com fallback seguro
  4. Schemas Zod: .optional() para campos opcionais

Decisões de Design

  1. ExtendedWizardPhase: Union type que inclui 0 | WizardPhase | '5B'

    • Fase 0 é numérica (consistente com outras fases numéricas)
    • Fase '5B' é string para diferenciar da fase 5 (título completo)

  2. PHASES_BY_VIDEO_TYPE: Record com arrays de fases

    • episode: [1, 2, 3, 4, 5, 6, 7, 8] (atual, sem mudança)
    • cut: [0, 5, '5B', 6, 7, 8]
    • reel: [0, 5, 6, 7, 8]

  3. EXTENDED_PHASE_METADATA: Novo objeto que estende PHASE_METADATA

    • Mantém backward compatibility com código existente que usa PHASE_METADATA
    • Stories futuras migrarão para usar EXTENDED_PHASE_METADATA

Project Structure Notes

  • Arquivos em src/lib/wizard/ seguem o padrão módulo TypeScript
  • Schemas Zod em src/lib/schemas/video.ts seguem padrão existente
  • Testes usam Vitest (padrão do projeto)
